# 모임 공유 안내 및 개인정보 제3자 제공 동의문

2026-10-30 · 검토 초안 · **공유·수령인·철회 정책 결정 후 적용**

## 1. 검토 판단

서버가 회원의 표시명·사진·영상 등을 다른 모임 참여자에게 제공하는 구조는 개인정보 제3자 제공 검토 대상이다. 이용자 요청에 의한 전송인지, 운영자가 제공하는지 등 구체적 구조에 대한 법률 검토가 필요하다. **본 초안은 모임별 별도 제공 동의를 마련하는 방안**이다. 모든 공유 서비스가 동일하게 가입 시 필수 동의를 받아야 한다는 결론은 아니다.

계약 이행을 위한 수집 근거만으로 제공까지 허용된다고 판단하지 않는다. 동의 방식을 채택하면 수령인·목적·항목·기간·거부 영향을 제시하고, 달라지는 사항에 필요한 새 동의를 검토한다. [개인정보 보호법 제17조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334739)

## 2. 참여 시 제공 안내·동의 초안

문서 ID 예시: consent-group-membership · 대상: 선택한 모임 1개

**[해당 모임 참여를 위한 동의] 모임 참여자에게 개인정보 제공**

| 구분 | 내용 |
| --- | --- |
| 제공받는 자 | **[확정 필요: 모임명·모임 식별자]의 참여자**. 실제 상대방은 **[확정 필요: 참여 전 열람 가능한 수령인 확인 경로]**에서 확인합니다. 향후 참여자 포함 여부는 아래 정책 확정 후 명시합니다. |
| 목적 | 모임 참여자 식별, 역할 표시, 공동 일정·장소 관리 |
| 제공 항목 | 표시명, 방장/일반 참여자 역할, 참여 상태, 이용자가 해당 모임에 작성한 일정·장소 정보 중 실제 공개하는 항목 |
| 보유·이용 기간 | 해당 모임에서 안내된 활동 및 기록 유지 기간 내 필요한 범위. **[확정 필요: 항목별 종료 기준, 나간 참여자 표시와 계획 보존 기간]** |
| 거부권·영향 | 동의를 거부할 수 있습니다. 참여자 표시 등 해당 모임 운영에 필요한 제공을 거부하면 해당 모임 참여가 제한됩니다. 무관한 기능 이용은 제한하지 않습니다. |

선택 문구: `위 내용을 확인하고 이 모임 참여를 위한 개인정보 제공에 동의합니다.`

현재 명세의 가입 전 초대 화면은 참여자 목록을 공개하지 않는다. 이 제한과 **제공받는 자 확인**을 양립시키는 로그인 후 참여 전 확인 절차가 필요하다. 표시명만으로 수령인을 충분히 특정할 수 있는지도 법률 검토한다. ‘서비스 제휴사 등’ 같은 포괄 표현으로 대체하지 않는다.

## 3. 사진·영상 공유 전 제공 안내·동의 초안

문서 ID 예시: consent-group-media · 범위: 모임과 공개 범위별

**[해당 파일 공유를 위한 동의] 사진·영상 등 개인정보 제공**

| 구분 | 내용 |
| --- | --- |
| 제공받는 자 | [확정 필요: 해당 모임의 현재 참여자 및, 정책에 따라 명확히 정한 향후 참여자 범위·확인 경로] |
| 목적 | 해당 모임 기록의 공동 열람 및 허용된 기기 저장 |
| 제공 항목 | 선택한 사진·영상 내용, 작성자 표시명, 설명, 촬영 시각, 기록일, 지정한 방문 장소 등 실제 공개하는 항목. 파일 내 위치 태그는 제거한 후 제공 |
| 서비스 내 이용 기간 | 해당 기록의 고정 보관 기한, 삭제·철회 또는 수령인의 접근권한 종료 중 해당하는 시점까지 |
| 수령인 기기 사본의 이용 기간 | **[확정 필요: 아래 4항의 정책 A/B 중 선택하여 실제 종료 시점 명시]**. 서버 기한을 사본에 자동 적용하거나 무기한 보관으로 임의 확정하지 않음 |
| 거부권·영향 | 거부하면 해당 파일을 모임에 공개하지 않습니다. 현재 서비스에는 비공개 개인 보관 기능이 없으므로 업로드를 취소할 수 있습니다. 계정 자체를 삭제할 필요는 없습니다. |

선택 문구: `위 모임의 안내된 참여자에게 선택한 파일과 관련 정보를 제공하는 데 동의합니다.`

사진에 등장하는 다른 사람의 개인정보·초상권은 업로더 본인의 동의로 대체되지 않는다. 공동 사진·아동 사진 등은 적법한 공유 권한을 확인하는 절차, 비회원 권리행사 접수, 필요시 비공개·삭제 조치를 함께 설계해야 한다. ‘모든 책임은 업로더에게 있다’는 면책만으로 해결하지 않는다.

## 4. 현재 명세에서 결정해야 할 두 가지

**새 참여자와 기존 파일:** 모든 현재 참여자가 초대를 발급할 수 있으므로 최초 업로드 때의 수령인만 계속 남아 있지 않는다. 향후 참여자에 대한 사전 동의 범위가 충분히 특정·설명될 수 있는지, 새 참여 시 통지·재동의나 과거 기록 접근 제한이 필요한지 결정한다. 가입 때 ‘모든 사람에게 제공’ 한 줄로 해결하지 않는다. 개인정보위의 수령인 유형화 기재 지침은 **처리방침 작성에 관한 지침**이며 개별 제공 동의 요건을 자동 면제하지 않는다.

**기기 사본:** 다음 두 정책은 제안 대안이며 아직 선택하지 않았다.

| 대안 | 설명 | 필요한 조치 |
| --- | --- | --- |
| A. 모임 목적·권한 기간으로 제한 | 제공 목적 달성·철회 등 정한 시점에 수령인에게 삭제 의무 부여 | 삭제 요청 전달 수단, 수령인 약정, 실제 통제 한계 안내 |
| B. 개인 추억 보관을 별도 범위로 허용 | 서버 보관과 별도로 적법한 개인 보관 목적·기간을 구체적으로 정함 | 별도 설명·동의 근거와 철회 영향 검토. ‘영구 이용’ 포괄 허락 금지 |

어느 대안이든 사본 자동 회수를 기술적으로 보장하지 않는다. 그렇다고 수령인의 목적 외 사용·무단 공개까지 허용하지 않는다. 이 결정 전에는 위 제공 동의문을 확정본으로 배포하지 않는다.

## 5. 업로드 확인 문구

> 선택한 파일은 이 모임의 안내된 참여자가 보고 기기에 저장할 수 있습니다. 파일 속 사람의 얼굴·음성·민감한 내용과 직접 지정한 장소를 확인해 주세요. GPS 태그 제거만으로 모든 위치나 신원이 숨겨지지는 않습니다. 타인의 권리를 침해하는 파일은 공유하지 마세요. 서버에서 삭제해도 다른 사람이 저장한 사본은 자동 회수되지 않습니다.

이 문구는 중요한 결과 설명이며, 필요한 개인정보 제공 동의나 등장인물의 동의를 대체하지 않는다. 표의 구체적 내용은 별도로 확인할 수 있어야 한다.

## 6. 철회·접근 종료

모임 나가기, 본인 파일 삭제, 공유 동의 철회, 계정 삭제를 구분한다. 철회 이후 신규 제공 중단과 서버 접근 제한, 수령인에 대한 필요한 조치, 사본 삭제 요청 방법을 정한다. 기존 명세는 나가도 본인 파일이 남으므로 **나가기=공유 동의 철회**로 기록하면 모순이 생긴다.

철회 경로: **[확정 필요: 모임 공유 설정 또는 별도 접수 경로]**. 앱 구현이 완료되기 전에는 존재하는 것처럼 공개하지 않는다. 파일 기한과 철회 범위도 동의 당시 기록으로 남긴다.
