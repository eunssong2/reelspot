# ReelSpot · At that place — 앱 개발

`feature/mobile-app` 브랜치는 React Native 앱, API·작업 서버, 배포 도구와 검증 문서를 관리합니다. [개발·실행 안내](1차%20개발%20코드/README.md), [앱 사용설명서](1차%20개발%20코드/docs/앱_사용설명서/README.md), [공개 서버 복구 상태](1차%20개발%20코드/docs/2026-10-30_공개서버_실행복구.md)를 참고하세요. 실제 카카오 로그인 완료와 일반 사용자 출시 준비는 별도 검증이 필요합니다.

`docs` 브랜치는 기능 명세, 개발 설계, 회의 기록을 관리합니다. 제품의 동작과 정책은 **기능 명세서**, 이를 구현하는 구조와 계약은 **1차 개발 설계서**, 결정의 배경과 변경 이력은 **회의록**으로 분리했습니다.

```text
.
├── 기능 명세서/
│   ├── 기능명세서.md          # 현재 정책 원본: v2.2
│   ├── 다이어그램/           # 유스케이스 원본·PNG·SVG
│   └── 참고 자료/            # 이전 명세와 기능 조사 근거
├── 1차 개발 설계서/
│   ├── 00 설계서 안내.html    # 설계 v0.3.2 읽기 시작점
│   ├── UI/                   # 프로토타입 화면·전환·상태 설계
│   ├── 기준/                 # 검증용 명세 사본·SHA256
│   ├── 부록/                 # API·DB·검증 결과
│   ├── 참고 자료/            # 소개 PDF·선행 화면 명세
│   └── 도구/                 # 문서 재생성·검증 도구
└── 회의록/                   # 회의 내용·반영 내역·당시 참고 자료
```

최신 정책은 기능명세서 **v2.2**, 설계는 **v0.3.2**입니다. 2026-10-24 개정으로 초대 조회·발급·공유·복사·개별 취소를 방장을 포함한 모든 현재 참여자에게 허용합니다. 문서의 설계·계약 검증과 실제 앱 기능 검수를 구분합니다.

기능·정책을 바꿀 때는 `기능 명세서/기능명세서.md`를 먼저 수정합니다. 설계서의 `기준/기능명세서.md`는 독립 열람·재생성·SHA256 검증을 위한 사본이며 별도의 정책 원본이 아닙니다. 정책 차이를 확인한 뒤 사본과 설계를 함께 갱신합니다. `참고 자료`와 `회의록`의 과거 내용이 현재 정책과 다르면 최신 기능명세서를 따릅니다.

`1차 개발 코드/`의 소스와 사용설명서는 이 개발 브랜치에서 관리합니다. 실행용 비밀 설정·DB/업로드 데이터·APK·ZIP·의존성·빌드 결과·원시 실행 로그는 제외합니다. `docs` 브랜치에는 구현 코드를 포함하지 않습니다. 원본 참고 앱 없이도 설계 문서를 열고 재생성할 수 있으며, 이전 APK 관찰 결과는 설계서 내부의 캡처·XML·기록으로 보존합니다.

UI는 2026-10-30 원격 `feature/ui-prototype`의 `c19f34c` 기준으로 갱신했습니다. [최신 UI 갤러리](1차%20개발%20설계서/UI/05%20UI%20화면%20갤러리.html)에 실행 캡처와 화면별 출처를 반영했으며, 화면 적용 기준은 [UI 통합 설계](1차%20개발%20설계서/UI/2026-10-30_UI_통합_설계.md), 미합의 정책은 [10월 30일 회의 안건](회의록/10월%2030일%20회의%20안건.md)에 정리했습니다. API/DB 스키마는 유지합니다.
