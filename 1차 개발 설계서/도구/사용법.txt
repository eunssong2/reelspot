프로토타입이 바뀐 경우
1. 외부 feature-ui-prototype checkout에서 git pull --ff-only 후 commit과 diff를 기록한다.
2. PPT가 바뀌면 capture_overview.py --pptx <절대경로>/docs/AT_THAT_PLACE_전체화면정리.pptx --commit <커밋> 실행.
   슬라이드 구성이 바뀌면 UI_MAP을 검토한다. 예상과 다르면 도구는 중단한다.
3. 별도 checkout에 의존성을 설치하고 일반/데모 Expo 웹을 실행한다. 기존 README는 옛 기능 설명을 포함하므로 라우트/소스를 우선 확인한다.
   일반: CI=1 npx expo start --web --port 18082
   데모: EXPO_PUBLIC_DEMO_MODE=1 CI=1 npx expo start --web --port 18081
4. capture_prototype.py --source <절대경로> --url http://localhost:18081
   capture_login_ui.py --source <절대경로> --url http://localhost:18082
   같은 커밋·새 브라우저 예시 데이터만 사용한다. 실계정/서비스 데이터로 캡처하지 않는다.
5. UI/프로토타입/출처.json·UI/전체화면정리/출처.json hash와 경로, 모델 매핑을 갱신한다.
6. 정책 원본→사본→생성 원천→Office/PDF/계약→검증 순서로 반영한다.
소스가 바뀌지 않았으면 저장된 캡처로 재생성하며 앱 실행을 새로 했다고 기록하지 않는다.

- 기록: UI/브이로그/피드백검토/재현결과.json·증거 PNG. source는 저장소 이름만 기록하며 개인 checkout의 절대경로는 저장하지 않는다. 커밋과 소스 해시 검증으로 실행 대상을 식별한다. Expo 실행 진단 로그는 시스템 임시 폴더의 vlog-repro-*.log에 저장하며 실패 시 경로를 표시한다.

- VB03·VB04는 코드 확인 상태다. UI 담당자의 실행 검수와 수정 후 확인이 필요하다.
