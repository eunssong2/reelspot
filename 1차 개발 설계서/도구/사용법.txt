정책 기준은 패키지 내부 기준/기능명세서.md(v2, 2026-10-22)이며 SHA256은 기준/기준선.json에 있습니다.

기존 DayLog 소스는 선택적 재사용 후보이며, 설계서 열람과 핵심 문서 재생성의 필수 의존이 아닙니다.

직접 편집
Word 문단·표, Excel 셀, PowerPoint 도형·텍스트, SVG 텍스트·도형을 수정할 수 있습니다.
UI/05 UI 설계.pptx의 신규 화면은 개별 도형입니다. 실제 APK 캡처 PNG는 별도 관찰 근거 이미지입니다.
Noto Sans CJK KR이 없으면 PowerPoint의 글꼴 바꾸기에서 맑은 고딕 등으로 바꿉니다.
재생성은 기존 산출물을 덮어씁니다. Office에서 직접 수정한 파일은 먼저 별도 보관하세요.

DB 정의가 바뀐 경우
검증 결과는 DDL SHA256에 연결됩니다. DB를 변경한 뒤 예전 성공 결과를 재사용할 수 없습니다.
아래 전용 임시 컨테이너만 사용하며 실제 사용자 DB에 검증 fixture를 넣지 않습니다.
docker run --rm -d --name atp-design-v02-pg --network none -e POSTGRES_HOST_AUTH_METHOD=trust postgres:16-alpine
.venv/bin/python 도구/verify_db.py
docker stop atp-design-v02-pg
.venv/bin/python 도구/validate_artifacts.py
verify_db.py는 새 이름의 검증 DB를 만들고 적용·동일hash재실행·hash변경거부·제약·정원경쟁·역할을 검사합니다.
001_initial.sql은 빈 DB의27개 업무 테이블 baseline입니다. 002_service_roles.sql은 DBA용 역할 템플릿입니다.
실제 적용에서는 PGHOST/PGPORT/PGUSER/PGDATABASE 등 전용 migrator 접속 환경을 설정한 뒤:
python 도구/apply_db_baseline.py
이 runner는 세션 advisory lock, 파일 hash 확인, 스키마와 이력의 동일 커밋을 수행합니다.
운영 DB에 초기 스키마를 다시 만들거나 DROP SCHEMA로 되돌리지 않습니다.

검증 범위
- 부록/DB/검증결과.json: 실행한 DDL·DB 제약·정원 경쟁
- 부록/계약예제/검증결과.json: 정상/오류 JSON을 OpenAPI에 적용한 결과
- 부록/독립 패키지 검증.json: 상위 원본·DayLog·APK 없는 복사본의 문서 재생성
- 부록/산출물 검증.json: 연결·파일·도형·스키마·기준선 검사
- 06 검수 및 추적.xlsx: 실제 앱 기능 검수는 미실행. 단위/API/경쟁/기기/운영 방식을 구분합니다.

검증된 변경과 관찰 시각은 실제 증거를 확인한 경우에만 build_evidence.py에서 갱신하세요.

PDF는 같은 콘텐츠를 HTML로 인쇄한 열람본으로 Office 원본과 줄바꿈/페이지 나눔이 다를 수 있습니다.
PPTX는 구조·참조를 검사하고 대응 SVG/PDF를 시각 검토합니다.
실제 앱·서버·외부 연동·실기기 빌드가 완성되었다는 뜻은 아닙니다.
