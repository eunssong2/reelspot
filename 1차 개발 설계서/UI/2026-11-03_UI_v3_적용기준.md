> 2026-11-05 현재 기준: 기능명세 v3.3·설계 v0.5.1. UI45는 ff5a5d0의 고정 미리보기·단일 열림 설정을 적용한다(D28). [브이로그 설계](../11%20브이로그%20제작%20설계.md)와 [새 UI45 실행 관찰](브이로그/편집설정/실행결과.json)을 우선하며 아래 870be87·9f64b5e 출처는 해당 시점의 이력이다.

기준: 디자이너·PM이 고객 요구를 화면과 동작으로 만들어 올리는 `feature/ui-prototype@870be87`(2026-10-30 23:43). 이 커밋을 웹으로 실행(일반 모드·데모 모드)해 44개 화면 상태를 수집하고 12개 규칙을 직접 조작해 확인했으며, 화면 코드 약 150개 파일을 대조했다. 정책 원본은 [기능명세서 v3.1](../기준/기능명세서.md)이다.

## 적용 원칙

1. **프로토타입과 겹치는 기능은 프로토타입의 화면·동작·문구가 우선한다.** 이전 사용자 결정(A16·A17)과 [전체 화면 정리 반영](2026-11-01_UI_전체화면정리_반영.md)의 P1~P14는 v3에서 프로토타입 기준으로 확정했다(명세 0.2절 D01~D24).
2. **프로토타입에 없는 기존 기능은 유지한다.** 화면은 프로토타입의 디자인 체계(코랄 `#F1706B`, 큰 버튼 56px·radius 14, 아래쪽 확인 카드, 토스트 1.8초)로 추가 설계하며 화면 명세에 `기존 유지`로 표시한다.
3. **프로토타입의 결함은 요구사항으로 옮기지 않는다.** 문구 모순·예시 데이터용 단순화·버그는 명세 0.4절 Q1~Q18로 관리하고, 결정 전까지 `v3 적용`값으로 설계한다.
4. 대표 화면은 UI 담당 전체 화면 정리 PPT 이미지 → 같은 커밋의 실행 캡처 → 명세 기반 설계안 순서로 고른다. 이미지·캡처는 예시 데이터로 동작하는 화면이며 기능 완료·권한 검증 결과가 아니다.

## 프로토타입 동작 중 고쳐서 반영한 것

- 일정 추가의 `같은 기간에 … 그대로 저장할 수 있어요` 안내 → 사용 중인 날짜 안내와 저장 비활성(Q1).
- 마지막 하루 삭제 시 기록 검사 없음 → 기록·진행 업로드가 있으면 거부(Q9).
- 취소된 날 카드가 다른 날을 엶·취소된 날/만료 일정에서 편집·업로드 가능 → 그날 보기 전용, 편집·업로드 차단(Q10).
- 기록을 장소 id로 조회(일반 모드) → 방문 단위(Q12). 정렬 문자열에 연도 없음 → 서버 시각(Q14).
- 다운로드 요청에서 동영상이 대표 이미지로 넘어감 → 동영상 파일 저장.
- 로그인 방식 고정 `카카오`, 참여 모임 0개일 때 예시 수 `3` → 실제 값.
- 앱 매니페스트의 카메라·마이크 권한 꺼짐 → 촬영 기능에 맞게 선언.
- 하루 일정 변경 화면의 이탈 확인 `나가기`가 확인창을 반복할 수 있음 → 한 번 확인 후 나가기.

## 2026-11-03 추가 대조 보완(v0.4.1)

[대조 보완](../10%20프로토타입%20대조%20보완.md)의 R01~R08·C01~C13을 함께 읽는다. 현재 프로토타입 커밋과 기존 캡처는 동일하며 이번 보완에서 새 실행 캡처를 만들지 않았다.

- UI38: 단일/여러 날 모두 날짜 제목 1~100자, 부모 일정 이름 유지. 날짜만 바꾸면 제목 유지.
- UI12: 변경 입력 0~30자. UI38에서 온 31~100자 기존 제목은 표시·시간/순서 저장 때 자동으로 자르지 않는다(Q15).
- UI08: 모임 전체 날짜 탭은 `groupDays` 커서로 조회하고 `(scheduleId, date)`로 선택한다. 월 달력 응답만으로 다른 달/해의 탭을 생략하지 않는다. 부분 조회 실패는 기존 탭과 선택을 유지한다.
- UI14: 접수된 후보만 제거하고 거부 후보·사유를 남긴다. 전부 접수됐을 때만 비운다.
- UI09·UI13: 묶음 첫 파일 완료 시각 고정, 묶음 내부 선택 순서 유지.
- 11월 3일의 15명·통합 달력·초대 단순화·브이로그 연결 등은 C01~C13 반영 대기다. 현재 화면에 구현됐다고 표시하지 않는다.
