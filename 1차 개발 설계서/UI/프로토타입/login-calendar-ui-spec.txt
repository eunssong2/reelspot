## 1. 제품 정의

### 1.1 한 줄 정의
소셜 계정으로 로그인해 가입을 마치고, 내가 속한 모임을 고르거나 새로 만들고, 모임 달력에서 일정을 확인·추가·변경해 일정 상세(UI08)로 들어간다. 모임의 참여자는 초대 링크·코드를 만들어 공유하고(공유하기), 받은 사람은 초대를 확인한 뒤 로그인해 참여한다.

### 1.2 확정 사항
| # | 내용 |
|---|---|
| 1 | 구조는 **모임 → 일정 → 장소 계획·기록**이다. 일정은 **시작 날짜와 종료 날짜만** 가진다. 여러 날 여행도 일정 하나다(팀 2절) |
| 2 | **반복 일정과 종일/시간 지정은 없다**(회의 2·3번). UI07 맞춤 반복 화면은 폐지됐다. 시각은 장소를 추가할 때 방문별로 입력한다(UI10·UI11, 다른 담당) |
| 3 | 로그인 수단은 **카카오·Google 두 개만** 표시한다. 공급자+공급자 사용자 식별값으로 계정을 구분하고 **같은 이메일이라도 자동으로 합치지 않는다**(F01) |
| 4 | 초대에서 시작한 사용자는 로그인·가입 후 **초대를 다시 누르지 않아도** 같은 초대 확인(UI24)으로 돌아간다. 로그인만으로 자동 참여시키지 않는다(F01·F05) |
| 5 | 필수 동의를 마치기 전에는 가입을 완료하지 않는다. 선택 동의를 거부해도 이용을 막지 않는다. **프로필 사진 입력은 없다**(F02) |
| 6 | 모임은 **첫 일정과 함께만** 만든다. 모임·방장 참여·첫 일정은 한 번에 생성되며 일부만 생기지 않는다(F03) |
| 7 | 정원은 방장 포함 **최대 10명 고정**이며 화면에서 정원을 고르지 않는다. 화면 배치·여행지 입력도 없다(팀 UI04) |
| 8 | 모든 날짜는 **Asia/Seoul 고정**, `YYYY-MM-DD`로 보관한다. 기기 시간대가 바뀌어도 날짜·오늘 표시는 한국 시간 기준이다 |
| 9 | 일정 추가·변경·취소·빈 일정 삭제는 **현재 방장만** 할 수 있다. 일정 조회와 초대 관리 진입은 모든 현재 참여자가 할 수 있다(팀 3절) |
| 10 | 기록이나 진행 중 업로드가 있는 일정은 **삭제하지 않고 취소**한다. 취소한 일정은 달력에 취소 표시로 남고 되돌릴 수 없다(F08·F11) |
| 11 | 생성 요청은 같은 요청 키(`Idempotency-Key`)로 재시도해 **중복 생성을 막는다**. 응답이 유실되면 실패로 단정하지 않고 결과를 확인한다(5절) |
| 12 | 화면에서 버튼을 숨기는 것은 편의일 뿐이며 권한·한도는 **서버가 최종 판정**한다 |
| 13 | **공유하기 = 초대 링크·코드 공유.** 링크와 코드는 같은 초대 하나이며 서버 발급 시각부터 **7일(168시간)** 유효하고, 초대 확인(미리보기) **50회**에 소진된다(회의 1번·F05) |
| 14 | 초대 발급·조회·공유·복사·취소는 **방장을 포함한 모든 현재 참여자**가 할 수 있다. 다른 참여자가 발급한 초대도 관리할 수 있다(v2.1) |
| 15 | 초대 메시지에는 **모임명·일정 요약·링크·코드만** 담는다. 로그인 전 미리보기에도 모임명·일정 요약만 보이고 대표 사진·참여자·장소·기록은 보이지 않는다 |
| 16 | 참여는 **초대 확인 → 로그인·가입 → 참여하기** 순서다. 방장 승인·신청 대기는 없다. 참여 확정은 확인 횟수를 쓰지 않는다 |
| 17 | 사진·영상의 다른 앱 공유는 없다(회의 8번). 이 문서의 `공유하기`는 초대 메시지에만 쓴다 |

### 1.3 담당 범위
| 포함 | 제외(다른 담당, 연결 계약만 7장) |
|---|---|
| 앱 시작·세션 복원, 로그인, 가입 동의·표시명, 내 모임 목록, 모임과 첫 일정 생성, 모임 달력·일정 목록, 일정 추가·변경·취소·빈 일정 삭제, 기간 선택 시트, **초대 발급·공유·취소(UI23), 초대 확인·참여(UI24)** | 일정 상세·장소·기록(UI08~UI21), 내 기록(UI22), 설정·마이페이지·로그인 수단 연결·계정 삭제(UI28~UI30), 모임 정보 변경·참여자 관리·강제 퇴장(UI25·UI26) |

### 1.4 용어
| 용어 | 정의 | 예시 |
|---|---|---|
| 모임 | 참여자·방장·이름·대표 사진을 공유하는 공간. 여러 일정을 가진다 | 주말 산책 모임 / 6/10명 |
| 방장 | 모임마다 한 명. 일정 추가·변경·취소·삭제 권한을 가진다 | |
| 현재 참여자 | 모임에 참여 중이고 나가거나 퇴장되지 않은 사용자 | |
| 일정 | 모임 안의 한 번의 활동. 제목·시작 날짜·종료 날짜·상태(활성/취소)를 가진다 | 우리의 서울 여행 / 10.17–10.19 |
| 표시명 | 참여자 목록·기록 작성자에 보이는 이름. 중복 허용, 20자 | 지민 |
| 보류 초대 | 로그인 전에 확인한 초대. 로그인·가입이 끝날 때까지 앱이 보관한다 | |
| 요청 키 | 생성 요청마다 하나씩 만드는 식별값. 재시도해도 결과가 하나만 생긴다 | |
| 초대 | 모임에 참여할 수 있는 링크와 코드 한 쌍. 상태는 사용 가능·소진·만료·취소 | 코드 `Q7KM2P8R` / 10.24 12:00 만료 |
| 확인 횟수 | 서버가 그 초대로 미리보기 요청을 받은 횟수. 50회면 소진 | 확인 12/50 |

## 3. 화면 흐름

```
[앱 시작] → 스플래시(세션 복원)
  ├ 세션 없음/복원 실패 ───────────────→ UI01 시작과 로그인
  ├ 가입 미완료(status=onboarding) ──→ UI02
  ├ 보류 초대 있음(초대 링크로 열림 포함) → UI24 초대 확인과 참여
  └ 정상 ─────────────────────────────→ UI03 내 모임

UI01 ─ 로그인 성공(신규) ──→ UI02 ─ 가입 완료 ─┬→ UI24   (보류 초대 있음)
UI01 ─ 로그인 성공(기존) ─────────────────────┴→ UI03     (보류 초대 없음)
UI01 ─ 이용약관·개인정보처리방침 ──→ D2 문서 보기

UI03 ─ 모임 카드 ──────────→ UI05 모임 달력
UI03 ─ "모임 만들기" ──────→ UI04 ─ 생성 성공 ─→ UI05 (UI04는 스택에서 교체)
UI03 ─ "초대 코드로 참여" ─→ UI24 (코드 입력)
UI03 ─ 하단 탭 ────────────→ [UI22 내 기록 / UI28 설정: 다른 담당]

UI05 ─ 일정 카드 ──────────→ [UI08 일정 상세: feature-spec.md]
UI05 ─ "일정 추가"(방장) ──→ UI06 추가 ─ 저장 ─→ UI05
UI05 ─ 일정 ⋯ "일정 변경"(방장) → UI06 변경 ─ 저장/취소/삭제 ─→ UI05
UI05 ─ "초대·관리" ─────────→ UI23 초대 발급과 관리
UI23 ─ "공유하기" ──────────→ [OS 공유 시트: 카카오톡 등] ─→ UI23
UI23 ─ "이 초대 취소" ──────→ D3 확인창 ─→ UI23
UI04·UI06 ─ 기간 필드 ──────→ D1 기간 선택 시트

[받은 사람] 초대 링크 탭 ──→ 앱 실행 → UI24 (로그인 전 미리보기)
UI24 ─ "로그인하고 참여 계속하기" → UI01 (→ UI02) ─→ UI24 (같은 초대, 로그인 후)
UI24 ─ "참여하기" 성공/이미 참여 ─→ UI05 (스택: UI03 → UI05)
```
- 뒤로가기는 한 단계 위 화면으로 간다. 시트·확인창(D1~D3)이 열려 있으면 그것을 먼저 닫는다.
- UI01·UI02에서 시스템 뒤로가기는 앱을 닫는다(UI02는 확인창 후). 로그인 이후 화면에서 UI01로 돌아가지 않는다.
- UI03은 로그인 후의 첫 화면(스택 바닥)이다. UI03에서 뒤로가기는 앱을 닫는다.

| 화면 | 역할 |
|---|---|
| 스플래시 | 세션 복원 중 표시 |
| UI01 시작과 로그인 | 카카오·Google 로그인 |
| UI02 가입 동의와 표시명 | 최초 가입자의 동의와 표시명 |
| UI03 내 모임 | 참여 중인 모임 목록과 생성·참여 진입 |
| UI04 모임과 첫 일정 생성 | 모임 이름과 첫 일정을 함께 입력 |
| UI05 모임 달력 | 월 달력·일정 목록, 일정 진입 |
| UI06 일정 추가와 변경 | 방장의 일정 추가·변경·취소·삭제 |
| UI23 초대 발급과 관리 | 초대 링크·코드 발급·공유·복사·취소(공유하기) |
| UI24 초대 확인과 참여 | 받은 초대 확인, 로그인 후 참여 |

## 4. 화면 상세

공통: 흰 배경(`#FFFFFF`)에 회색 면(`#F2F4F6`)으로 카드·입력창을 구분하고 그림자는 시트·토스트에만 쓴다. 주 색상 코랄(`#F1706B`, 눌림 `#DC5F5A`, 연한 면 `#FDEDEB`), 오류 `#F04452`. 좌우 여백 20, 카드 곡률 20, 버튼 곡률 14. 본문 17pt 이상. 터치 영역 최소 48dp, 주요 실행 버튼 높이 56dp 이상(팀 기준). 모든 아이콘 버튼에 접근성 라벨을 붙인다. 큰 글씨·긴 모임명·긴 일정 제목에서도 버튼과 내용이 겹치지 않아야 한다(2줄까지 표시 후 말줄임). 토큰 값은 `src/theme/theme.ts`, `src/prototype/styles/tokens.ts`를 따른다.

글자 수는 **Unicode NFC 정규화 후 앞뒤 공백을 뺀 사용자 인식 문자(grapheme) 단위**로 센다. 이름·제목은 줄바꿈을 받지 않는다. 앱과 서버가 같은 규칙을 쓴다(팀 6.1).

날짜 표시: 입력 필드는 `2026.10.17`, 카드의 기간은 `10.17–10.19`(당일 일정은 `10.24`), 해를 넘기면 `2026.12.30–2027.01.02`. 요일이 필요한 곳은 `10월 17일 토요일`.

### 4.0 스플래시 (세션 복원)
- 앱 시작 시 기기에 저장된 세션이 있으면 스플래시(로고)를 유지한 채 `sessionRefresh`를 호출한다.
- 성공 → `profileGet`으로 상태 확인: `onboarding`이면 UI02, 보류 초대가 있으면 UI24, 아니면 UI03.
- `AUTH_EXPIRED`·세션 없음 → UI01. **보류 초대·미완료 업로드 정보는 지우지 않는다.**
- 오프라인: 스플래시에서 무한 대기하지 않는다. `인터넷에 연결되어 있지 않아요` + `다시 시도`를 보여 주고 저장된 세션은 지우지 않는다.
- 초대 링크(딥링크)로 앱이 열리면 링크의 초대 값을 먼저 보류 초대로 저장한 뒤 위 순서를 따른다. **세션이 없어도 UI01이 아니라 UI24(로그인 전 미리보기)로 간다.** 로그인한 상태에서 링크를 열면 보던 화면 위에 UI24를 연다.

### 4.1 UI01 시작과 로그인
**구성**: 로고 / 워드마크 `AT THAT PLACE` / 큰 문구 `함께한 순간을\n한곳에 모아요` / 보조 문구 `모임의 일정별로 사진과 영상을 함께 보관해요.` / (하단) `카카오로 시작하기` / `Google로 시작하기` / `이용약관 · 개인정보처리방침`.
- **카카오 버튼**: 배경 `#FEE500`, 글자 `#191600`, 카카오 심볼. 카카오톡 앱 로그인을 먼저 시도하고, 앱이 없거나 쓸 수 없으면 **카카오계정 웹 로그인으로 자동 전환**한다.
- **Google 버튼**: 흰 배경 + 회색 테두리, Google 로고. 시스템 계정 선택 화면을 쓴다.
- 두 버튼 외의 로그인 수단(이메일·전화번호·Apple 등)은 두지 않는다.
- 누르면 **두 버튼을 모두 잠그고** 누른 버튼에만 로딩 표시를 한다(연속 입력 방지). 인증 창이 닫히면 잠금을 푼다.
- 인증 결과로 `authExchange`(provider, credential, nonce, loginAttemptId, `Idempotency-Key`)를 호출한다. 응답 `onboardingRequired`가 참이면 UI02, 아니면 보류 초대 여부로 UI24/UI03. 모두 **스택 교체(replace)**로 이동한다.
- **인증 취소**(사용자가 창을 닫음, `AUTH_CANCELLED`): 안내 없이 원래 상태로 돌아간다.
- **오프라인**: `인터넷에 연결되어 있지 않아요. 연결을 확인하고 다시 시도해 주세요.`
- **인증 실패**(`AUTH_INVALID`): `로그인하지 못했어요. 다시 시도해 주세요.`
- **서비스 장애**(`PROVIDER_UNAVAILABLE`, 503): `{카카오|Google} 로그인이 잠시 원활하지 않아요. 잠시 후 다시 시도하거나 다른 방법으로 시작해 주세요.`
- 오류 문구는 버튼 위에 빨간 글씨로 표시하고, 다음 로그인 시도 때 지운다.
- 하단 링크 → D2(로그인 전 열람용, `consentDocs` 사용). 로그인 전에도 열 수 있어야 한다.
- 보류 초대가 있으면 문구 아래에 `초대받은 모임에 참여하려면 로그인해 주세요.`를 한 줄 보여 준다(모임명은 UI24에서 이미 확인했으므로 반복하지 않는다).

### 4.2 UI02 가입 동의와 표시명
**구성**: 큰 제목 `처음 오셨네요` / 안내 `문서를 읽고 필요한 항목에 동의해 주세요.` / 동의 행 목록 / 표시명 입력 / 안내 `중복 표시명도 사용할 수 있어요. 최대 20자` / 주 버튼 `동의하고 시작하기`.
- **동의 행**: 서버 `consentDocs(locale=ko)`가 준 문서마다 한 행. 왼쪽 체크박스, 가운데 문서 이름, 오른쪽 `필수`(코랄) 또는 `선택`(회색) 표시와 `›`. 행 전체(체크박스 제외)를 누르면 D2로 문서를 연다. **항목 수·이름을 앱에 고정하지 않는다**(실제 항목은 운영 문서 확정 후 정해진다).
- 문서 로딩 중에는 행 자리에 로딩 표시, 실패하면 `동의 문서를 불러오지 못했어요 · 다시 시도`를 보여 주고 제출 버튼을 잠근다.
- **표시명**: 소셜 계정 이름을 초기값으로 넣는다(제안값, 지우고 바꿀 수 있음). 이름을 받지 못했으면 빈 칸 + 안내 `이름을 입력해 주세요`. 오른쪽 아래에 `n/20`.
  - 공백만 입력 → `표시명을 입력해 주세요`. 21자 이상 붙여넣기 → 20자에서 자르지 않고 그대로 두고 `표시명은 20자까지 쓸 수 있어요`(입력값 보존 원칙).
  - 줄바꿈은 입력되지 않게 막는다. 사진 프로필 입력란은 두지 않는다.
- **제출 버튼**: 필수 문서가 모두 체크되고 표시명이 유효할 때만 활성. 누르면 `onboard(displayName, consents[{documentId, version, agreed}])`를 호출한다. 선택 문서도 `agreed:false`로 함께 보낸다. 요청 중 버튼·입력 잠금.
- **오류**: `TEXT_REJECTED` → 표시명 아래 `이 표시명은 사용할 수 없어요. 다른 이름을 입력해 주세요.`(입력 유지). `CONSENT_REQUIRED`(문서 버전이 그사이 바뀜) → 문서 목록을 다시 불러오고 바뀐 항목의 체크를 해제한 뒤 `동의 문서가 바뀌었어요. 다시 확인해 주세요.`
- 성공 → 보류 초대가 있으면 UI24, 없으면 UI03(replace).
- 시스템 뒤로가기: 확인창 `가입을 그만둘까요?` / `입력한 내용은 저장되지 않아요.` / `계속하기`·`그만두기`. 그만두면 로그아웃(`logout`) 후 UI01. 보류 초대는 유지한다.

### 4.3 UI03 내 모임
**구성**: 큰 제목 `함께하는 모임` / 회색 `최근 공동 활동순` / 모임 카드 목록 / 하단 고정 `모임 만들기`(주 버튼)·`초대 코드로 참여`(테두리 버튼) / 하단 탭 `모임 | 내 기록 | 설정`.
- **모임 카드**: 왼쪽 대표 사진 정사각 썸네일(없으면 기본 이미지), 오른쪽 첫 줄 모임명(굵게, 최대 2줄), 둘째 줄 `6/10명 · {요약}`, 오른쪽 끝 `›`.
  - 요약은 서버가 고른 일정 하나: 진행 중 → `진행 중: 우리의 서울 여행`, 가까운 미래 → `다음 일정: 성수 당일치기`, 최근 과거 → `최근 일정: …`, 없으면 `아직 일정이 없어요`. **취소 일정은 요약에 쓰지 않는다.**
  - 보관 만료 7일 전·1일 전 일정이 있으면 카드 안 아래 줄에 연한 코랄 띠 `보관 안내 · 만료 7일 전 기록이 있어요`(1일 전이면 `내일 보관이 끝나는 기록이 있어요`).
  - 카드 선택 → 그 모임의 UI05.
- **정렬**: 서버가 준 순서를 그대로 쓴다(최근 공동 활동 시각 내림차순, 동률은 모임 생성 시각·식별값 역순). **열람만으로 순서가 바뀌지 않는다.** 앱에서 다시 정렬하지 않는다.
- **이어 불러오기**: 30개 단위 커서. 목록 끝에 가까워지면 다음 페이지를 부르고, 실패하면 목록 끝에 `더 불러오지 못했어요 · 다시 시도`.
- **빈 상태**(조회 성공 + 0개): 큰 글씨 `아직 함께하는 모임이 없어요`, 아래 `모임을 만들거나 받은 초대 코드로 참여해 보세요.` 하단 버튼 두 개는 그대로 보인다.
- **조회 실패**: `모임 목록을 불러오지 못했어요 · 다시 시도`. 빈 상태 문구와 섞지 않는다.
- 종료된 모임과 내가 나간 모임은 목록에 나오지 않는다(공동 상세로 열지 않는다).
- 화면에 돌아올 때마다 다시 조회하되 스크롤 위치는 유지한다.
- `모임 만들기` → UI04. 활성 모임 100개·방장 모임 20개 한도는 **버튼을 숨기지 않고** 생성 요청에서 서버가 판정한다(UI04 오류 참고).
- `초대 코드로 참여` → UI24(코드 입력 상태로 연다).
- 하단 탭 `내 기록`→UI22, `설정`→UI28. 탭은 UI03·UI22·UI28에서만 보이고 UI04 이후 화면에서는 숨긴다.

### 4.4 UI04 모임과 첫 일정 생성
**구성**: 뒤로가기, 제목 `새 모임 만들기` / 모임 이름 / 첫 일정 제목 / 시작 날짜·종료 날짜 / 안내 두 줄 / 하단 고정 `모임과 첫 일정 만들기`.
- **모임 이름**: 필수, 1~50자, 안내 문구 `예: 주말 산책 모임`, 오른쪽 아래 `n/50`.
- **첫 일정 제목**: 필수, 1~100자, 안내 문구 `예: 우리의 서울 여행`, `n/100`.
- **기간**: `시작 날짜 2026.10.17` / `종료 날짜 2026.10.19` 두 칸. 어느 칸을 눌러도 D1이 열린다. 처음에는 비어 있고 `날짜 선택` 회색 문구.
- 안내: `시간은 장소를 추가할 때 입력해요. 반복 설정은 없어요. 필요하면 일정을 더 추가해요.` / `한국 시간 · 최대 10명 · 정원 변경 없음`.
- **종일/시간 지정 토글, 반복 행, 정원 선택, 화면 배치, 여행지 입력은 두지 않는다.**
- 과거 날짜도 고를 수 있다. 종료 날짜 + 3개월이 이미 지난 기간이면 기간 아래에 `이 기간은 보관 기한이 지나 사진·영상을 올릴 수 없어요.`를 경고로 보여 주되 생성은 막지 않는다(F07).
- **제출 버튼**: 세 값이 모두 유효할 때만 활성. 누르면 `groupCreate(name, firstSchedule{title, startDate, endDate, timezone:'Asia/Seoul'})`. 요청 중 모든 입력·버튼을 잠그고 버튼에 로딩 표시.
- **요청 키**: 처음 제출할 때 만들고, 같은 입력으로 다시 시도하면 **같은 키를 재사용**한다. 입력을 바꾼 뒤 제출하면 새 키를 만든다.
- **성공**(200) → 새 모임의 UI05로 **교체 이동**(스택: UI03 → UI05). 첫 일정 시작 날짜가 있는 달을 열고 그 날짜를 선택한다. 토스트 `모임을 만들었어요`.
- **처리 중**(202 + operation, 공개 전 텍스트 검사 대기 등): 버튼 자리에 `만드는 중이에요…`를 보여 주고 `operationGet`으로 결과를 확인한다. 화면을 떠나도 생성은 계속되며, UI03에 돌아오면 생성된 모임이 보인다.
- **응답 유실**(시간 초과·연결 끊김): 실패로 단정하지 않는다. `저장 결과를 확인 중이에요`(UI35 패턴)를 보여 주고 같은 요청 키로 결과를 확인한다. 모임이 두 개 생기면 안 된다.
- **오류**: `VALIDATION_ERROR` → 해당 필드 아래 사유. `TEXT_REJECTED` → 해당 필드 아래 `사용할 수 없는 표현이 있어요. 다른 이름을 입력해 주세요.` `GROUP_LIMIT` → `참여 중인 모임이 100개라 더 만들 수 없어요.` `OWNER_CREATE_LIMIT` → `방장인 모임이 20개라 더 만들 수 없어요.` 모든 오류에서 입력값을 유지한다.
- **이탈**: 입력한 값이 있으면 확인창 `만들기를 그만둘까요?` / `입력한 내용은 저장되지 않아요.` / `계속 작성`·`나가기`. 없으면 바로 뒤로.

### 4.5 D1 기간 선택 시트
**구성**: 아래에서 올라오는 시트, 손잡이 / 제목 `일정 기간` / 안내 줄 / 월 달력 / `취소`·`선택 완료`.
- 달력은 **월요일 시작**(UI05와 같게), 좌우로 넘겨 월 이동. 오늘은 코랄 글씨.
- 첫 번째 탭 = 시작 날짜, 두 번째 탭 = 종료 날짜. 시작보다 앞 날짜를 누르면 시작 날짜를 그 날로 옮긴다. 같은 날을 두 번 누르면 당일 일정(시작=종료).
- 안내 줄: 아무것도 없을 때 `시작 날짜를 눌러 주세요.`, 시작만 있을 때 `종료 날짜를 눌러 주세요. 당일이면 같은 날을 한 번 더 눌러요.`, 둘 다 있을 때 `2026.10.17 – 10.19 · 3일`.
- 선택 범위: 양 끝은 코랄 원, 사이 날짜는 연한 코랄 띠.
- **과거 날짜를 막지 않는다.** 시작 날짜부터 366일을 넘는 날짜는 흐리게 표시하고 누를 수 없다. 누르면 `일정은 366일까지 만들 수 있어요`.
- 열 때마다 바깥 값(현재 입력값)으로 초기화한다. 취소하면 아무것도 바뀌지 않는다.
- `선택 완료`는 시작·종료가 모두 정해졌을 때만 활성.

### 4.6 UI05 모임 달력
**구성**: 뒤로가기, 모임 이름(헤더, 1줄 말줄임) / 월 머리 `‹  2026년 10월  ›` + 오른쪽 `오늘` / 보기 전환 `달력 | 일정 목록` + 오른쪽 `초대·관리 ›` / 달력(또는 일정 목록) / 선택 날짜의 일정 목록 / 하단 고정 `일정 추가`(방장만).
- **달력 격자**: 요일 머리 `월 화 수 목 금 토 일`(토 파랑·일 빨강 없이 회색 통일, 접근성). 6주 고정 높이로 그려 월마다 높이가 흔들리지 않게 한다. 이번 달이 아닌 날짜는 흐리게.
- **날짜 셀**: 날짜 숫자 아래에 일정 이름표를 **최대 3개**, 넘치면 `+N`. 여러 날 일정은 기간의 **모든 날짜 셀**에 같은 색 띠로 이어 그린다(주가 바뀌면 다음 주 첫 칸에서 다시 시작). 같은 날 여러 일정은 시작 날짜가 빠른 것, 같으면 기간이 긴 것을 위에 둔다.
  - 취소 일정은 회색 띠 + 이름 취소선으로 남긴다.
  - 오늘은 숫자에 코랄 테두리 원, 선택한 날짜는 코랄 채운 원 + 흰 숫자.
- **월 이동**: `‹ ›`와 좌우 넘김. `오늘`은 오늘이 있는 달로 가서 오늘을 선택한다.
- **날짜 선택**: 날짜를 누르면 달력 아래 `10월 17일 일정` 구역에 **그날 걸친 모든 일정**을 카드로 보여 준다(4개 이상이어도 모두). 이번 달이 아닌 흐린 날짜를 누르면 그 달로 넘어가며 선택한다.
- **일정 카드**: 첫 줄 제목(굵게, 최대 2줄), 둘째 줄 `10.17–10.19 · 장소 3곳`(장소 수는 응답에 있을 때만), 취소면 오른쪽에 회색 `취소된 일정` 배지. 카드 선택 → **UI08로 바로 이동**(날짜별 화면을 거치지 않는다, `scheduleId` 전달). 취소 일정도 열 수 있다(기록 보존 조회).
  - 방장에게는 카드 오른쪽에 `⋯` 버튼(접근성 라벨 `일정 메뉴`) → `일정 변경`(UI06 변경 모드). 취소 일정에는 `⋯`를 두지 않는다.
- **일정 목록 보기**: 보고 있는 달과 기간이 겹치는 일정을 시작 날짜 오름차순(같으면 생성 순)으로 나열한다. 카드는 위와 같고 맨 위에 시작 날짜 구분 머리 `10월 17일 토요일`. 월 이동은 그대로 쓴다.
- **보기 방식**은 기기에 사용자별로 기억한다(다음 진입 시 마지막 방식으로 연다).
- **조회**: `calendar(groupId, from, to)`로 화면에 그리는 6주 범위(최대 42일)를 한 번에 부른다. 월을 빠르게 넘기면 **마지막 요청의 응답만 반영**한다(요청 번호 비교). 이미 받은 달은 캐시로 먼저 보여 주고 다시 조회한다.
- **처음 열 때**: 모임 생성 직후(UI04에서 옴)는 첫 일정 시작 달·시작 날짜를 선택. 그 외에는 오늘이 있는 달·오늘을 선택.
- **복귀**: UI08·UI06·UI23에서 돌아오면 기준 월·선택 날짜·보기 방식·스크롤을 그대로 두고 그 범위를 다시 조회한다.
- **빈 상태**: 선택 날짜에 일정이 없으면 `이 날에는 일정이 없어요`. 모임에 일정이 하나도 없으면(마지막 빈 일정을 지운 경우 등) 달력 아래에 `아직 일정이 없어요`와, 방장에게는 `일정 추가로 첫 일정을 만들어 보세요.`, 참여자에게는 `방장이 일정을 추가하면 여기에 보여요.`
- **조회 실패**: 달력은 날짜만 그리고 띠를 비운 채 `일정을 불러오지 못했어요 · 다시 시도`. **일정 0개로 보이게 두지 않는다.**
- `초대·관리 ›` → UI23. 모든 현재 참여자에게 보인다.
- `일정 추가` → UI06 추가 모드. **현재 방장에게만** 보인다. 선택한 날짜를 시작·종료 기본값으로 넘긴다.
- **권한 상실**(`FORBIDDEN`, 내가 나갔거나 퇴장됨, 모임 종료): `이 모임을 확인할 수 없어요.` 안내 후 UI03으로 돌아가 목록을 다시 조회한다.

### 4.7 UI06 일정 추가와 변경
**구성**: 뒤로가기, 제목 `일정 추가` 또는 `일정 변경`, 부제(모임 이름) / 제목 입력 / 시작·종료 날짜 / 안내 `시간은 각 장소에서 입력해요 · 반복 없음` / (조건부) 보관 배너·겹침 안내·기간 밖 영향 카드 / 하단 고정 `저장` / (변경 모드) 맨 아래 링크 `일정 취소(기록 보존)` · `빈 일정 삭제`.
- **제목**: 필수, 1~100자, `n/100`. 변경 모드는 현재 값으로 채운다.
- **기간**: UI04와 같은 두 칸 + D1. 추가 모드는 UI05에서 선택한 날짜로 채운다(시작=종료).
- **보관 배너**(변경 모드, 첫 기록 완료로 보관 기한이 고정된 일정): `최초 기록 완료 후 보관 기한은 바뀌지 않아요 · 보관 마지막 날 2027.01.19`. 기간을 늘려도 기한은 그대로라는 뜻이다.
- **겹침 안내**: 새 기간이 같은 모임의 다른 일정(취소 제외)과 겹치면 기간 아래에 `같은 기간에 '성수 당일치기' 일정이 있어요. 그대로 저장할 수 있어요.`(2개 이상이면 `'…' 외 N개`). 저장을 막지 않는다. 겹침은 새 기간 범위로 `calendar`를 조회해 판단한다.
- **저장(추가)**: `scheduleCreate(groupId, {title, startDate, endDate, timezone})` + 요청 키. 성공 → UI05로 돌아가 새 일정의 시작 달·시작 날짜를 선택, 토스트 `일정을 추가했어요`.
- **저장(변경)**: `scheduleUpdate(scheduleId, {title?, startDate?, endDate?, expectedVersion})`. 바뀐 값만 보낸다. 성공 → UI05로 돌아가 토스트 `일정을 바꿨어요`.
  - **기간 밖 영향**(`409 OUTSIDE_RANGE_CONFIRMATION_REQUIRED`, `details{visits, media}`): 카드 `기간을 줄이면 기간 밖이 되는 기록 {media}개 · 방문 {visits}개` / `삭제되지 않고 일정 안의 '기간 밖 기록' 구역에 남아요.` / `그래도 저장`(같은 요청에 `confirmOutsideRange:true`) · `기간 다시 고르기`.
  - **버전 충돌**(`VERSION_CONFLICT`): UI35 패턴 — `다른 사람이 먼저 수정했어요. 내 입력을 유지했어요.` / `최신 내용 확인`(최신 값을 보여 주기만) / `최신 내용에 다시 적용`(최신 버전으로 내 입력 재요청) / `취소`. 말없이 덮어쓰지 않는다.
  - `SCHEDULE_CANCELLED` → `취소된 일정은 바꿀 수 없어요.` 후 UI05.
- 저장 중에는 입력·버튼을 잠근다. 실패하면 입력을 유지하고 `저장하지 못했어요 · 다시 시도`.
- **일정 취소**(변경 모드): 확인창 D3 `일정을 취소할까요?` / `기록은 보관 기한까지 남아요. 취소하면 누구도 새 사진·영상을 올릴 수 없고 되돌릴 수 없어요.` / `일정 취소`(빨강) · `돌아가기`. → `scheduleCancel(expectedVersion)`. 성공 → UI05, 토스트 `일정을 취소했어요`. `ALREADY_CANCELLED` → 이미 취소된 것으로 화면을 갱신.
- **빈 일정 삭제**(변경 모드): 확인창 D3 `일정을 삭제할까요?` / `방문 계획 {n}곳도 함께 지워지고 되돌릴 수 없어요.`(방문 0이면 둘째 문장만) / `삭제`(빨강) · `돌아가기`. → `scheduleDelete(expectedVersion)`. 성공 → UI05, 토스트 `일정을 삭제했어요`.
  - `NOT_EMPTY` → 확인창 `기록이 있는 일정은 삭제할 수 없어요` / `대신 일정을 취소하면 기록은 보관 기한까지 남아요.` / `일정 취소로 진행` · `닫기`.
  - 기록·업로드 존재 여부를 일정 상세 응답으로 알 수 있으면 해당하지 않는 링크를 숨긴다. 알 수 없으면 두 링크를 모두 보이고 서버 판정을 따른다.
- **이탈**: 변경이 있으면 D3 `저장하지 않은 변경이 있어요` / `저장` · `변경 버리기` · `계속 편집`(팀 F10과 같은 3택). 변경이 없으면 바로 뒤로.
- **권한**: 방장만 들어올 수 있다. 저장 중 `FORBIDDEN`(방장이 바뀜) → `방장만 일정을 바꿀 수 있어요.` 후 UI05로 돌아가 다시 조회한다.

### 4.8 UI23 초대 발급과 관리 (공유하기)
**구성**: 뒤로가기, 큰 제목 `모임에 초대하기` / 회색 `현재 6/10명 · 초대는 7일 · 확인 50회까지` / 현재 초대 카드 / `링크 복사`·`공유하기` / `이 초대 취소` / 안내 `받은 사람이 다른 사람에게 전달하면 그 사람도 참여할 수 있어요.` / `이전 초대` 목록 / 하단 고정 `새 초대 발급`.
- **누가**: 방장을 포함한 **모든 현재 참여자**. 방장 전용 표시나 잠금을 두지 않는다.
- **현재 초대 카드**: 사용 가능한 초대 중 가장 최근에 발급한 것. 위에 `초대 코드`, 가운데 큰 글씨 코드 `Q7KM2P8R`(고정폭, 글자 간격 넓게, 누르면 코드 복사), 아래 `10.17 12:00 발급 → 10.24 12:00 만료 · 확인 12/50`. 시각은 한국 시간 `MM.DD HH:mm`.
  - 남은 확인이 10회 이하면 `확인 45/50 · 5회 남음`을 코랄로 강조한다.
- **`링크 복사`**(테두리 버튼): 초대 링크만 클립보드에 넣고 토스트 `링크를 복사했어요`. 코드를 누르면 `코드를 복사했어요`.
- **`공유하기`**(주 버튼): OS 공유 시트를 연다. 메시지는 아래 형식이며 **모임명·일정 요약·링크·코드만** 담는다(대표 사진·참여자·장소·기록 없음).
  ```
  [At that place] '주말 산책 모임'에 초대해요.
  일정: 우리의 서울 여행 (10.17–10.19)
  링크를 누르거나 앱에서 코드 Q7KM2P8R 를 입력하세요.
  https://{초대 링크}
  10.24 12:00까지 참여할 수 있어요.
  ```
  - 일정 요약은 취소되지 않은 진행 중 → 가장 가까운 미래 → 최근 과거 일정 하나, 없으면 줄을 뺀다.
  - 공유 시트를 닫거나 공유를 취소해도 **초대는 그대로**다(공유 취소 ≠ 초대 취소). 공유 시트를 열 수 없으면 `링크 복사`로 안내한다.
- **`이 초대 취소`**(빨간 글씨 링크) → D3 `이 초대를 취소할까요?` / `이 링크와 코드로는 더 이상 참여할 수 없어요. 이미 참여한 사람은 그대로예요.` / `초대 취소`(빨강)·`돌아가기`. → `inviteRevoke(inviteId, expectedVersion)`. 성공 → 카드가 이전 초대 목록으로 내려가고 토스트 `초대를 취소했어요`.
- **이전 초대 목록**: 현재 카드에 없는 나머지 초대를 발급 최신순으로. 행마다 코드, `10.16 발급 · {상태}`, 상태 배지 `사용 가능`(코랄)·`소진 50/50`·`만료`·`취소`(회색). 사용 가능한 행에는 `공유`·`취소` 버튼. 소진·만료·취소 행은 보기만 한다.
- **`새 초대 발급`**: `inviteCreate(groupId)` + 요청 키. 성공하면 새 초대가 현재 카드가 되고 확인 횟수는 0부터 시작, **기존 초대는 원래 기한·남은 횟수대로 유지**한다. 토스트 `새 초대를 만들었어요`. 같은 요청의 재시도(응답 유실)는 같은 초대를 돌려받는다.
- **빈 상태**(사용 가능한 초대 없음): 카드 자리에 `지금 사용할 수 있는 초대가 없어요` / `새 초대를 발급해 링크를 보내 보세요.` `링크 복사`·`공유하기`는 숨긴다. 화면에 들어왔다고 자동 발급하지 않는다.
- **정원 10/10**: 발급·공유는 막지 않고 회색 줄 `지금은 정원이 다 찼어요. 자리가 나야 새로 참여할 수 있어요.`
- **갱신**: 화면 진입·복귀(공유 시트에서 돌아올 때 포함) 시 `invitesList`로 다시 조회한다. 화면을 보는 중 만료 시각이 지나면 그 카드를 만료로 바꾸고 다시 조회한다.
- **오류**: 목록 실패 `초대를 불러오지 못했어요 · 다시 시도`. 발급 실패 `초대를 만들지 못했어요 · 다시 시도`, 결과 불명은 `저장 결과를 확인 중이에요`(UI35, 같은 요청 키). 취소 `VERSION_CONFLICT`(다른 참여자가 먼저 바꿈) → 목록을 다시 불러오고 `초대 상태가 바뀌어 다시 불러왔어요`. `GROUP_CLOSED` → `종료된 모임이라 초대할 수 없어요.` `FORBIDDEN`(나갔거나 퇴장, 이용 제한) → `이 모임을 확인할 수 없어요.` 후 UI03.
- 발급자 이름은 화면에 쓰지 않는다(서버 이력용, 관리 권한의 기준이 아님).

### 4.9 UI24 초대 확인과 참여
**구성**: 뒤로가기(닫기), 큰 제목 `초대 확인` / 초대 코드 입력 / 미리보기 카드 / 안내 `참여 후에 장소와 기록을 볼 수 있어요.` / 주 버튼(로그인 상태에 따라 하나) / 안내 `확인한 내용은 로그인 뒤에도 유지돼요. 초대는 7일 · 확인 50회까지`.
- **진입 세 가지**: ① 초대 링크(로그인 전·후 모두) → 코드 칸을 링크 값으로 채우고 바로 확인 ② UI03 `초대 코드로 참여` → 빈 코드 칸에 키보드를 띄움 ③ 로그인·가입 완료 후 복귀 → 보류 초대의 미리보기를 그대로 표시.
- **코드 입력**: 영문 대문자·숫자만, 공백·하이픈은 지우고 소문자는 대문자로 바꾼다. 붙여넣은 텍스트에 초대 링크가 들어 있으면 링크에서 코드를 꺼낸다. 8자가 되면 `확인` 활성(코드 길이 8자는 설계안이며 확정 시 상수만 바꾼다).
- **확인**: `invitePreview(tokenOrCode)`. 서버는 **성공 응답마다 확인 횟수를 1 올린다.** 그래서 앱은 받은 결과를 보류 초대로 보관하고 같은 화면·로그인 복귀에서 **다시 부르지 않는다.** 확인 버튼은 요청 중 잠근다.
- **미리보기 카드**: 첫 줄 모임명(굵게), 둘째 줄 일정 요약 `우리의 서울 여행 · 10.17–10.19`(없으면 `아직 일정이 없어요`). **대표 사진·참여자·인원·장소·기록은 보이지 않는다.**
- **로그인 전**: 주 버튼 `로그인하고 참여 계속하기` → 보류 초대 저장 후 UI01. 로그인(신규면 UI02까지) 끝나면 이 화면으로 돌아온다. **로그인 성공만으로 자동 참여하지 않는다.**
- **로그인 후**: 주 버튼 `참여하기` → `inviteJoin(tokenOrCode)` + 요청 키(확인 횟수를 쓰지 않는다). 서버가 초대 기한·횟수·취소, 모임 상태, 정원 10명, 내 활성 모임 100개, 재참여 차단, 이용 제한을 다시 검사한다.
  - 성공 → 그 모임의 UI05(스택: UI03 → UI05), 토스트 `'주말 산책 모임'에 참여했어요`, 보류 초대 삭제.
  - `alreadyMember` → 인원을 늘리지 않고 UI05, 토스트 `이미 참여 중인 모임이에요`.
- **참여할 수 없을 때**(확인·참여 둘 다): 카드 자리에 사유와 다음 행동. 입력한 코드는 지우지 않는다.

  | 코드 | 문구 |
  |---|---|
  | `INVITE_INVALID` | `초대 코드가 맞지 않아요. 다시 확인해 주세요.` |
  | `INVITE_EXPIRED` | `기한(7일)이 지난 초대예요. 초대한 사람에게 새 초대를 받아 주세요.` |
  | `INVITE_EXHAUSTED` | `확인 횟수(50회)를 모두 쓴 초대예요. 새 초대를 받아 주세요.` |
  | `INVITE_REVOKED` | `취소된 초대예요. 새 초대를 받아 주세요.` |
  | `GROUP_CLOSED` | `종료된 모임이에요.` |
  | `CAPACITY_FULL` | `모임 정원(10명)이 다 찼어요.` |
  | `REENTRY_BLOCKED` | `이 모임에는 다시 참여할 수 없어요.`(사유를 더 밝히지 않는다) |
  | `GROUP_LIMIT` | `참여 중인 모임이 100개라 더 참여할 수 없어요.` |
  | 이용 제한(`FORBIDDEN`) | `지금은 모임에 참여할 수 없어요.` + `문의하기` |

  - 만료·소진·취소·종료·차단은 다시 시도해도 안 되므로 버튼을 `닫기`로 바꾸고 보류 초대를 지운다. 정원 초과·모임 100개는 상황이 바뀔 수 있어 `다시 시도`를 남긴다.
  - 오프라인·서버 오류는 `인터넷에 연결되어 있지 않아요` / `초대를 확인하지 못했어요 · 다시 시도`로 위와 구분한다.
- **동시성**: 9명일 때 두 사람이 동시에 참여해도 10명까지만 확정된다(서버). 49회일 때 동시 확인도 50회까지만 성공한다. 앱은 서버 응답만 따른다.
- **닫기/뒤로가기**: 사용자가 닫으면 보류 초대를 지운다. 로그인 전이면 UI01, 로그인 후면 이전 화면(없으면 UI03).

### 4.10 D2 문서 보기 / D3 확인창
**D2 문서 보기**: 전체 화면. 헤더 문서 이름과 닫기 ✕, 본문 위에 `버전 {version} · 시행일 YYYY.MM.DD`, 본문은 서버가 준 문서 주소의 내용. 가입 중(UI02)에서 열었으면 하단에 `동의하고 닫기`(누르면 그 행을 체크하고 돌아감). 로딩 실패 시 `문서를 불러오지 못했어요 · 다시 시도`.

**D3 확인창**: 가운데 카드. 제목·본문·버튼 1~3개. 되돌릴 수 없는 동작의 확인 버튼은 빨간색. 시스템 뒤로가기는 가장 안전한 선택(`돌아가기`/`계속 편집`)과 같다. 팀원 명세의 M3와 같은 컴포넌트를 쓴다.

## 5. 핵심 처리 규칙

| 항목 | 규칙 |
|---|---|
| 계정 식별 | (공급자, 공급자 사용자 식별값)으로 계정을 찾는다. 같은 이메일의 다른 공급자 계정은 **별개 계정**이며 자동으로 합치지 않는다. 다른 수단 연결은 설정(UI29)에서 재인증 후 한다 |
| 세션 | 액세스 토큰 만료 시 `sessionRefresh`로 한 번 갱신하고 원래 요청을 다시 보낸다. 갱신 실패(`AUTH_EXPIRED`)면 UI01로 보내고 로그인 후 **보던 화면으로 복귀**한 뒤 권한을 다시 확인한다 |
| 보류 상태 보존 | 보류 초대(토큰/코드와 확인 결과)와 미완료 업로드 정보는 로그인 취소·실패·로그아웃 전 단계에서 지우지 않는다. 계정이 바뀌면 다른 계정의 캐시와 분리한다 |
| 가입 완료 | 필수 동의 + 유효한 표시명이 모두 서버에 저장된 뒤에만 완료. 가입 미완료 사용자는 모임·일정 화면에 들어갈 수 없다 |
| 글자 수 | NFC 정규화·앞뒤 공백 제거 후 사용자 인식 문자 단위. 표시명 20, 모임 이름 50, 일정 제목 100. 줄바꿈 불가 |
| 날짜 | `YYYY-MM-DD`, Asia/Seoul. 시작 ≤ 종료, 종료 포함 최대 366일(DB `end_date - start_date <= 365`). 과거 날짜 허용 |
| 오늘 | 기기 시간대와 상관없이 한국 시간의 오늘 |
| 모임 생성 | 모임·방장 참여·첫 일정이 한 번에 생성. 요청 키로 재시도해도 하나만 생긴다. 활성 참여 100개·방장 모임 20개 한도는 서버 판정 |
| 모임 목록 순서 | 서버의 최근 공동 활동순을 그대로 쓴다. 활동 = 모임 생성·이름/대표 사진 변경·참여/나가기·일정/방문/완료 기록의 생성·수정·삭제. 단순 열람은 제외 |
| 대표 일정 요약 | 진행 중 → 가장 가까운 미래 → 가장 최근 과거, 취소 제외(서버가 계산) |
| 달력 조회 | 한 요청은 최대 366일(`RANGE_TOO_LARGE`). 화면은 6주(42일) 범위만 요청한다. 늦게 온 이전 월 응답이 최신 월을 덮지 않는다 |
| 겹치는 일정 | 같은 모임에서 기간이 겹쳐도 저장한다. 저장 전 안내만 하고 병합·복제하지 않는다 |
| 일정 변경 | 대상 식별값은 그대로, `expectedVersion`으로 낙관적 잠금. 기간 밖 영향은 서버가 계산하고 사용자 확인 후 저장 |
| 취소·삭제 | 기록·진행 중 업로드가 있으면 삭제 불가 → 취소. 취소는 되돌리지 않는다. 빈 일정 삭제는 빈 방문 계획을 함께 지운다. 마지막 일정을 지워도 모임·참여자·초대는 유지 |
| 보관 기한 | 최초 기록 완료 시점에 `종료 날짜 + 3개월`(없는 날은 말일)로 고정. 이후 기간을 바꿔도 기한은 그대로(F21). 이 화면은 표시만 한다 |
| 권한 | 일정 추가·변경·취소·삭제는 현재 방장. 초대 관리는 모든 현재 참여자. 버튼 숨김과 별개로 서버가 매 요청 검증 |
| 초대 유효기간 | 서버 발급 시각 ≤ 현재 < 발급 + 168시간일 때만 확인·참여. 조회·공유·재전달로 기한이 늘지 않는다 |
| 확인 횟수 | 성공한 미리보기 응답마다 +1(로그인 여부·같은 사람 재확인과 무관). 50회면 소진. 로그인 복귀·참여하기는 횟수를 쓰지 않는다 |
| 초대 발급 | 요청마다 새 링크·코드. 이전 초대는 원래 기한·남은 횟수 유지. 같은 요청 키 재시도는 같은 초대 |
| 초대 영향 | 소진·만료·취소는 이미 참여한 사람에게 영향 없음. 발급자가 나가도 그 초대는 자동으로 바뀌지 않는다 |
| 참여 | 한 계정은 한 모임에 활성 참여 하나. 정원 10명·활성 모임 100개·재참여 차단·이용 제한을 서버가 참여 시 재검증 |

### 6.2 테이블 (팀 DB 설계를 그대로 쓴다)
> 실제 스키마는 팀 DB 설계(`1차 개발 설계서/02 데이터베이스 설계`, `부록/DB/001_initial.sql`, PostgreSQL)다. 이 화면이 읽고 쓰는 테이블과 핵심 제약만 정리한다.

| 테이블 | 이 화면과 관련된 컬럼·제약 |
|---|---|
| `users` | `display_name`(공백만·줄바꿈 불가), `status` `onboarding → active` (가입 완료 시 전환) |
| `identities` | 공급자·공급자 사용자 식별값으로 사용자 연결(이메일 병합 없음) |
| `sessions` | `device_id`, `refresh_hash`, `expires_at`, `revoked_at` |
| `consent_documents` | `item_key`, `version`, `required`, `content_ref`, `effective_at`, `UNIQUE(item_key, version)` |
| `consent_events` | 문서·버전별 동의/거부/철회 시각 기록 |
| `groups` | `name`, `owner_user_id`, `status(active/closed)`, `cover_asset_id`, `activity_at`(목록 정렬), `version` |
| `memberships` | `group_id`, `user_id`, `ended_at`/`end_reason`(나감·퇴장·종료·계정 삭제) |
| `schedules` | `title`, `start_date`, `end_date`, `status(active/cancelled/deleted)`, `cancelled_at`, `retention_last_date`, `expires_at`, `version`, `CHECK(end_date >= start_date AND end_date - start_date <= 365)` |
| `invitations` | `group_id`, `issuer_user_id`(이력용), `code_hash`·`token_hash`(원문은 암호문으로만 보관), `issued_at`, `expires_at = issued_at + 168시간`(CHECK), `revoked_at`, `use_count 0~50`, `max_uses = 50`, `exhausted_at`, `version` |
| `reentry_blocks` | 강제 퇴장 후 재참여 차단(참여 시 `REENTRY_BLOCKED`) |
| `operations` | `idempotency_key`, `route`, `state`, `response_snapshot`, `UNIQUE(actor_id, route, idempotency_key)` — 요청 키 재시도·결과 확인 |

팀 설계에서 제거된 `recurrence_series`·`recurrence_exceptions`, `schedules.all_day/start_at/end_at`은 쓰지 않는다.

## 7. 팀 연결 계약

### 7.1 입력·출력 요약
| 연결 | 입력 | 이 화면의 처리 |
|---|---|---|
| UI05 → UI08 일정 상세 | `groupId`, `scheduleId` (+ 표시용 제목·기간) | 일정 카드 선택 시 이동. **표시용 값을 식별자로 쓰지 않는다** |
| UI08 → UI05 복귀 | 일정 변경·취소·삭제 여부 | 기준 월·선택 날짜 유지, 범위 재조회 |
| 초대 링크(딥링크) → 앱 | 링크 주소 `…/invite/{token}` | 앱 링크(Android App Links)로 열어 UI24. 앱이 없으면 스토어 안내 웹 페이지(웹 페이지에도 모임명·일정 요약만) |
| 앱 → OS 공유 시트 | 메시지 텍스트(4.8 형식) | 카카오톡 등 받는 앱은 사용자가 고른다. 결과(보냄·취소)는 쓰지 않는다 |
| UI03 하단 탭 | — | UI22·UI28로 전환 |
| UI28 로그아웃 → UI01 | — | 세션·사용자 캐시 정리 후 UI01 |
| 결과 불명·충돌 | `operationId` | UI35 공통 패턴으로 확인 |

### 7.2 API (팀 설계 v0.3.1의 operation 이름을 따른다)
| 목적 | 팀 API (operationId · 경로) | 요청 → 응답 · 도메인 오류 |
|---|---|---|
| 로그인 | `authExchange` · `POST /auth/exchange` | provider(kakao\|google), credential, nonce, loginAttemptId + `Idempotency-Key` → session, user, onboardingRequired · AUTH_CANCELLED, AUTH_INVALID, PROVIDER_UNAVAILABLE |
| 세션 갱신 | `sessionRefresh` · `POST /auth/refresh` | refreshToken → session · AUTH_EXPIRED |
| 내 프로필 | `profileGet` · `GET /me/profile` | → profile · AUTH_EXPIRED |
| 동의 문서 | `consentDocs` · `GET /consent-documents` | locale=ko → documents[{id, version, required, url}] · DOCUMENT_UNAVAILABLE |
| 가입 완료 | `onboard` · `POST /onboarding` | displayName, consents[{documentId, version, agreed}] → user, consentReceipts · CONSENT_REQUIRED, TEXT_REJECTED |
| 로그아웃(가입 중단) | `logout` · `POST /auth/logout` | deviceId, pendingAction → sessionRevoked · PENDING_UPLOADS |
| 모임 목록 | `groupsList` · `GET /groups` | cursor?, limit≤30 → items[], nextCursor · AUTH_EXPIRED |
| 모임+첫 일정 생성 | `groupCreate` · `POST /groups` | name, firstSchedule{title, startDate, endDate, timezone} → group, membership, firstSchedule (또는 202 operation) · GROUP_LIMIT, OWNER_CREATE_LIMIT, VALIDATION_ERROR, TEXT_REJECTED |
| 달력 | `calendar` · `GET /groups/{groupId}/calendar` | from, to(포함, ≤366일) → schedules[], dateCounts · RANGE_TOO_LARGE, FORBIDDEN |
| 일정 추가 | `scheduleCreate` · `POST /groups/{groupId}/schedules` | {title, startDate, endDate, timezone} → schedule (또는 operation) · VALIDATION_ERROR, TEXT_REJECTED, FORBIDDEN |
| 일정 변경 | `scheduleUpdate` · `PATCH /schedules/{scheduleId}` | title?, startDate?, endDate?, expectedVersion, confirmOutsideRange? → schedule · VERSION_CONFLICT, OUTSIDE_RANGE_CONFIRMATION_REQUIRED(details{visits, media}), TEXT_REJECTED, FORBIDDEN, SCHEDULE_CANCELLED |
| 일정 취소 | `scheduleCancel` · `POST /schedules/{scheduleId}/cancellation` | expectedVersion → schedule(status=cancelled) · VERSION_CONFLICT, ALREADY_CANCELLED, FORBIDDEN |
| 빈 일정 삭제 | `scheduleDelete` · `POST /schedules/{scheduleId}/deletion` | expectedVersion → deletedId, deletedVisitIds · NOT_EMPTY, VERSION_CONFLICT, FORBIDDEN |
| 일정 상세(방문 수·보관 기한) | `scheduleDetail` · `GET /schedules/{scheduleId}` | → schedule, retention, plan[], version · FORBIDDEN, EXPIRED |
| 결과 확인 | `operationGet` · `GET /operations/{operationId}` | → operation{state, result} · NOT_FOUND |
| 초대 목록 | `invitesList` · `GET /groups/{groupId}/invites` | cursor? → invites[] · FORBIDDEN |
| 초대 발급 | `inviteCreate` · `POST /groups/{groupId}/invites` | (본문 없음) + `Idempotency-Key` → invite{id, link, code, issuedAt, expiresAt, useCount:0, maxUses:50, state} · GROUP_CLOSED, FORBIDDEN |
| 초대 취소 | `inviteRevoke` · `POST /invites/{inviteId}/revocation` | expectedVersion → invite · FORBIDDEN, VERSION_CONFLICT |
| 초대 확인 | `invitePreview` · `GET /invite-preview` | tokenOrCode (성공마다 useCount+1) → groupName, scheduleSummary, inviteState, usesRemaining · INVITE_INVALID, INVITE_EXPIRED, INVITE_EXHAUSTED, INVITE_REVOKED, GROUP_CLOSED |
| 참여 | `inviteJoin` · `POST /invitations/join` | tokenOrCode (횟수 미소모) + `Idempotency-Key` → groupId, membershipId, alreadyMember · INVITE_EXPIRED, INVITE_EXHAUSTED, INVITE_REVOKED, CAPACITY_FULL, REENTRY_BLOCKED, GROUP_CLOSED, GROUP_LIMIT |

공통 오류 응답은 `{code, message, requestId, retryable, operationId?, currentVersion?, details?, itemErrors?}`이다. 화면 문구는 `code`로 고르고 서버 `message`를 그대로 띄우지 않는다. `requestId`는 문의용 번호로만 보여 준다(UI35).

### 7.3 보류 초대 계약
```ts
// 앱 내부 저장(계정과 분리된 기기 저장소). 스플래시·UI01·UI02·UI24가 함께 쓴다.
type PendingInvite = {
  tokenOrCode: string;
  preview: { groupName: string; scheduleSummary: string | null }; // invitePreview 결과(다시 부르지 않음)
  savedAt: number; // epoch ms
};

// 로그인·가입 화면이 끝날 때 다음 화면을 고르는 규칙
function nextAfterAuth(p: { onboardingRequired: boolean; pending: PendingInvite | null }):
  'UI02' | 'UI24' | 'UI03';
```
- 보류 초대는 UI24에서 참여가 끝나거나(성공·이미 참여) 사용자가 그 초대를 닫았을 때만 지운다. 로그인 실패·취소로 지우지 않는다.
- 초대 유효기간(7일)·확인 횟수(50회)·정원은 참여할 때 서버가 다시 검사한다. 앱은 숫자를 직접 판정하지 않고 응답 코드를 따른다.

### 7.4 팀 합의가 필요한 항목
부록 D.4의 차이 항목 / 실제 동의 문서 항목·문구(10/26 회의: 약관 항목 조사) / 카카오·Google 앱 등록 정보(키 해시, OAuth 클라이언트) / 일정 변경의 진입 위치(UI05 `⋯` 메뉴와 UI08 중 어디에 둘지) / 일정 목록 보기의 범위·정렬 / 초대 링크 도메인과 앱 링크 설정(`assetlinks.json`), 앱 미설치 시 웹 안내 페이지 / 초대 메시지 문구 / 카카오톡 공유를 OS 공유 시트로만 할지 카카오 공유 SDK를 쓸지.

## 8. 상태·오류 문구

| 상황 | 사용자에게 보이는 동작 |
|---|---|
| 세션 복원 중 | 스플래시 유지. 오프라인이면 무한 대기하지 않고 `인터넷에 연결되어 있지 않아요` + `다시 시도` |
| 로그인 취소 | 안내 없이 UI01 원래 상태 |
| 로그인 실패 | `로그인하지 못했어요. 다시 시도해 주세요.` |
| 로그인 서비스 장애 | `{카카오|Google} 로그인이 잠시 원활하지 않아요. 잠시 후 다시 시도하거나 다른 방법으로 시작해 주세요.` |
| 동의 문서 실패 | `동의 문서를 불러오지 못했어요 · 다시 시도`, 제출 잠금 |
| 표시명 오류 | 공백 `표시명을 입력해 주세요` / 21자 `표시명은 20자까지 쓸 수 있어요` / 검사 거부 `이 표시명은 사용할 수 없어요. 다른 이름을 입력해 주세요.` |
| 초기 로딩 | 로딩 표시. 응답 전에는 모임 0개·일정 0개로 단정하지 않는다 |
| 모임 없음 | `아직 함께하는 모임이 없어요` / `모임을 만들거나 받은 초대 코드로 참여해 보세요.` |
| 모임 목록 실패 | `모임 목록을 불러오지 못했어요 · 다시 시도` |
| 모임 한도 | `참여 중인 모임이 100개라 더 만들 수 없어요.` / `방장인 모임이 20개라 더 만들 수 없어요.` |
| 입력 검사 거부 | `사용할 수 없는 표현이 있어요. 다른 이름을 입력해 주세요.` |
| 결과 불명 | `저장 결과를 확인 중이에요` → 같은 요청 결과 확인(UI35) |
| 기간 초과 | `일정은 366일까지 만들 수 있어요` |
| 보관 기한 지난 기간 | `이 기간은 보관 기한이 지나 사진·영상을 올릴 수 없어요.`(생성은 허용) |
| 날짜에 일정 없음 | `이 날에는 일정이 없어요` |
| 모임에 일정 없음 | `아직 일정이 없어요` + 방장/참여자별 안내 |
| 달력 조회 실패 | `일정을 불러오지 못했어요 · 다시 시도`(빈 달력과 구분) |
| 겹치는 일정 | `같은 기간에 '{제목}' 일정이 있어요. 그대로 저장할 수 있어요.` |
| 기간 밖 영향 | `기간을 줄이면 기간 밖이 되는 기록 a개 · 방문 b개` / `삭제되지 않고 일정 안의 '기간 밖 기록' 구역에 남아요.` |
| 저장 실패 | `저장하지 못했어요 · 다시 시도`, 입력 유지 |
| 저장 충돌 | `다른 사람이 먼저 수정했어요. 내 입력을 유지했어요.` → 최신 내용 확인 / 다시 적용 |
| 기록 있는 일정 삭제 | `기록이 있는 일정은 삭제할 수 없어요` → 일정 취소 안내 |
| 취소된 일정 변경 | `취소된 일정은 바꿀 수 없어요.` |
| 방장 권한 없음 | `방장만 일정을 바꿀 수 있어요.` |
| 모임 접근 불가 | `이 모임을 확인할 수 없어요.` 후 UI03 |
| 초대 목록 실패 | `초대를 불러오지 못했어요 · 다시 시도` |
| 사용 가능한 초대 없음 | `지금 사용할 수 있는 초대가 없어요` / `새 초대를 발급해 링크를 보내 보세요.` |
| 초대 발급 실패 | `초대를 만들지 못했어요 · 다시 시도` |
| 초대 취소 충돌 | `초대 상태가 바뀌어 다시 불러왔어요` |
| 정원 다 참 | `지금은 정원이 다 찼어요. 자리가 나야 새로 참여할 수 있어요.`(UI23) / `모임 정원(10명)이 다 찼어요.`(UI24) |
| 초대 참여 불가 | 4.9 표의 코드별 문구 |
| 참여 성공 / 이미 참여 | 토스트 `'{모임명}'에 참여했어요` / `이미 참여 중인 모임이에요` |
| 네트워크 없음 | 새 조회·생성·변경을 막고 `인터넷에 연결되어 있지 않아요` + `다시 시도`. 입력값은 지우지 않는다 |

토스트는 약 2초 표시(`모임을 만들었어요`, `일정을 추가했어요`, `일정을 바꿨어요`, `일정을 취소했어요`, `일정을 삭제했어요`, `링크를 복사했어요`, `코드를 복사했어요`, `새 초대를 만들었어요`, `초대를 취소했어요`).

## 11. 구현 순서 제안
1. 순수 로직: 글자 수 계산(NFC·grapheme), 날짜 계산(한국 시간 오늘, 366일, 6주 범위, 여러 날 띠 배치, `+N`), 다음 화면 결정(`nextAfterAuth`)을 먼저 만들고 단위 테스트한다.
2. 인증: 스플래시 세션 복원 → UI01(카카오·Google) → UI02 → 보류 초대 보존.
3. 조회: UI03 → UI05(달력·일정 목록·복원).
4. 생성·편집: D1 → UI04(요청 키·결과 확인) → UI06(추가·변경·충돌·기간 밖·취소·삭제).
5. 초대: UI23(목록·발급·복사·공유·취소) → 앱 링크 설정 → UI24(미리보기·보류 초대·로그인 복귀·참여·오류 표).
6. 오류·로딩·권한 상실(8장)과 접근성 라벨, 큰 글씨 확인.
7. QA 시나리오 전체를 Android 12 이상 실기기에서 확인한다(카카오톡 설치/미설치, 앱 설치/미설치 상태의 초대 링크 둘 다).
