# 2026-10-30 UI 통합 설계

기준: 기능명세 v2.3 / 설계 v0.3.3 / UI `feature/ui-prototype@a67ee60`.

최신 캡처는 **디자인 참고용 데모 실행 화면**이다. 아래 제품 적용 기준과 화면별 계약을 함께 사용한다. 별도 정책 승인이 필요한 버튼은 제품 구현에서 보류한다. 기존 업무 API·DB 구조는 유지하고, 이미 확정된 가입 구성에 맞춰 문서의 동의/고지 구분과 게시 본문 필드를 API·DB 설계에 동기화한다. 운영 DB는 변경하지 않는다. 판단 배경과 미결 사항은 [10월 30일 회의 안건](../../회의록/10월%2030일%20회의%20안건.md)에 있다.

## 제품 화면 전환

```mermaid
flowchart TD
  Home[UI03 내 모임] --> Group[UI05 모임 달력]
  Group --> Detail[UI08 일정 전체 계획 · 날짜 필터]
  Detail --> All[UI09 전체 기록 · 미지정 · 기간 밖]
  Detail --> Day[UI08 날짜별 장소]
  Day --> Search[UI10 장소 추가]
  Search --> Day
  Day --> Edit[UI12 순서 · 시각 · 제목]
  Day --> Records[UI13 방문 기록]
  Records --> Select[UI16 선택]
  Select --> Save[UI21 휴대폰 저장]
  Detail --> Members[UI26 참여자]
  Members --> Invite[UI23 초대 관리]
  Home --> My[UI36 마이페이지]
  My --> Settings[UI28 설정]
  My --> Mine[UI22 내가 올린 기록]
  Settings --> Account[UI37 프로필 및 계정]
  Settings --> Join[UI24 초대 확인 · 참여]
  Settings --> Rights[내 기록 · 신고/차단 · 문의 · 캐시 · 계정 삭제]
```

S01만을 의무 첫 화면으로 사용하는 변경은 A02 합의 전 보류한다. 요약 배너·날짜 카드는 UI08에 반영하면서 전체 보기 접근을 유지한다. `roomId`는 이 UI의 일정(`scheduleId`)에 대응하고, 참여·초대는 상위 `groupId`, 방문 기록은 `scheduleId + visitDate + visitId`로 범위를 확인한다. 임의 날짜 ID를 별도 여행방으로 저장하지 않는다.

모든 화면은 서버 응답 후 완료 처리한다. 진행·빈 결과·조회 실패를 구분하고, 복귀 시 날짜·필터·스크롤을 유지한다. 전체 선택은 불러온 선택 가능 파일 중 최대120개이고, 권한 상실·삭제·만료 시 선택/집계를 갱신한다. 사진·영상 파일 외부 공유는 제공하지 않는다.
