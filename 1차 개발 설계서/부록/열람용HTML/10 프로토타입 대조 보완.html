기준과 이번 검토 범위

검토 기준일은 2026-11-03(Asia/Seoul)이다. 네 worktree 모두 로컬 변경이 없는 상태에서 각각 git pull --ff-only를 실행했고 모두 Already up to date였다. 이 문서의 커밋은 검토 시작점이며 이후 최신 커밋을 자동 의미하지 않는다.

이번 작업은 소스·mock·라우트·기존 캡처 출처·문서 생성 모델·OpenAPI·DB 정의를 정적으로 대조했다. 기존 v3 작성 당시의 실행 관찰과 이번 검증을 구분한다. 새로운 앱 실행·실기기·외부 공급자 검수는 수행하지 않았다.

우선순위는 연결된 일반 프로토타입 화면/동작 → 동일 커밋 UI 정리 PPT의 시각 표현 → 프로토타입에 없는 기존 명세다. 코드와 PPT 충돌은 Q 항목으로 남긴다. 데모 브리지·토스트·메모리 저장·샘플 인원·미연결 실험은 실제 API/영속 저장/권한 완료로 인정하지 않는다.

11월 3일 최초 대조에서는 C01~C13 모두 반영 대기였다. 현재 9f64b5e에서는 C06/C13의 UI가 부분 반영됐으며 실제 렌더·갤러리 저장은 대기다. C01~C05·C07~C12는 여전히 반영 대기다. 현재 프로토타입 우선이라는 작업 지시를 따라 아직 UI에 없는 요청은 이번 문서 보완만으로 현행 정책을 바꾸지 않았다. PM·디자이너의 다음 프로토타입 커밋과 결정 기록을 연결해 확정한다.

화면·API·DB 보완 계약

UI38의 하루 제목은 단일/여러 날 모두 day_plans.title에 1~100 graphemes로 저장한다. UI12는 같은 값을 읽고 새 변경 입력만 0~30자로 제한한다. 기존 31~100자 제목을 변경하지 않은 요청은 그대로 허용한다. 날짜 이동만 요청하면 title을 생략한다(Q18 추가 설계·PM 확인 대기). 프로토타입은 이때도 표시 중인 기본 제목 문자열을 저장한다. 서버에서 NFC·앞뒤 공백 제거 후 grapheme를 검사하며 기존 긴 제목의 자동 절단을 금지한다(Q15).

추가 설계 Q17(PM/백엔드 확인 대기): groupDays GET /groups/{groupId}/days는 현재 참여 모임의 활성 일정·활성 날짜를 date,scheduleId 오름차순으로 60개씩 반환한다. 취소/삭제 날짜는 탭에서 제외한다. 응답 items에는 scheduleId·scheduleVersion·scheduleTitle·day·expiresAt이 들어가며 nextCursor=null이면 끝이다. 커서는 다른 모임에서 재사용할 수 없다. 앱은 키 중복을 제거하고 다음 페이지 실패 시 기존 탭/선택을 유지한다. 선택 날짜는 별도 scheduleDetail로 열어 중간 페이지를 기다리지 않으며, 전체 기간/총 개수는 페이지 완독 전 확정 표시하지 않는다.

월 달력은 calendar API를 계속 사용한다. groupDays는 모든 모임을 합친 통합 달력(C02)이 아니라 한 모임 안의 날짜별 장소 탭(D10)을 위한 누락 계약이다. 취소 날짜에서 들어오면 원래 scheduleId/date 상세를 보기 전용으로 열고 다른 활성 날짜로 대체하지 않는다.

하루 이동은 모임→일정→날짜 계획→방문/기록/작업 순으로 잠그고 버전을 재확인한다. day_plans.plan_date·visits.visit_date·media/upload_tasks.record_date를 한 트랜잭션에서 옮긴다. 방문 날짜 복합 FK는 해당 트랜잭션에서 지연 검사하고 커밋 전에 일치시킨다. 일정/계획/변경된 방문·기록·작업 버전을 올려 이전 날짜·버전 요청을 거부한다. 보관 고정 시각·기한·최초 접수 시각은 바꾸지 않는다. 초기 DDL은 이 서비스 트랜잭션의 구현을 대신하지 않는다.

기록 UploadTask에는 요청의 clientFileId를 필수로 돌려준다. 부분 업로드 접수는 clientFileId로 대조해 tasks에 들어온 후보만 제거한다. fileErrors 후보는 이유와 함께 남기고 재시도 시 한도를 다시 확인한다. 응답 유실은 동일 멱등 키의 결과를 먼저 확인한다. 서버 접수 전 후보 X 제거와 접수 후 서버 파일 삭제(C10)는 서로 다른 동작이다.

추가 설계 Q16(PM 확인 대기): 임시 정렬 기준은 submissions.first_completed_at이다. 첫 완료와 동시에 한 번 확정하고 후속 파일 완료/실패/삭제로 바꾸지 않는다. 최신/오래된순은 묶음 정렬 방향만 바꾸며 동률은 submissionId로 고정하고 각 묶음 내부는 selectionIndex 오름차순이다.

추가 설계 확인 대기 — 2026-11-04 검토 반영

Q16: 첫 파일 완료 시각은 기존 DB 구조를 따른 설계 선택이다. 실제 업로드가 없는 mock 화면만으로 고객이 첫 완료와 전체 완료 중 어느 쪽을 원하는지 확정할 수 없다. PM은 지연 완료 파일이 추가될 때 묶음 위치를 바꿀지 확인한다. 결정 전에는 첫 완료 시각 고정을 임시 적용한다.

Q17: groupDays의 한 페이지 기본·최대 60개는 프로토타입에서 나온 수치가 아니다. PM과 백엔드 담당자는 대표 모임 날짜 수, 응답 크기, 부분 로딩 경험을 검토한다. 결정 전에는 60개와 커서 조회를 임시 적용한다.

Q18: 프로토타입은 날짜만 바꿔도 기본 제목 문자열을 저장한다. 현재 설계의 title 생략은 날짜 이동/일차 재번호 후 기본 제목을 자동 갱신하려는 추가 설계다. PM은 문자열 고정과 자동 갱신 중 원하는 동작을 확인한다. 결정 전에는 title 생략을 임시 적용한다.

Q16~Q18은 확인 대기이며 승인 기록이 없다. 확정 시 기능명세·API·UI·검수 기대값을 함께 갱신한다. v3.1은 이 임시 설계와 프로토타입 관찰을 명확히 구분한 개정이다.
