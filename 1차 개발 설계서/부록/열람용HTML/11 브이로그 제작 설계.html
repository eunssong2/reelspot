1 적용 범위와 변경 근거

2026-11-06 사용자 후속 지시가 아래 프로토타입 기준보다 우선한다. Google 로그인은 제외하고 C01~C13 추가 요청을 적용한다. 콘텐츠 자동 판정은 사용자 요청으로 일시 중지(disabled)한다. Q20은 서버 FFmpeg 생성, 원본 영상 음성 유지, 추가 배경음악 없음, 임시 보관 후 기기 저장으로 사용자가 선택했다. 구현 기준은 정원 15명(기존 모임 포함), 전체 모임 달력, 모임 내부 목록, 초대 168시간/성공 미리보기 50회 소진 후 자동 발급이다. 이전 유효 코드는 유지하며 50번째 확인 이후의 새 참여 제한은 기존 규칙을 유지한다. 렌더 결과는 24시간 보관하고 사용자당 동시 대기·진행 작업은 2개로 제한한다. 아래 미연결·반영 대기는 당시 프로토타입의 이력이다. 최신 앱·서버 및 Android 15 근거는 frontend/docs/2026-11-06_잔여구현_검증.html과 frontend/artifacts/remaining-20261106/을 따른다. 실제 서버 배포·실기기·실제 외부 인증 재검증 완료를 뜻하지 않는다.

기능명세 v3.3·설계 v0.5.1, 2026-11-05. 기준 feature/ui-prototype@ff5a5d0. 직전 9f64b5e 대비 EditStep.tsx 1개 파일 변경. 전체 화면 정리 PPT는 그대로이며 새 흐름은 라우트·화면 코드를 우선한다. 이전 캡처의 커밋은 바꾸지 않는다. 9f64b5e 근거는 UI/브이로그/출처.json·소스/에 보존한다. ff5a5d0 변경 소스·해시·실행 관찰은 UI/브이로그/편집설정/에 별도 보관하고 UI45 대표 화면만 새 근거로 교체한다.

F30은 현행 UI 요구사항으로 추가했다. 출시 단계·렌더 위치·보관·음성은 Q20 결정 대기다. F01~F29의 기존 정책은 유지한다. C06 자막 UI·C13 브이로그 연결은 부분 반영, 실제 렌더·갤러리 저장은 미연결이다.

코드 주석의 AT THAT PLACE 브이로그 화면기획 v4는 참조 이름이다. 저장소에는 해당 기획서 원본이 없으며 작성자도 확인되지 않았다. 한도 수치의 근거는 model.ts의 제안 상수다. Q19 확정에 필요한 원본 확보는 프로토타입 커밋 9f64b5e의 작성자 혜원에게 문의한다. 커밋 작성자와 기획서 작성자를 동일인으로 단정하지 않는다.

2 화면 흐름과 입력 규칙

UI05 → UI39 날짜 → UI40 장소·비율 → UI41 미디어 → UI42 템플릿(2~5개) → 필요 시 UI43 공통길이·UI44 구간 → UI45 편집 → UI46 전체 구성 → UI47 미리보기 → UI48 생성 → UI49 완성·저장. 닫기/뒤로 가기는 초안을 보존한다.

기록 있는 날짜만 선택, 취소 일정도 열람 가능한 기록이 있으면 가능. 날짜 최초 선택은 날짜 오름차순, 장소는 방문순, 미디어 선택은 사용자가 고른 순서다. 미디어 목록만 오래된순/최신순 전환한다. 장소 미지정 기록은 현재 흐름 대상이 아니다.

장소당 10개, 전체 50개, 총 길이 180초는 Q19의 제안값이다. 날짜별 제목 화면 2초도 총 길이에 포함한다. 사진은 이어 재생에서 기본 3초, 분할에서 기본 5초이며 사진만 고르면 1~10초로 조절한다. 영상의 기본 사용 길이는 원본과 5초 중 짧은 값이다. 직접 조절하면 원본 길이까지 가능하다. 분할은 가장 짧은 영상에 길이를 맞추고 각 영상의 시작 위치를 따로 정한다.

자막은 40자, 브이로그 제목과 편집용 날짜 제목은 30자까지 입력한다. 날짜·장소 표시, 글씨체 3종, 색감 4종, 전환 4종을 제공한다. 화면 맞춤은 미디어별 설정이다. UI45에서는 이어 재생의 현재 미디어 또는 분할에서 고른 칸에 채우기/전체 맞춤과 여백을 적용한다. 자르기는 UI41의 미디어 선택 → 크게 보기 → 자르기에서만 연다. 저장된 자르기 좌표는 이어 재생과 분할 배치에 모두 사용하지만 UI45에서 자르기 영역을 변경할 수는 없다. 자르기는 0~1 비율 좌표로 저장하며 최소 폭과 높이는 0.05다. 전환은 장소 장면별로 선택한다. 프로젝트 기본 전환을 변경하는 화면은 없다. 원본 파일 대신 편집 지시만 변경한다.

UI45 고정 영역은 상단 순서 편집·장면 미리보기·이전/다음 또는 분할 칸 선택, 하단 이 장소 완료다. StepFrame scroll=false로 바깥 스크롤을 끄고 ScrollView flex=1 안에 길이·색감·화면 맞춤·날짜/장소명·자막·글씨체·전환을 둔다. 세로 미리보기 기준 폭 상한은 170에서 130으로 축소됐다. 가로는 기준 폭의 1.9배와 가용 폭 중 작은 값으로 계산한다. 가로 전체 구분선과 최소 높이52 헤더를 사용한다.

색감·맞춤·표시·자막·전환은 단일 열림 아코디언이다. openSec의 최초값은 null이며 같은 항목 재탭은 null, 다른 항목 탭은 그 ID로 전환한다. 접힌 요약은 색감 이름, 채우기/맞춤, 날짜 켬/끔·장소명 켬/끔, 자막 또는 없음, 전환 이름이다. 한 줄 말줄임으로 표시하되 값을 자르지 않는다. 펼친 헤더는 요약을 숨긴다. button과 accessibilityState.expanded를 제공한다. 글씨체는 별도 시트다. 장면 이전/다음·분할 칸 선택은 열린 아코디언을 유지하고 대상 값만 바꾼다. 길이 행은 이어 재생의 현재 유효 동영상 또는 사진만 선택한 구성에서 표시한다. 사진·동영상 혼합 구성에서 현재 사진에는 길이 행이 없다. 분할에 영상이 있으면 설정 길이 행 대신 고정 영역의 길이 변경 링크로 UI43을 연다.

이어 재생의 색감/자막/맞춤은 현재 파일, 분할의 색감/자막은 장면 전체, 맞춤은 선택 칸을 따른다. 대상 전환 시 요약도 재계산한다. 값 변경과 전환 예시는 고정 미리보기에서 확인한다. 전환 없음은 예시 애니메이션이 없고 다시 보기 버튼이 비활성이다. 첫 장소의 실제 전환 없음 안내와 정지 커버/최종 렌더 경계는 유지한다. 키보드가 열려도 입력 중인 자막과 커서가 보여 수정할 수 있어야 한다(VB05). 미리보기 고정 때문에 입력을 막아서는 안 된다. 키보드 중 미리보기 축소/입력 위치 변경 등 해결 방식은 11월 10일 회의에서 정한다.

편집 완료 날짜를 제외했다가 다시 선택하면 기존 설정을 복원한다. 장소를 하나도 고르지 않은 날짜는 확인 후 제외하며, 삭제된 기록은 경고와 재선택으로 복구한다. 일반 장면 편집은 완료 표시를 해제하지만 미디어 화면 자르기는 해제하지 않는다. 글씨체를 전체 적용해도 다른 장소의 완료 표시는 유지된다(VB03·VB04).

전체 구성 화면은 미완료 장소가 있으면 미리보기로 진행하지 않는다. 하지만 기존 미리보기 → 자막·장면 수정 → 장소 편집 → 자막 아코디언 펼치기 → 자막 변경 → 뒤로 → 뒤로 경로에서는 영상 생성 버튼이 활성 상태로 남아 생성 화면에 진입한다(VB01). 현재 미리보기는 한도만 검사한다. 제품에서는 모든 생성 경로에서 완료 상태와 유효 미디어를 재검증해야 한다.

3 데이터 설계 — 로컬 편집본과 기존 DB 경계

현재 저장: AsyncStorage key=reelspot.vlog.drafts.v1, 값={groupId:VlogDraft}, 모임당 한 초안. 초안 읽기 완료 뒤 이어서/새로를 묻는다. 이어서는 첫 미완료 장소 미디어 또는 전체 구성으로 이동하며 마지막 화면 인덱스를 복원하는 방식이 아니다. 저장 실패는 현재 코드에서 무시되므로 실제 앱에서는 오류 안내·재시도와 내구성 확인을 추가한다.

VlogDraft: groupId,title,dayKeys[],placeKeys{dayKey:visitKey[]},mediaIds{visitKey:mediaId[]},settings{visitKey:PlaceSetting},aspect,dayTitleCard,dayTitles,transition,render?,updatedAt. dayKey=itineraryId/dayId, placeKey는 방문 식별자다. 실제 앱에서는 schedule/day/visit/media ID 매핑을 명시하며 장소 provider ID로 합치지 않는다.

openSec는 EditStep 컴포넌트의 일시 상태(null/filter/fit/show/caption/transition)다. VlogDraft·PlaceSetting·타임라인·signature·API·DB에 추가하지 않는다. 열기/접기만으로 done을 해제하지 않으며 새 마운트 시 모두 접힌다. 실제 값 변경은 기존 patch와 초안 저장을 따른다.

PlaceSetting: mode(sequence/split),templateId,showDate,showPlace,fontId,captions,videoStart,videoLen,photoSec,lengthSec,transition,filters,frames,done. FrameAdjust={fit,bg,crop?}, crop={x,y,w,h}. Timeline은 날짜→장소→선택 미디어를 펼친 scenes[]와 totalSec,itemCount,aspect,transition이다.

RenderMark: signature,uri,durationSec,createdAt,savedToGallery. signature는 제목·출력비율·장면순서·구간·자막·필터·프레임 등을 비교하는 직렬화 값이며 보안 서명이나 파일 무결성 해시가 아니다. done 등 진행 상태는 제외한다. 생성 시 입력 snapshot과 signature를 고정한다.

추가 구현 설계 Q21: 저장 키/레코드를 userId+groupId+schemaVersion으로 격리한다. 로그아웃·계정 교체·퇴장 시 다른 계정/모임의 편집본과 임시 파일이 노출되지 않도록 한다. persisted URI의 유효성·파일 존재·현재 접근을 복원과 저장 전에 검사한다.

기존 PostgreSQL groups/memberships/schedules/day_plans/visits/media는 읽기 원천이다. 브이로그 편집으로 이를 갱신하지 않는다. 신규 서버 프로젝트/렌더 테이블은 Q20 미결이므로 이번 초기 DDL에 만들지 않는다. 서버 렌더 선택 시 사용자 소유 project/revision/job/output 및 보관·용량·취소·멱등 계약을 별도 확정한다.

4 API·렌더 연결 계약과 실패 처리

기존 groupDays → scheduleDetail → mediaList/mediaStream을 사용해 참여·방문·접근 가능한 파일을 조회하는 연결 설계다. 이는 프로토타입의 mock 조회를 실제 구현으로 바꾸기 위한 설계이며 이미 연동되었다는 뜻이 아니다. mediaList의 오래된순 정렬을 사용하고 서버 시각·방문 경계 F16/Q12/Q14를 적용한다.

로컬 인터페이스 renderVlog({title,timeline,onProgress,isCancelled}) → {status:done,uri,durationSec}|{status:failed,reason?}|{status:cancelled}|{status:not_connected}. 현재 setRenderHandler 호출 없음. 실제 진행 콜백만 표시하고, 미연결은 그대로 안내한다. 임의 시간 경과로 성공을 만들지 않는다.

saveToGallery(uri) → saved|denied|failed|not_connected. 현재 setGallerySaveHandler 호출 없음. saved 확인 후만 저장 완료. 권한 거절은 설정/재시도, 공간 부족 등 실패는 완성본 보존. 기존 exportCreate(purpose=save)는 원본 다운로드 계약이며 합성 영상 생성 API가 아니다.

출력 목표: portrait=1080×1920, landscape=1920×1080, MP4. 렌더러는 timeline.aspect와 aspectOf를 읽는다. vlogBridge의 9:16 전용 주석은 가로 선택보다 좁은 옛 설명이므로 양쪽 비율을 구현한다. 프레임률·코덱·비트레이트·음성 믹스·음악·폰트 파일은 Q20 확정 전 고정 계약으로 만들지 않는다.

추가 구현 설계 Q21: 생성/저장 직전 참여·모임상태·기한·삭제·차단·검사 상태와 실제 원본 길이/선택/한도를 재검증한다. 위치 제거된 허용 파일만 이용한다. 원본 접근 불가 시 해당 장소를 재편집하게 하며 오래된 done=true로 통과시키지 않는다.

추가 구현 설계 Q21: 요청마다 독립 취소 토큰/세대를 사용한다. 뒤로가기·닫기·시스템 뒤로가기·재시도 후 이전 요청 콜백으로 최신 결과를 덮어쓰지 않는다. 생성 성공과 실제 저장 성공은 별개 상태이며, 로컬 URI 복원 실패시 재생성으로 안내한다.

5 업무 상태·검수 범위와 남은 결정

제품이 따라야 할 상태 흐름은 초안 loading → 선택/편집 → 모든 장소 완료 → preview → generating → rendered → saving → saved다. 현재 프로토타입에는 미완료 상태로 generating에 진입하는 VB01 우회가 있다. generating에서 failed/not_connected/cancelled는 초안 보존; saving에서 denied/failed/not_connected는 완성본 보존. 편집 내용 변경은 기존 render를 stale로 판정해 재생성을 요구한다.

프로토타입 전체 미리보기는 영상 커버로 시간·자막·배치를 확인한다. 실제 동영상 움직임과 음성, 최종 MP4와 같은 결과라는 주장은 하지 않는다. 글꼴3종은 기기 계열 대체 표시이며 최종 폰트·한글/이모지·전환·가로/세로·자르기 렌더 검수는 남아 있다.

9f64b5e의 웹 실행에서 재현된 결함은 VB01 미완료 생성 진입 우회와 VB02 분할 구간 초과다. VB02는 공통 길이를 2초로 줄여 시작을 13초로 정한 다음 공통 길이를 8초로 늘리면 원본 15초 영상에 사용 13~21초가 표시된다. TemplateSteps의 setLen이 시작 위치를 보정하지 않는 것이 원인이다. 이어 재생의 setVideoLen은 시작 위치도 보정한다. 별도 UI/브이로그/피드백검토/재현결과.json에 경로·실제 문구·캡처를 보관한다.
