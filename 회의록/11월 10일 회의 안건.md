# 2026년 11월 10일 회의 안건 — 브이로그 UI 수정과 제작 연동

상태: **회의 전 검토안**. 작성 기준일은 2026-11-04이며, 아래 요청과 담당 제안은 회의 결정이나 수정 완료를 뜻하지 않는다.

기준은 `feature/ui-prototype@9f64b5e88d7d3e663726975f2408b181f13a0413`, 기능명세 v3.2, 설계 v0.5.0이다. 이후 변경이 있으면 회의에서 최신 커밋과 재검수 결과를 함께 확인한다.

문서 변경과 프로토타입 코드 수정은 별도 작업이다. 아래 결함은 문서에 기록됐지만 프로토타입에서 해결된 상태는 아니다.

## 1. Q20 정책 결정과 Q21 구현 인계

**Q20은 정책·범위 결정 대기**다. 영상 생성과 갤러리 저장 handler는 미등록이며 현재는 미연결 안내를 표시한다. UI49는 코드 기반 설계 도식으로, 실제 완성본 화면을 실행 관찰한 자료가 아니다.

먼저 브이로그의 1차 출시 포함 여부를 결정하고, 그 결과에 따라 VB 수정과 Q21 구현·검증의 우선순위를 정한다. 회의에서는 실제 제작의 출시 단계, 로컬/서버 렌더 방식, 음성·음악 처리, 결과물 보관·용량·삭제 정책, 담당자와 실기기 성능 기준을 정한다. 미리보기는 동영상 커버 기반이므로 최종 영상의 움직임·소리와 동일하다고 볼 수 없다.

**Q21은 정책 승인 대상이 아닌 구현 인계·검증 대기**다. 다음 요구의 담당과 검수 방법을 정한다.

- 기존 참여·권한·삭제·만료·차단 규칙을 생성과 저장 직전에 재검증한다.
- 삭제된 미디어와 오래된 완료 표시, 원본을 넘는 구간을 다시 검사한다.
- 초안과 임시 파일을 계정별로 격리하고 저장 실패·URI 무효·계정 교체를 처리한다.
- 생성 취소·뒤로가기·재시도 후 이전 요청의 콜백이 새 결과를 덮어쓰지 않게 한다.
- 실제 렌더·저장이 확인되기 전 성공으로 표시하지 않는다.

## 2. 웹에서 재현된 결함 — UI 담당 수정 요청

공통 준비: 일반 모드 `/prototype`에서 **주말 산책 모임 → 브이로그 만들기 → 10월 17일 → 오후의 커피 → 15초·8초 영상 선택**으로 진입한다. 실계정이 아닌 예시 데이터 기준이다.

### VB01 — 미완료 장소가 있어도 이전 미리보기에서 생성 진입

- 관련 화면: UI45·UI46·UI47·UI48. 검수: **TC-F30-13**.
- 재현: 이어 재생 선택 → 이 장소 완료 → 전체 미리보기 → `자막·장면 수정` → 완료 장소 편집 → 자막 변경 → 뒤로 → 뒤로 → `영상 생성`.
- 실제 결과: 자막 변경으로 `done=false`가 됐는데도 기존 미리보기의 생성 버튼이 활성 상태여서 UI48로 들어간다. 전체 구성에서 `전체 미리보기`를 누르면 “아직 편집하지 않은 장소 1곳”이라며 막는 것과 다르다.
- 원인: 미리보기의 생성 버튼은 한도만 검사하며 장소 완료 상태를 재검사하지 않는다.
- 수정 요청: 미리보기 진입과 생성 시작 모두에서 장소 완료·유효 미디어·한도를 확인한다. 이전 화면으로 돌아가는 경로에서도 같은 조건을 적용한다.
- 완료 증거: 같은 경로에서 미완료 안내 후 편집으로 복구되고, 장소 완료 후에만 생성 진입이 가능함을 영상 또는 캡처로 기록한다.

근거: [미리보기 우회 화면](../1차%20개발%20설계서/UI/브이로그/피드백검토/VB01-preview-bypass.png), [생성 진입 화면](../1차%20개발%20설계서/UI/브이로그/피드백검토/VB01-generate.png), [OutputSteps 소스 사본](../1차%20개발%20설계서/UI/브이로그/소스/src/prototype/vlog/OutputSteps.tsx).

### VB02 — 분할 공통 길이를 늘리면 사용 구간이 원본을 초과

- 관련 화면: UI43·UI44. 검수: **TC-F30-14**.
- 재현: 15초·8초 영상을 2분할로 선택 → 공통 길이를 2초로 축소 → 첫 영상 구간 시작을 13초로 이동해 적용 → 공통 길이를 8초로 증가.
- 실제 결과: 원본 15초 영상에 **`사용 0:13~0:21`**이 표시된다.
- 원인: 분할 길이 화면의 `setLen`은 기존 `videoStart`를 보정하지 않는다. 이어 재생의 `setVideoLen`은 시작 위치를 보정하므로 두 경로를 구분해야 한다.
- 수정 요청: 공통 길이 변경 때 모든 영상의 `시작 + 사용 길이 ≤ 원본 길이`를 보장한다. 자동 보정 또는 적용 거부 방식과 안내 문구를 정하고, 렌더 직전에도 같은 조건을 검사한다.
- 완료 증거: 위 예시에서 시작이 7초 이하로 보정되거나 길이 변경이 거부되는지 확인한다. 여러 영상·마지막 유효 구간·기존 초안 복원도 함께 검수한다.

근거: [원본 초과 구간 화면](../1차%20개발%20설계서/UI/브이로그/피드백검토/VB02-out-of-range.png), [TemplateSteps 소스 사본](../1차%20개발%20설계서/UI/브이로그/소스/src/prototype/vlog/TemplateSteps.tsx).

## 4. 자르기·화면 맞춤의 현재 위치

| 동작 | 진입 위치 | 적용 대상 |
| --- | --- | --- |
| 자르기 영역 변경 | **UI41 미디어 선택 → 크게 보기 → 자르기** | 해당 미디어의 자르기 좌표. 이어 재생과 분할에서 모두 사용 |
| 채우기·전체 맞춤·여백 | **UI45 장면 편집** | 이어 재생의 현재 미디어 또는 분할 미리보기에서 선택한 칸 |
| 장면 전환 | UI45 | 해당 장소 장면에 들어올 때. 프로젝트 기본 전환을 바꾸는 화면은 없음 |

UI45에는 자르기 진입 버튼이 없다. **TC-F30-15는 UI45의 칸별 채우기·맞춤·여백만 검수**하며, 자르기와 완료 표시 예외는 UI41·TC-F30-16에서 확인한다. UI45에 자르기 버튼을 추가하려면 기존 동작 설명과 구분해 새 요구사항으로 기록한다.
