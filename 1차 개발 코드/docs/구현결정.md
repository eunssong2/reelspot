# 설계 기준과 구현 결정

기준: 설계 v0.3 / 기능명세 v2(2026-10-22). 구현일: 2026-10-24. 설계서와 원본 기능명세서는 수정하지 않았습니다.

| 항목 | 구현 기준·이유 |
| --- | --- |
| 실패 후 업로드 재시도 | F14의 실패 시 자리 반환을 적용. 실패 상태에서 재시도하면 P11 자리와 바이트 예약을 다시 확보. 다른 파일이 자리를 썼으면 `MEDIA_LIMIT`. 단순 transport 재발급은 이미 유지 중인 자리를 중복 확보하지 않음 |
| 운영 제한 파일 | 완료 파일의 `restricted`도 P11에 포함. 조회 가능 개수와 업로드 자리 계산을 분리하고 제한 해제로 한도를 초과하지 않게 함 |
| 초대 마지막 확인 | 현행 명세대로 확인 50회에 소진. 50번째 확인 응답은 성공하지만 이후 새 참여는 거부. 별도 참여 보장 토큰은 추가하지 않음 |
| 종료 후 기록 맥락 | F23의 최소 모임명·일정명·기록일·작성자·기한 유지. 장소명 영구 스냅샷 정책은 임의로 추가하지 않음 |
| 업로드 만료 | 접수 성공과 완료 확정을 분리. 완료 직전 현재 참여·모임·기한 재검증. 만료된 진행 작업도 정리 큐로 전환 |
| 관리 결과 알림 | 신고·운영·복구 결과는 계정 귀속 알림. 개인 차단 필터를 적용하지 않으며 공동 접근 권한을 복원하지 않음. 일정 푸시·메일은 추가하지 않음 |
| 계약 보완 | `UploadTask`에 후보 매칭용 `clientFileId/selectionIndex` 명시, 전체 후보 거부 시 `submissionId:null`, 일정 계획에 `outsideRange`, 로그인 수단 해제에 재인증 헤더. `scripts/contract-extensions.mjs`에서 재현 |
| 텍스트 검사 | 최초 생성·변경 모두 공개 전 검사. 즉시 통과는 원자 적용. 판정 불가는 검토 Operation과 운영 케이스로 보존하며 승인 후 원 요청을 최신 권한·버전으로 재검증 |
| 보관과 물리 정리 | 즉시 새 접근 차단, 별도 정리 작업. 용량 바이트 반환은 실제 원본 정리 후 한 번만 적용. 파일 개수 자리는 논리 삭제 시 반환 |
| 빈 방문과 실패 업로드 | 실패 작업은 진행 중 작업에서 제외. 빈 방문을 삭제한 뒤 해당 실패 작업을 재시도하면 `DELETED`로 거부하여 방문을 되살리지 않음 |
| 운영 증거 | 접수 시점의 최소 정보와 위치 제거 열람본을 암호화해 별도 보관. 별도 운영 토큰으로만 열람하며 결정 후 최대 90일에 정리 |
| 기존 코드 재사용 | 기존 DayLog 전체 복사 없이 신규 앱. 로그인·업무 DB·카메라·전송·저장 흐름을 새 계약에 맞춰 작성 |
| 소셜 로그인 | 공급자+subject 기준. 이메일 자동 병합 없음. 명시적 로그인 수단 연결에 최근 재인증 요구 |
| 운영 인증 | 개발 모드는 설정한 로컬 토큰, 실제 모드는 별도 OIDC + audience/issuer/MFA/역할. 앱 JWT 거부 |
| 기기별 촬영 음성 코덱 | Android 12 에뮬레이터의 CameraX 프로필이 AMR 음성을 선택하는 현상을 실측. 앱 촬영본만 Media3 Transformer 1.9.0으로 H.264/AAC 또는 무음 MP4를 준비한 뒤 후보를 생성. 이미 호환되는 촬영본은 그대로 사용. 촬영일·전체 구간·회전을 유지하며, 가져온 파일과 서버의 입력 형식 검증은 유지 |

실제 공급자 키·동의 문서·운영 인력·지원 연락처·스토어 서명·App Links 도메인은 사용자/운영 계정의 설정이 필요합니다. 개발용 대역 성공을 실연동 검수 결과로 기록하지 않습니다.
