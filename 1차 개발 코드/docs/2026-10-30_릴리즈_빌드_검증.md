# 0.2.0 Android 릴리즈 빌드

기준: 기능명세 v2.3, 설계 v0.3.3, 고객 UI `feature/ui-prototype@a67ee60368819ce5a325b5fe2ace17f9c85140c1`.

## 앱 반영

- 카카오 시작 화면과 로고, 가입 문서 카드·표시명 입력. Google 신규 로그인 버튼을 숨기고, 개인정보 안내는 체크 없이 열람한다. 실제 게시 문서가 없으면 가입을 허용하지 않는다.
- 모임 목록 카드, 모임/내 기록/마이페이지 탐색, 모임과 첫 일정 동시 생성, 기간 선택 시트.
- 월요일 시작 42일 달력, 오늘/월 이동, 월과 겹치는 일정 목록, 선택일의 전체 일정, 취소 표시, 방장 편집. 늦게 도착한 이전 달 응답을 버린다.
- 기간 선택 취소 시 원래 입력 유지, 당일 일정, 최대 366일, 미저장 이탈 확인. 일정 편집에서 실제 모임 소속과 방장 권한을 확인한다.
- 저장 결과가 불명확하면 입력과 요청을 유지한다. 일정 변경 재시도는 처음 전송한 버전·확인 여부까지 보관해 동일 요청으로 처리한다. 5xx·429는 결과 확정으로 처리하지 않는다.
- 모든 현재 참여자의 초대 발급/취소, 활성/이전 초대 목록, 링크와 코드 복사, OS 공유창. 공유 직전에 서버 상태를 다시 확인하며 공유창 종료를 상대방 수신으로 표시하지 않는다.
- 초대 코드 또는 서비스 HTTPS 링크 확인, 로그인·가입 후 확인 결과 복원, 명시적 참여 버튼. 임의 외부 주소는 초대로 처리하지 않는다.
- 서버 달력 정렬을 시작일·생성 시각·ID로 고정하고 모임 카드에 실제 확정 보관 기한의 7일/1일 안내를 제공한다. `Group.retentionWarnings`는 구현 계약의 선택 필드다.

## 재빌드

```bash
cd "/home/sphan/Documents/samsun/docs/1차 개발 코드/mobile"
npm run release:android
```

Android SDK와 JDK 21이 필요하다. 이 작업 환경에서는 설치된 SDK와 `.data/tools/jdk21`을 사용한다. 명령은 Expo 네이티브 파일 생성, JavaScript 재번들, ARM64/x86_64 빌드, APK 서명 검증과 최상단 복사를 수행한다.

- 앱 버전: `0.2.0`, Android versionCode `2`, 패키지 `kr.atthatplace.app`.
- Android 12(API 31) 이상, `arm64-v8a`와 `x86_64`. 32비트 ARM은 포함하지 않는다.
- JavaScript가 APK에 포함되어 Metro 없이 실행된다. 서버 통신은 `https://sphan0325.ddns.net`을 사용한다.
- 결과: 프로젝트 최상단 `at-that-place-release.apk`, 개발 폴더 `artifacts/at-that-place-release.apk`.

## 서명과 설치

개발용 debug 키와 다른 전용 릴리즈 키로 서명한다. `.data/release-signing/`의 키·비밀번호는 Git에서 제외되며, 권한을 디렉터리 700/파일 600으로 제한한다. 다음 버전 업데이트를 위해 이 디렉터리를 비공개로 백업하고 같은 키를 사용해야 한다. 기존 파일이 일부만 남아 있으면 자동으로 새 키를 만들지 않는다.

기존 debug 서명 preview APK에는 덮어쓰기 설치할 수 없다. 기존 앱을 제거하면 해당 기기의 로그인·임시 입력·전송 대기 파일 등이 삭제되므로 필요한 전송과 저장을 먼저 끝내야 한다. 릴리즈끼리는 같은 키로 서명하고 versionCode를 올려 업데이트한다.

새 인증서 지문을 로컬 `.env`의 `ANDROID_APP_SHA256`에 추가했고 기존 지문은 유지했다. 서버 재시작에도 반영했다. 외부 HTTPS의 `/.well-known/assetlinks.json`을 정상 제공해야 Android의 검증된 초대 링크가 동작한다.

## 검증 범위와 공개 사용의 제약

- 모바일/서버 타입 검사와 모바일 린트, 모바일 정책 테스트 8개.
- 실제 PostgreSQL과 미디어 도구를 이용한 통합 테스트 58개 통과(건너뜀 0개). 개발용 문서와 계정은 전용 테스트 DB에만 생성했다. 인증 공급자 응답은 테스트 대역을 사용하므로 실제 카카오 계정 로그인 완료를 증명하지 않는다.
- 초기 호스트 테스트에서는 테스트 문서 미초기화와 미디어 도구 부재가 발견되어, 개발 문서를 초기화하고 도구가 포함된 컨테이너에서 재검증했다. 보관 안내 테스트의 초기 데이터는 DB의 보관기한 불변 제약에 맞게 수정했다.
- 에뮬레이터 화면 검사와 최종 APK 검증 결과는 아래 기록을 따른다. 로그인 이후의 실제 서비스 전체 흐름을 완료한 것으로 간주하지 않는다.

이번 서버 변경은 DB 백업 후 적용했고 내부 API는 production/provider/review 모드로 정상 응답한다. 외부 `/health`, `/v1/app-config`, `/v1/consent-documents`는 Nginx 준비 상태의 **503**으로 확인됐다. 사용자 권한으로 다음 활성화가 필요하다.

```bash
sudo python3 "/home/sphan/Documents/samsun/docs/1차 개발 코드/deploy/install-nginx.py"
```

이는 공개 경로를 API에 연결하는 단계다. 이후에도 실제 가입 문서 게시와 운영 검토 인증 설정이 필요하다. 문서가 없는 상태를 동의한 것으로 처리하거나 검토 대기 콘텐츠를 임의 승인하지 않았다. 가입 연령·운영 정보 등 미확정 정책은 [10월 30일 회의 안건](../../회의록/10월%2030일%20회의%20안건.md)을 따른다. APK 파일 생성은 일반 사용자 출시 승인·모든 실연동 검증 완료를 뜻하지 않는다.

## 에뮬레이터 화면 확인

Android 15 x86_64의 별도 읽기 전용 에뮬레이터에서 릴리즈 서명 APK 설치와 Metro 없는 시작을 확인했다. 초기 OS System UI 응답 지연은 재시작 후 해소됐고, 검사 중 앱 AndroidRuntime/ReactNativeJS 오류 로그는 없었다.

- 서버 503 안내·재시도와 비활성 카카오 버튼, Google/개발 로그인 버튼 미노출.
- 모임 생성 화면과 42일 기간 선택 시트, 같은 날 두 번 선택해 당일 기간 적용.
- 기간을 다시 선택하다 취소하면 원래 날짜 유지.
- 미저장 이탈 확인의 ‘계속 작성’을 누르면 실제 입력값 유지.
- 인증이 필요한 서버 쓰기는 수행하지 않았다. 이 검사는 실제 카카오 가입·모임 생성 완료와 구분한다.

## 최종 APK 확인

최상단 복사본과 `artifacts` 파일의 SHA-256이 같고, 최종 생성한 JavaScript 번들과 APK 안의 번들도 바이트 단위로 일치한다. 파일 크기는 120,296,316바이트(약 115 MiB)다.

```text
720369234306e3a30c0b998f28fb52be9ae6b9929f45dd8e276258a501e77fd5
```

전용 RSA 3072 키 서명 검증, versionCode 2, Android API 31 이상, ARM64/x86_64, 디버깅 비활성, 평문 통신 비활성을 확인했다. QA 인증서·네트워크 예외·QA 주소·설정된 서버 비밀키는 최종 앱에 포함되지 않았다. 최종 파일을 에뮬레이터에 다시 설치해 카카오 전용 시작 화면을 확인했고 앱 오류 로그는 없었다. 초대 토큰 보존 수정은 회귀 테스트와 최종 번들에 포함됐다.
