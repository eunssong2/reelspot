# 공개 서버 실행 복구 · 2026-10-30

## 실제 원인과 확인 근거

- 시스템 Nginx의 앱 location은 `install-nginx.py --prepare`가 만든 `return 503` 고정 응답이었다. 카카오 요청이 API에 도달하지 않았다.
- `1-api-1` 컨테이너가 없고 `127.0.0.1:8081`에 리스너가 없었다.
- 기존 DB·워커는 2026-10-26 15:49:52 UTC에 종료된 상태였다. 두 컨테이너의 종료 코드는 255, OOM=false, restart=no였다. 기록만으로 최초 종료 원인 자체를 확정하지는 않았다.
- 실제 서버 빌드 시 Compose/BuildKit이 `x-docker-expose-session-sharedkey contains value with non-printable ASCII characters`로 실패했다. 한글 경로에서 로컬 build context를 전달하는 과정의 오류였으며, ASCII 작업 디렉터리에서 tar 스트림으로 빌드해 해결했다.

## 이번에 적용한 변경

- `.data/backups/`에 기존 DB를 비공개 파일로 백업하고 기존 볼륨을 유지했다. 누락된 008~011 마이그레이션을 적용했다.
- `npm run server:start`: 소스 허용 목록만 포함한 이미지 빌드 → DB 실행 확인 → DB 백업 → 마이그레이션 → API·워커 실행 → 상태 검사를 자동화했다. `.env`와 로컬 저장 파일은 이미지에 포함하지 않는다.
- API와 워커의 Compose 실행 모드를 `production/provider/oidc/review`로 지정했다. 개발용 로그인과 자동 콘텐츠 통과를 공개하지 않는다.
- API·DB·워커 모두 `restart: unless-stopped`를 사용한다. 명시적으로 중지한 서비스까지 강제로 다시 켠다는 뜻은 아니다.
- Nginx 설치에서 ‘공개용 문서 미게시’를 API 전체 연결 실패와 분리했다. 개발 문서는 계속 차단하고, 필수 게시 문서 없는 신규 가입 완료도 기존 API 검증으로 차단한다.

## 사용자 터미널에서 마지막 연결 적용

```bash
sudo python3 "/home/sphan/Documents/samsun/1차 개발 코드/deploy/install-nginx.py"
```

`--prepare`를 붙이지 않는다. 기존 설정을 백업하고 Nginx 문법 검사 후 reload한다. Guacamole과 인증서 설정을 유지한다. 이 세션에서 `sudo -n true`는 비밀번호 필요로 실패했으므로 시스템 적용은 수행하지 못했다.

## 연결 후에도 남는 기능 제한

- DB에는 개발 문서 2개만 있고 게시 문서는 0개다. 운영 모드의 동의 목록은 빈 배열이며, 가입 완료가 불가능하다. 게시본의 운영자·연령 등 미정 정보를 임의로 채우지 않았다.
- 운영자 OIDC와 실제 검사 서비스가 미설정이다. 검토 모드에서는 텍스트·파일이 운영 검토를 기다리고 자동으로 공개되지 않는다. 이 상태를 업로드 정상 완료로 표현하지 않는다.
- Google 로그인은 사용자 요청에 따라 보류했다.
- 신규 일반 사용자 출시 준비 완료를 의미하지 않는다. Nginx 전환 후 실제 카카오 계정으로 로그인·콜백·앱 복귀를 확인하고, 게시 문서와 운영 검토 경로를 완성해야 한다.
