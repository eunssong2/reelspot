# Android 에뮬레이터 추가 실행 검증

검증일: 2026-10-24. Android 12(API 31) x86_64 에뮬레이터에 개발 APK를 설치하고 ADB 터치·입력으로 직접 조작했습니다. 로컬 API·PostgreSQL·미디어 워커를 사용했으며 로그인·콘텐츠 판정은 개발 모드입니다.

## 발견하고 수정한 문제

| 문제 | 수정 | 재확인 |
| --- | --- | --- |
| 잘못된 예정 시각에 `VALIDATION_ERROR` 코드가 그대로 표시됨 | 날짜·시간·파일 처리 오류를 한국어로 안내. 장소 등록의 시간 형식을 제출 전 확인하고 버튼 위에 오류 표시 | `10:03` 거부 안내 표시 → `10:05`로 변경 후 장소 등록 성공 |
| 본인 기록 수정 화면에서 `Text strings must be rendered within a <Text> component` 발생 | Text 밖에 렌더링하던 명시적 공백 제거 | 앱 재실행 후 오류 없이 진입·선택·설명 변경, 서버 버전 1→2 확인 |
| 앱에서 촬영한 소리 있는 영상이 서버에서 `FILE_INVALID`로 실패 | 기기 프로필이 AMR 음성을 선택하는 것을 원본 probe로 확인. 앱 촬영본에만 네이티브 호환 준비 단계 추가. 이미 H.264/AAC인 파일은 변환 없이 통과. 무음 선택도 제공 | 새 APK 설치 → 같은 기기에서 재촬영 → H.264/AAC 준비 → WorkManager 전송 → 서버 완료 |

서버의 AAC/무음 입력 조건을 완화하지 않았습니다. Media3 Transformer 버전은 기존 Expo Video와 같은 1.9.0입니다. 준비 단계는 구간 자르기나 사용자 편집 없이 코덱을 맞추며, 원래 촬영 시각을 MP4 메타데이터로 전달합니다. API 사용 근거는 [Android 공식 Transformer 설명](https://android-developers.googleblog.com/2025/03/media-processing-performance-jetpack-media3-transformer.html)입니다.

## 변경 후 검사

- Android 전체 기본 ABI 디버그 빌드 성공: `assembleDebug`, 2분 9초. 새 APK를 에뮬레이터에 재설치.
- 모바일 TypeScript, lint, Android 번들 내보내기 통과.
- 앱 재실행 이후 ReactNativeJS 오류·AndroidRuntime 크래시 로그 없음.
- 기존 서버 자동 검사 28개 통과 기록은 유지. 이번에는 서버 코드를 바꾸지 않아 서버 검사를 반복 실행하지 않음.

로그·UI XML·화면 캡처·ffprobe 결과는 `artifacts/emulator-followup/`에 있습니다. APK는 Metro와 로컬 API가 필요한 개발 빌드입니다.

## 확인하지 않은 범위

실제 소셜·지도·심사·운영 인증 연동, 실제 단말의 청취 품질과 음성 동기화, HDR·회전·코덱 전체 조합, 장시간 전송 복구, 성능 목표, 출시 서명은 별도 검수가 필요합니다. 에뮬레이터는 오디오 출력 없이 구동했으며 음성 트랙의 존재·형식과 재생 진행을 확인했습니다.
