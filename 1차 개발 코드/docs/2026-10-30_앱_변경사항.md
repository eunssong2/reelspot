## 카카오 개발자 콘솔 설정

지도 JavaScript 키와 로그인 REST API 키는 용도가 다르다. 현재 지도 키를 읽는 경로는 프로젝트 루트 `.env`이며, 앱 설정에는 공개 가능한 지도 키/웹 출처만 허용 목록으로 전달한다.

1. 같은 카카오 앱의 **앱 ID**, **REST API 키**를 루트 `.env`의 `KAKAO_APP_ID`, `KAKAO_REST_KEY`에 입력한다. Client Secret이 활성화되어 있다면 `KAKAO_CLIENT_SECRET`도 서버에만 입력한다. Admin 키는 사용하지 않는다.
2. 카카오 로그인 활성화 후 **Redirect URI**를 등록한다. 등록 주소는 `https://sphan0325.ddns.net/v1/auth/kakao/callback`이다. 앱 API의 HTTPS 연결은 [HTTPS 연결 안내](HTTPS_연결.md)를 따라 별도로 적용해야 한다. 실제 서버 주소가 다르면 `PUBLIC_URL`에서 계산한 주소를 사용하거나 `KAKAO_REDIRECT_URI`를 지정한다. 등록값과 코드의 값이 완전히 같아야 한다. 운영 서버는 HTTPS가 필요하다.
3. 앱 복귀 주소 `atthatplace://oauth/kakao`는 앱에 등록된 스킴이다. 위 서버 Redirect URI와 구분한다. 앱 복귀 주소를 카카오의 서버 콜백 대신 등록하지 않는다.
4. 지도 **웹 도메인**에는 `EXPO_PUBLIC_KAKAO_WEB_ORIGIN`과 동일한 출처를 등록한다. 현재 값은 `https://sphan0325.ddns.net`이다. 앱은 해당 출처를 WebView HTML의 base URL로 사용한다. 카카오맵 사용 설정과 Android WebView에서의 실제 로딩도 확인한다.
5. 필요하지 않은 이메일·프로필 사진 동의는 요청하지 않는다. 표시명은 기존 앱 가입 화면에서 입력한다. 실제 카카오 로그인·재로그인·로그아웃·계정 연결·탈퇴 연동 검수는 콘솔 설정 완료 후 진행한다.
6. 비용 우선순위는 월 0원이다. 카카오 콘솔의 유료 API/추가 쿼터 설정을 사용하지 않고 무료 한도를 확인한다. 앱의 오류 처리는 콘솔 과금 설정을 대신하지 않는다. 지도 JS 호출과 서버 장소 검색의 한도는 각각 확인해야 한다.

공식 근거: [카카오 로그인 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api), [사전 설정](https://developers.kakao.com/docs/ko/kakaologin/prerequisite), [카카오 장소 검색](https://developers.kakao.com/docs/ko/local/dev-guide), [지도 Web API](https://apis.map.kakao.com/web/documentation/).

## 실행과 업데이트

```bash
# 1차 개발 코드/ 에서. 기존 DB를 지우거나 seed로 초기화하지 않는다.
npm run db:migrate
npm run dev
# 워커는 기존 Docker 구성으로 실행
# docker compose --profile worker up -d --build worker

# 별도 터미널에서 설치 파일 생성
cd mobile
npm run preview:android -- --abi=x86_64,arm64-v8a
```

새 마이그레이션 `008_kakao_login.sql`은 로그인 인계용 임시 테이블을 추가한다. 기존 업무 테이블/사용자 데이터는 초기화하지 않는다. 워커도 새 코드를 적용해야 만료된 로그인 인계 데이터가 정리된다.

서버 키만 변경하면 API/워커를 재시작한다. 지도 JS 키·웹 출처·앱 API 주소를 변경하면 APK를 다시 빌드한다. 확인용 APK는 개발 서명 및 HTTPS 전용 빌드이고, Play Store 배포용 서명 APK가 아니다.

## 검증 결과

테스트 DB는 기존 서비스 DB와 분리해 PostgreSQL 16을 사용했다.

- API/모바일 타입 검사 및 모바일 lint: 통과. 서버·운영 웹 빌드 통과.
- 서버 통합·실제 사진/영상·새 카카오/초대 회귀 테스트: Docker 워커 환경에서 46개 통과, skip 0. 이후 이용 제한/종료 모임의 캐시 재시도 시나리오를 추가해 인증/초대 3개 재검증 통과.
- 모바일 정책/날짜/지도 문자열 안전성/HTTPS 강제 테스트: 4개 통과.
- Android ARM64+x86_64 APK: HTTPS 최종 빌드 성공. 패키지의 `usesCleartextTraffic=false`, HTTPS API 문자열 및 두 CPU ABI 확인.
- Android 15 에뮬레이터: 개발 로그인 → 홈 → 마이페이지/계정 → 일정 배너/날짜/장소 타임라인 확인. 캡처는 [실행화면 폴더](2026-10-30_실행화면)에 보관. 기능 검수는 분리한 테스트 API/DB로 수행했으며 공개 HTTPS API 실연동 검수는 아직 아니다. 빈 날짜 선택 → 수기 장소 저장 → 같은 날짜로 복귀/새 장소 표시, 카테고리 검색의 빈/생략 검색어 계약도 확인했다.
- 후속 확인: 로그인용 앱 ID·REST 키·Client Secret 입력 확인. 인가 요청 302(카카오 계정 화면), 지도 SDK 200, 실제 REST 장소 검색 200. 실 계정 로그인 완료·실기기 지도 렌더링은 HTTPS API 연결 후 검증 필요. 최신 구현은 [확정 기능 구현현황](2026-10-30_확정기능_구현현황.md) 참고.

파일별 해시는 [변경파일 목록](2026-10-30_변경파일.json), APK 해시와 검수 결과는 [검증 JSON](2026-10-30_검증결과.json)에 보관했다.

## 이번 변경의 경계

`회의록/10월 30일 회의 안건.md`의 미결 정책(불연속 일정, 일정별 커버, 프로필 사진, 별도 참여자 정렬·차단 의미 등)은 확정으로 취급하지 않았다. 연속 기간 366일, 5분 단위, 장소 15개, 사진 5/영상 2 누적 한도, 선택 120개는 유지했다.

약관/개인정보 처리와 명세 F02·F20·F24의 출시 정합성은 별도 미결 사항이다. 이 빌드의 개발 완료를 일반 사용자 출시 승인으로 간주하지 않는다. 기존 구현 기준선 `기준/`은 최초 구현 시점의 기록이며, 최신 적용 내용은 이 문서 및 상위 기능명세 v2.2와 함께 확인한다.

`1차 개발 코드/`는 현재 저장소의 `.gitignore` 대상이다. 이번 소스 변경과 APK는 로컬에 있으며, 문서 저장소 push만으로 앱 코드가 배포되지는 않는다. `.env`는 계속 제외한다.
