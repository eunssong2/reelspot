## 계약·DB 및 적용 순서

`contracts/design.openapi.json`은 docs 설계 사본, `contracts/openapi.json`과 `generated.ts`는 구현 확장까지 포함한 생성본이다. 앱 계약 사본과 동일하다. 기존 운영용 API 확장은 유지했다.

브이로그용 `GET /groups/{groupId}/vlog-sources`를 구현 계약에 추가했다. `groupDays`는 활성 날짜 전용인 반면 F30은 취소 일정의 열람 가능한 기록도 선택하므로, 현재 참여자가 조회할 수 있는 삭제되지 않은 일정 ID를 별도로 제공한다. 실제 기록 조회에는 기존 scheduleDetail/mediaList/mediaStream의 차단·만료·삭제·검사 상태 검증을 적용한다. 신규 렌더 테이블이나 공개 미디어 URL은 만들지 않았다.

서버 배포 전 `npm run db:migrate`로 **013_spec_v32.sql**을 적용한다. visits의 5분 제약만 1분으로 완화하고, 기존 파일·초대·적용된 마이그레이션은 유지한다. 신규 업로드 10개는 API에서 제한하여 기존 최대 120개 제출·작업 조회·다운로드를 보존한다. 이후 새 서버와 계약이 같은 앱을 배포한다. 기존 서버에 새 앱만 배포하면 groupDays/vlog-sources가 없어 동작하지 않는다.

개발 환경은 `npm run db:seed`로 동의 항목을 갱신할 수 있다. 운영에서는 승인된 필수 2종·선택 2종의 게시본을 별도로 준비해야 한다. 개발 예시 문서는 운영 환경에 노출하지 않는다.

## 검증 결과

- 서버: 타입 검사·서버/운영 웹 빌드 통과. 실제 PostgreSQL + ffmpeg/ImageMagick을 포함한 테스트 **74개 통과, 실패 0, 건너뜀 0**.
- 앱: 타입 검사·lint 통과, 로직 테스트 **28개 통과, 실패 0, 건너뜀 0**, Android JS export 통과.
- Android APK: x86_64 확인용 빌드 통과. 해시와 소스 범위는 [검증 메타데이터](2026-11-04_명세_v3.2_검증.json)에 기록했다. 새 버전 배포나 기기 설치를 하지 않았다.
- DB는 전용 로컬 컨테이너에서 001~013을 적용했다. 기존 실행 중인 API·worker·운영 DB와 분리했다. 미디어 검사는 기존 도구 이미지에 변경한 서버 소스를 마운트하여 실행했다.
- 전체 TC-F30의 Android 조작, 실제 카메라 앱·권한별 흐름, 글꼴/이모지, 모든 화면 시각 검수, ARM64 빌드·실기기 성능은 이번 검증에 포함하지 않았다. 이전 릴리즈의 화면 캡처를 새 구현 증거로 사용하지 않는다.
