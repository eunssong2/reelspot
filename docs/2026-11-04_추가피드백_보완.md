## 결함 수정

## 업로드 후보 보관 — 사용자 선택 반영

사용자가 **현행 F14대로 화면을 떠날 때 후보 비우기**를 선택했다. 영속 보관을 새 정책으로 채택하거나 명세 원천을 바꾸지 않았다.

- 새 후보는 기록 화면의 메모리에만 둔다. 시트를 닫고 다시 열 때는 유지한다.
- 다른 기록 장소·날짜로 이동하거나 라우트를 떠나면 비운다. 카메라 Activity 진입·앱 background/foreground 자체는 라우트 이탈로 취급하지 않는다.
- 이탈 시 새 후보의 기기 사본을 정리한다. 접수 큐·기존 다른 저장 후보에서 참조하는 파일과 기기 앨범 원본은 삭제하지 않는다.
- 촬영·접수가 진행 중이면 종료 후 정리한다. 화면 이탈 뒤 늦게 돌아온 촬영 결과가 재진입 시 후보로 나타나지 않는다.
- 프로세스 재시작 시 새 후보를 복원하는 영속 목록은 만들지 않는다. 강제 종료는 정리 콜백을 보장하지 않으므로 기기 사본의 물리 삭제까지 보장하지 않으며 계정 로컬 정리의 적용 대상이다.
- 앞선 버전에서 이미 저장한 후보만 기존 복구 경로로 읽는다. 읽은 후보는 화면 메모리로 전환한다. 삭제·이동된 장소 때문에 접근하지 못하는 이전 저장본은 `저장 공간과 캐시` 또는 `파일 전송 상태`의 **이전 저장 후보 정리**에서 서버 연결 없이 확인·정리할 수 있다. 읽을 수 없는 저장본은 명시적으로 목록만 제거하며, 알 수 없는 파일을 추정하여 지우지 않는다.

이전 보고의 “새 후보를 계정·일정·날짜·장소별로 영속 저장”은 이번 사용자 선택으로 대체됐다. 제출 시 장소·날짜 일치 검사와 원래 메타데이터 보존은 유지한다. `writeUploadDraft`의 디스크 쓰기는 이전 저장 후보를 원래 장소로 넘기는 복구 경로에만 남아 있다.

## 자동 검증과 한계

앱 로직 30건, 컴포넌트 흐름 19건, 타입 검사와 lint가 통과했다. 흐름 검사는 앞선 10건에 복원 1건, 일부 미디어 삭제 1건, 충돌 2건, 이전 후보 정리 3건, 화면 이탈·늦은 카메라 결과 2건을 추가했다. 이전 A→B 검사도 새 보관 정책에 맞춰 시트 닫기 유지·장소 이탈 비우기·B만 제출로 변경했다.

흐름 검사의 대체 범위는 **네이티브 UI, 카메라, 파일 시스템, AsyncStorage, API, 라우터, 공통 UI(Sheet·useAction 등), Records, DayTimeline, candidate, enqueueTask, 영상 플레이어 등**이다. 실제로 실행하는 컴포넌트와 상태·핸들러는 UploadSheet, Schedule, Invites, TimeEditModal, UploadDrafts, 브이로그 흐름·선택·편집·초안 저장이다. 순수 후보 생성·파일 검사·네이티브 전송 성공을 이 검사로 주장하지 않는다. 이번 결함의 누락 원인은 해당 시나리오를 검사하지 않은 데 있다.

서버 코드와 이전 서버 검증 대상 76개 파일의 해시를 비교했다. 변경이 없어 서버 74건의 이전 통과 결과를 그대로 참조하며 이번에 재실행했다고 기록하지 않는다. `by_time` 별칭 이외의 이전 APK 전체 호환은 보증하지 않는다. 날짜 제목 등 계약 차이가 있으므로 배포 버전은 앱·서버를 함께 관리해야 한다.

전체 화면 문구·배치의 명세 일치를 판정한 것은 아니다. Q19 한도 확정·Q20 실제 렌더/결과 저장 연결도 여전히 남아 있다. 빌드·네이티브 점검의 범위와 최종 해시는 아래 후속 기록에 분리한다.

## Android 에뮬레이터 점검

Android 15, 720×1560 에뮬레이터를 별도 읽기 전용 AVD 인스턴스로 실행했다. 검증용 사본은 index/layout을 시험 진입 화면으로 바꾸고 API·세션만 fixture로 대체했으며 서버 쓰기는 모두 차단했다. 실제 TimeEditModal·UploadSheet·Sheet·useAction·ImagePicker·candidate·Transfer.normalizeCapture·파일 시스템·AsyncStorage를 사용했다. 기존 실행 서버나 실제 계정에는 접근하지 않았다.

| 조작 | 관찰 |
| --- | --- |
| 분 휠 스크롤 후 확인 | 14:01에서 14:03으로 이동하고 실제 콜백 값 14:03 확인 |
| 시트에서 사진 촬영 | 권한 요청→기기 카메라→촬영 확인→같은 시트의 후보 1개 |
| 시트에서 짧은 영상 촬영 | 준비·검사를 거쳐 후보 2개(사진+영상), 파일 분석 H.264/AAC, 1280×720, 1.939300초 |
| 4:3 자르기 | 대표 사진과 같은 ImagePicker 설정으로 기기 자르기 실행, 512×384 결과. 대표 사진 서버 적용까지 검사한 것은 아님 |
| 시트 닫기·다시 열기 | 후보 2개 유지 |
| 다른 라우트 이동·돌아오기 | 전용 사본 폴더가 비고, 기록 화면 재진입 시 빈 시트 확인 |

캡처·UI XML·영상 분석과 fixture 소스는 frontend의 로컬 `artifacts/review2-native/`에 있다. 이 폴더는 git 제외 산출물이며 파일 해시를 검증 JSON에 기록했다. 네이티브 사본은 최종 소스에서 읽을 수 없는 이전 목록의 정리 가드와 빈 사본 목록의 조기 반환을 보완하기 전이다. 해당 두 줄의 차이는 `fixture/final-storage-guard.diff`에 보존했고, 최종 손상 목록 정리는 자동 흐름 검사에서 확인했다. 휠·촬영·자르기·정상 후보 이탈 경로의 실행 코드는 동일하다.

최종 제품 소스의 Android export와 x86_64 확인용 APK 재생성도 통과했다. **네이티브 검증 사본 APK와 최종 제품 APK는 별개**다. 최종 제품 APK의 전체 로그인·서버 업로드·모임 사진 서버 반영은 이 점검의 범위에 포함하지 않았다.

남은 기기 점검: 카메라 실행 중 앱 프로세스 종료와 복귀, 실제 휴대폰별 권한·코덱 차이, 브이로그 복귀 오류 배너 배치. 이 항목과 전체 화면 검수를 완료했다고 판정하지 않는다.
