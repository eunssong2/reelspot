# 카카오 지도 연결 가이드 (1단계: 지도 표시)

## 연결 방식

이 프로젝트는 **Expo(React Native) + Expo Go**로 실행합니다(`android/`, `ios/` 네이티브 폴더 없음).
그래서 **WebView 안에서 카카오맵 JavaScript SDK**를 띄우는 방식을 씁니다.

- 필요한 키: **JavaScript 키 1개**
- 필요한 콘솔 등록: **JavaScript SDK 도메인 `http://localhost`** + **카카오맵 사용 설정 ON**
- Android/iOS 플랫폼(패키지명·번들 ID·키 해시) 등록은 **필요 없습니다.** 지금 `app.json`에도 `android.package` / `ios.bundleIdentifier`가 정해져 있지 않습니다. (나중에 카카오 네이티브 SDK로 바꿀 때만 필요하며, 그때 앱 식별자를 먼저 정해야 합니다.)
- REST API 키 · Admin 키 · 네이티브 앱 키는 **쓰지 않습니다.**

## 1. 카카오 콘솔 설정 (앱: 릴스팟)

[Kakao Developers](https://developers.kakao.com) → **내 애플리케이션** → **릴스팟** 선택 후:

| 순서 | 메뉴 | 할 일 |
|---|---|---|
| 1 | **[앱] > [플랫폼 키] > JavaScript 키** | 키를 복사해 `.env`에 넣습니다. |
| 2 | 같은 화면의 **JavaScript SDK 도메인** | 아래 표의 도메인을 **환경별로 각각** 등록합니다. |
| 3 | **[카카오맵] > [사용 설정]** | 상태를 **ON** |

### 환경별로 등록할 도메인 (포트가 다르면 다른 도메인입니다)

| 환경 | 실제 요청 출처 | 등록할 값 |
|---|---|---|
| PC 웹 (`npm run web`, 8081 포트) | `http://localhost:8081` | `http://localhost:8081` |
| 모바일 앱 (Expo Go의 WebView) | `http://localhost` (코드의 `KAKAO_WEB_ORIGIN`) | `http://localhost` |

- 개발 서버가 8081이 아닌 포트(예: 8082)로 뜨면 그 포트도 따로 등록해야 합니다.
- 화면 왼쪽 위 상태 표시에 **실제 요청 출처**가 나오니, 등록할 값이 헷갈리면 그 값을 그대로 등록하세요. 실패 시에는 카카오가 돌려준 원문 오류(`domain mismatched! caller=…`, `disabled OPEN_MAP_AND_LOCAL service`)가 화면에 그대로 표시됩니다.
- REST API 키 · Admin 키 · 네이티브 앱 키와 Android/iOS 플랫폼(패키지명·번들 ID) 등록은 필요 없습니다.

## 2. 키를 넣는 곳

프로젝트 폴더의 **`.env`** (git에 올라가지 않음. 형식 예시는 `.env.example`)

```
EXPO_PUBLIC_KAKAO_JS_KEY=여기에_JavaScript_키
```

## 3. 실행 방법

```bash
npx expo start -c        # .env 나 metro.config.js 를 바꾼 뒤에는 -c 로 재시작
```

- **PC 웹:** 터미널에서 `w` 키를 누르거나 브라우저로 `http://localhost:8081` 접속. 지도는 HTML `div`에 카카오 JavaScript SDK로 직접 그립니다(`src/map/KakaoMapView.web.tsx`).
- **모바일 앱:** 휴대전화 Expo Go로 QR 스캔(PC와 같은 Wi-Fi). 지도는 WebView 안에서 같은 SDK로 그립니다(`src/map/KakaoMapView.tsx` + `kakaoMapHtml.ts`).

지도는 앱 흐름의 **여행 장소 검색** 화면(`src/screens/PlaceSearchScreen.tsx`)에서 볼 수 있습니다. 내 모임 → 여행모임 1 → Day의 `+ 추가`로 들어갑니다.

## 4. 화면에서 확인할 것

1. 화면 위쪽에 `지도를 불러오는 중…` 이 잠깐 보이고, 지도 타일이 그려지면 사라집니다.
2. **드래그**로 이동, **휠/핀치/+−** 로 확대·축소합니다.
3. 검색창에 장소명(예: 경복궁)을 입력해 검색하거나 칩(관광지·맛집·카페·숙소)을 누르면 결과가 **이름표가 붙은 핀**으로 표시됩니다.
4. 아래 **결과 시트**에 장소명·카테고리·거리·주소가 나옵니다. `관련도순 ▾` 로 거리순 정렬, 핸들로 접기/펼치기.
5. **핀을 누르면** 해당 항목이 강조·스크롤되고, **목록의 장소를 누르면** 그 장소의 사진·동영상 올리기 화면으로 이동합니다. `+ Day n에 추가` 는 일정에 담습니다.

## 5. 실패했을 때

15초 안에 지도가 안 뜨면 오류 카드와 **다시 시도** 버튼이 뜹니다. 임시 지도로 대체하지 않습니다.

- **웹**: 브라우저는 실패 응답 본문을 읽을 수 없어서(CORS), 개발 서버(`metro.config.js`의 `/__kakao-sdk-check`, 개발 전용)가 같은 출처로 카카오에 다시 물어 원문 오류를 보여 줍니다. 이 파일을 바꾼 뒤에는 개발 서버를 재시작해야 합니다.
- **모바일**: WebView가 보고한 출처(`window.location.origin`)로 앱이 카카오에 다시 물어 원문 오류를 보여 줍니다. 이 재조회는 WebView가 실제로 보낸 `Referer`가 아니라 **보고된 출처를 흉내 낸 요청**이므로, 기기에서의 최종 확인은 실제 지도가 뜨는지로 판단합니다.

## 6. 범위

- 지도 표시·이동·확대/축소, 장소명 검색, 카테고리 검색(관광지·맛집·카페·숙소), 이름표 핀, 결과 시트
- 로그인·서버 저장은 없습니다. 일정과 모임은 `src/mock/tripData.ts` 의 mock 데이터이고 새로고침하면 초기화됩니다.

## 7. 서울 테스트 설정 (`src/map/seoul.ts`)

- 초기 중심: 서울시청(37.5665, 126.9780), 초기 확대 레벨 7 (서울 도심을 둘러보기 좋은 정도. 숫자가 클수록 넓게 보임)
- 검색 결과 제한: 장소명 검색·관광지/맛집/카페 검색 모두 **주소가 "서울…"인 장소만** 표시합니다. 요청 단계에서 서울 영역으로 좁히고, 결과에서 한 번 더 주소로 거릅니다. 제외된 개수는 화면에 표시됩니다.
- 지도 이동·확대/축소는 제한하지 않습니다. 서울 밖으로 옮긴 뒤 카테고리 버튼을 누르면(현재 지도 중심 주변 검색) 결과가 없다고 나옵니다.
- 다른 지역으로 바꿀 때는 `seoul.ts`의 상수만 바꾸면 웹·모바일 WebView 모두 반영됩니다.
