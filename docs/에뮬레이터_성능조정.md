# 에뮬레이터 반응·자원 조정

2026-10-24, 현재 PC의 Android 15 x86_64 에뮬레이터와 원격 데스크톱에서 확인했습니다.

## 적용한 변경

- 사용하지 않던 Android 12 에뮬레이터와 완료된 Gradle 데몬을 종료했습니다. PC 사용 메모리는 약 21GB에서 9~10GB로 줄었습니다. API와 미디어 워커는 유지했습니다.
- Android 15 화면을 1080×2340/440dpi에서 720×1560/293dpi로 조정하고 시스템 화면 전환 애니메이션을 껐습니다.
- 원격 데스크톱의 CPU 그래픽 대신 Mesa Zink를 통해 NVIDIA RTX 5060 Ti를 사용하는 경로로 실행했습니다. Android SurfaceFlinger의 실제 GLES 렌더러 문자열로 확인했습니다.
- 에뮬레이터의 번들 할당기에서 발생한 TLS 재귀 충돌을 GDB로 확인했습니다. GNU libc/libgcc 우선 로딩은 에뮬레이터 프로세스에만 적용합니다. 전역 라이브러리나 GPU 드라이버를 교체하지 않았습니다.
- 그래픽 명령 전송을 공유 메모리 방식인 ASG로 설정했습니다. 게스트 Vulkan은 사용하지 않고, 호스트 Zink가 Vulkan으로 GPU를 이용합니다.
- 버튼·모임 카드·돌아가기에 Android 눌림 효과와 색/투명도 피드백을 추가했습니다. 버튼의 비활성 상태도 접근성 속성으로 전달합니다.
- 개발 메뉴·개발 검사·Metro 연결이 없는 로컬 확인용 APK를 만들었습니다. JavaScript를 APK 안에 포함하고, 동일한 개발 서명으로 덮어 설치해 계정·모임 데이터를 유지했습니다.

## 실행

현재 PC의 그래픽 구성을 다시 적용하려면 코드 폴더에서 실행합니다.

```bash
npm run emulator:fast
```

이미 `emulator-5556`이 실행 중이면 중복 실행하지 않습니다. 실행기는 현재 Linux x86_64 워크스테이션의 원격 화면 `:10.0`, Android15 AVD를 기본으로 합니다. 원래 AVD 설정은 `~/.android/avd/Android15.avd/config.ini.atp-before-performance`에 보존했습니다. `--software`는 진단용 선택지이며, 현재 AVD에서 확인용 APK와 함께 시험했을 때 System UI 응답 없음이 발생해 최종 구성으로 채택하지 않았습니다.

프로젝트 최상단의 `at-that-place-preview.apk`는 **x86_64 에뮬레이터용** 확인 APK입니다. API와 미디어 워커가 실행 중이면 Metro 없이 앱 아이콘으로 실행됩니다. 실제 배포용 서명·실제 공급자 연동이 적용된 출시 APK가 아닙니다.

재생성:

```bash
cd mobile
npm run preview:android
```

첫 최적화 빌드는 12분 31초 걸렸습니다. 이후 실행기는 필요한 앱 작업 `:app:assembleRelease`만 빌드하도록 지정했습니다. 빌드 결과를 `artifacts/`와 프로젝트 최상단에 복사합니다. 로컬 확인 모드에서만 HTTP API 연결을 허용합니다.

## 확인한 결과와 해석 범위

- Metro를 종료한 상태에서 앱을 강제 종료 후 다시 실행하고 모임 목록 표시를 확인했습니다.
- Android의 `am start -W` 최종 기록은 앱 창 표시까지 1,025ms입니다. 서버 데이터 로딩까지 포함한 전체 시간과는 구분합니다. `artifacts/emulator-performance/cold-start-final.txt` 참고.
- 버튼을 누르는 동안 색과 투명도가 달라지는 것을 실제 화면에서 확인했습니다. [눌림 표시 캡처](../artifacts/emulator-performance/button-pressed.png) 참고.
- 홈 ↔ 설정을 준비 2회 후 측정 8회 왕복했습니다. 데이터 생성·변경·삭제 없이 화면 이동만 수행했습니다.
- 최종 GPU/ASG 구성의 표본은 182프레임, 중앙값 117ms, p95 150ms, 지연 프레임 86.26%였습니다. **부드러운 60fps를 달성한 결과는 아닙니다.** 초기 사용자 기록의 p95는 200ms였지만 중앙값은 77ms였으므로, 전반적인 프레임 속도가 개선됐다고 단정할 수 없습니다. 메모리 여유·개발 부하 제거·눌림 피드백 개선과 남은 표시 지연을 구분합니다.
- 소프트웨어 그래픽 비교의 `gfx-software-preview.txt`는 System UI 오류 중 수집된 2프레임뿐이므로 성능 비교에서 제외합니다.
- 초기 사용자 사용 기록과 반복 이동 측정은 동일한 표본이 아니므로 단순 수치 비교만으로 전체 속도 개선율을 주장하지 않습니다. 중간 구성에서도 프레임 지연이 남아 있어, GPU 인식만으로 60fps를 달성했다고 판단하지 않습니다.
- TypeScript, 모바일 lint, Android 최적화 APK 빌드가 통과했습니다. 두 실행 스크립트는 Node 구문 검사도 통과했습니다.

원본 측정은 `artifacts/emulator-performance/gfx-*.txt`에 있습니다. `gfx-before.txt`는 변경 전 사용자 실행 기록이며, `gfx-final-asg.txt`가 최종 구성에서 반복 이동한 기록입니다. 에뮬레이터 계측치와 원격 데스크톱 화면 전송을 포함한 체감 지연, 실기기 성능은 서로 다릅니다.

구성 참고: [Android 하드웨어 가속 설명](https://developer.android.com/studio/run/emulator-acceleration), [Vulkan 관련 에뮬레이터 문제 해결](https://developer.android.com/studio/run/emulator-troubleshooting).
