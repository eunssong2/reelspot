# 2026-11-06 설계 대조 피드백 수용·보완 및 Android 15 검수

> 11월 6일 후속 재검토: 아래 최초 검수 이후 지적된 보류 초대 회귀·공유 문구·로그인 오류·전송 띠를 수정했다. 최신 근거는 마지막 **초대 뒤로 가기 최종 검증** 절이며, 최초 103개 테스트·APK/번들 해시는 수정 전 이력이다.

## 판정

**“설계서 전체 구현 완료가 아니다”라는 총평은 타당하다.** 다만 파일 변경 유무만으로 미구현 수를 확정할 수 없으며, 기존 구현·이번 보완·외부 연동·제품 결정을 구분해야 한다. 이 보고서는 전체 앱 전수 검수 또는 출시 승인이 아니다.

기준은 `docs/기능 명세서/기능명세서.md` v3.3, `docs/1차 개발 설계서/11 브이로그 제작 설계.md`, prototype의 v3.3 편집 화면이다. 기존 실제 API 연결·권한 검사·초안 무효화 로직을 유지하며 UI 변경을 이식했다.

작업 시작 전에 요청받은 기존 변경을 커밋했다. frontend `43a6ed0`, backend `d1f7a15`, docs `439a4a0`. **이 보고서의 후속 변경과 검수 기록은 최종 커밋에 함께 보존한다.** 푸시·배포·실제 서버 `.env` 변경은 없다. backend 제품 코드는 이번 후속 작업에서 변경하지 않았다.

## 반박 또는 조건부 수용

1. **전 참여자의 브이로그 진입은 결함이 아니다.** F06/F30은 방장 제한 없이 참여자의 진입을 허용한다. 렌더 서버 미연결은 사실이지만 Q20 제품 결정과 구현 범위의 문제다. 이를 이유로 진입을 임의 차단하지 않았다.
2. **장소 기록 머리 정보는 이미 구현돼 있었다.** 장소 이름과 일정 이름·날짜·요일을 보여 준다. 이번에는 사진/영상 수와 섹션 문구를 보완했다. 현재 화면 증거는 `72-place-records.png`다.
3. **사용 중 날짜 처리가 전무했던 것은 아니다.** 기존 선택 비활성·저장 검사·서버 검증이 있었다. 즉시 안내가 부족했던 부분은 수용했다.
4. **보기 변경 시 선택 해제는 F19에 맞는다.** 명세는 “보기를 바꾸면 선택 모드가 끝난다”고 한다. 새로고침으로 선택이 사라지는 것은 수정했고, 보기 전환 자체의 해제는 유지했다.
5. 초대 관리도 전체 미구현이 아니라 발급·목록·복사·공유·취소가 이미 있고 세부 규정이 빠진 상태였다. 제시된 중간 등급 22개/미착수 12개는 원래 결함 ID별 종결표 없이 새 숫자로 재계산하지 않았다.

## 남은 한계와 결정

- VB05 방식은 11월 10일 회의에 올릴 **제안안**이다. 확정 설계 또는 VB05 완료로 판정하지 않는다. 원래 결함이 관찰된 Gboard 전체 키보드 검증이 남아 있다.
