# 2026-11-04 후보 수명 및 복구 안내 보완

기능명세 v3.2·설계 v0.5.0, `docs@ded2a6c7e2420b5959fd18d05ede38943f18c781` 기준이다. frontend 작업 사본을 수정했다. backend 구현, docs 원천, 프로토타입은 변경하지 않았다. 커밋·푸시·배포하지 않았다.

## 검토와 수정

리뷰의 후보 삭제 회귀 지적이 맞다. 이전 구현은 포커스 해제를 화면 이탈로 취급했다. 사진 상세·저장 공간·전송 상태처럼 부모 기록 화면을 유지하는 이동까지 후보를 지웠다. 이전 보고의 “다른 라우트 이동·돌아오기” 검증은 이 잘못된 동작을 확인한 것이므로 올바른 후보 수명의 근거로 사용할 수 없다.

| 항목 | 최종 동작 |
| --- | --- |
| 후보 수명 | `useUploadDraft`를 포커스 수명에서 기록 화면 컴포넌트 수명으로 변경했다. 시트 닫기, 자식 라우트 열기와 복귀, 앱 background/foreground에는 유지한다. 실제 기록 화면 종료·장소/날짜 범위 변경으로 컴포넌트가 해제될 때 후보와 앱 사본을 정리한다. |
| 이탈 확인 | 명세 5절에 따라 후보가 있으면 화면·시스템 뒤로가기 및 라우트 제거 전에 확인한다. `계속 담기`는 유지하고 `비우고 나가기`는 정리한다. 기록→날짜 화면 전환과 날짜 범위 변경도 같은 확인을 거친다. 촬영·접수 중에는 비우기를 막는다. |
| 촬영본 안내 | 앱에서 촬영한 파일은 앨범에 저장되지 않아 비우면 다시 가져올 수 없음을 명시했다. 앨범 원본·전송 큐·다른 저장 후보가 참조하는 파일은 삭제 대상에서 제외한다. |
| 복구·재조회 오류 안내 | 두 안내를 StepFrame의 안전 영역 안, 스크롤 본문으로 옮겼다. 복구 및 재시도 버튼에 최소 높이 48dp를 적용했다. |
| 시간 창 | 닫거나 저장에 성공하면 오류·재시도 정보를 초기화한다. 충돌 안내의 내부 버전 번호는 제거하고 최신 계획 내용을 표시한다. |
| 이전 후보 정리 | 저장 공간·전송 상태의 정리 진입 버튼은 이전 저장 후보가 있을 때만 표시한다. 정리 화면에도 촬영본 삭제 안내를 추가했다. |

사용자가 선택한 **현행 F14대로 화면을 떠날 때 비우기**를 유지한다. 새 후보의 영속 저장을 도입하지 않았다. 프로세스 강제 종료는 메모리 후보를 잃고 정리 콜백을 보장하지 않으므로 즉시 물리 파일 삭제까지 보증하지 않는다. 이전 저장 후보에 대한 명시적 복구·정리 경로는 유지한다.

## 자동 검증

- 앱 로직 **30건**, 컴포넌트 흐름 **24건** 통과, 실패·건너뜀 0.
- 타입 검사, lint(경고 없음), Android export, 최종 소스의 x86_64 확인용 APK 빌드 통과. 기존 네이티브 설정을 사용해 `--skip-prebuild`로 빌드했다.
- 기존 흐름 테스트의 잘못된 blur 삭제 기대값을 변경했다. 사진 상세 복귀 유지, 실제 해제 시 사본 삭제, 이탈 확인 취소·확정, 라우트 제거 시 원래 액션 재개, 안내의 안전 영역/스크롤 배치와 버튼 크기, 시간 오류 초기화, 정리 메뉴 조건부 표시를 검사했다.
- 흐름 테스트는 네이티브 UI·카메라·파일 시스템·AsyncStorage·API·라우터·공통 UI(Sheet/useAction)·Records·DayTimeline·candidate·enqueueTask·영상 플레이어 등을 대체한다. 따라서 이 검사만으로 실제 파일 전송 성공이나 기기 동작을 주장하지 않는다. react-test-renderer 폐기 예정 안내는 테스트 로그에 남아 있다.
- backend 검증 대상 **76개 파일의 해시가 이전 기록과 일치**한다. 서버 테스트 74건의 이전 통과 결과를 참조하며 이번에 다시 실행하지 않았다. 서버/운영 웹 빌드도 재실행하지 않았다.

## Android 시험 사본에서 관찰

별도 Android 15 읽기 전용 AVD(720×1560, 293dpi)에서 확인한 뒤 종료했다. 시험 사본은 앱 진입/layout/API·세션을 바꾸고 기록·사진 상세 시험 라우트를 추가했다. 실제 UploadSheet, 후보 수명, 이탈 확인 Sheet, ImagePicker, 후보 생성, 파일 시스템, AsyncStorage, Expo 라우터와 브이로그 화면을 사용했다. 서버 쓰기는 차단했다. 대상 공통 컴포넌트 소스는 최종 제품 소스와 바이트 단위로 같다. Schedule 전체는 자동 흐름 검사 대상이며 네이티브 시험 기록 라우트는 이를 단순화한 진입 화면이다.

| 조작 | 관찰 및 근거 |
| --- | --- |
| 실제 사진 촬영→시트 닫기→사진 상세 라우트→시스템 뒤로가기 | 같은 사진의 `1개 업로드하기`가 유지됨. `10-candidate`, `12-photo`, `14-retained` |
| 시스템 뒤로가기→계속 담기 | 촬영본 손실 안내가 있는 확인 시트가 나타나고 취소 후 후보 1개 유지. `16-system-confirm`, `17-cancelled` |
| 실제 기록 종료→비우고 나가기→재진입 | 후보 0개, 빈 업로드 시트. `18-discard`~`21-empty` |
| 삭제된 사진이 포함된 브이로그 초안과 재조회 실패 | 두 안내가 헤더 아래 본문에 정상 표시. 복구/재시도 버튼 각각 88px 높이(293dpi에서 약 48.05dp). `24-recovery` |
| 복구 버튼 선택 | 사진 선택 화면으로 진입, 삭제된 기록 1개를 제외했다는 안내와 남은 선택 표시. `25-media-recovery` |

최종 APK와 시험 사본 APK는 별개다. 위 시험은 **로그인부터 서버 업로드까지의 전체 흐름 검증이 아니다**. 네이티브 사본은 release 앱이라 `run-as` 파일 조회가 거부되었다. 이번 물리 사본 삭제 검증은 모의 파일 시스템 호출 검사이고, 에뮬레이터에서는 후보 목록이 비워지는 UI를 확인했다. 동영상 촬영·휠·4:3 자르기는 이전 시험 사본의 결과를 참고할 수 있지만 이번에 재실행하지 않았다.

캡처·UI XML·시험 진입 소스·제품 소스 비교 기록은 frontend의 `artifacts/review3-native/`에 있다. git 제외 로컬 증거이고 해시는 [검증 기록](2026-11-04_후보수명_복구안내_검증.json)에 남겼다. APK는 `artifacts/at-that-place-preview.apk`이다.

## 남은 검증과 범위

**최종 APK 로그인→촬영/선택→서버 업로드는 미완료**다. 현재 서버는 카카오 인증만 활성화돼 있고, 사용자는 사용 가능한 로그인 테스트 기기가 없어 이 검증을 미완료로 기록하도록 지정했다. 인증을 우회하거나 서버 테스트 데이터를 생성하지 않았다.

카메라 실행 중 프로세스 종료·복귀, 실제 휴대폰별 권한/코덱 차이, 전체 화면 문구·배치 검수는 남아 있다. F01~F30 전체 화면 일치를 보증하지 않는다. Q19 한도 확정, Q20 실제 영상 합성·결과 저장도 미결정 상태다. 기존 APK 전체 호환은 보증하지 않으며 향후 배포 시 013 마이그레이션과 앱·서버 버전을 함께 관리해야 한다.
