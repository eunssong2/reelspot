# 2026-11-06 피드백 반영과 Android 15 실행 검수

후속 닉네임·달력 수정과 격리 production 이미지 검수는 [별도 보고서](2026-11-06_닉네임_달력_production_검수.md)를 따른다. 아래 닉네임 저장 시 제한·달력 오류 문구는 당시 관찰 기록이며 후속 수정으로 대체됐다. 후속 개발 빌드에서 발견한 시작 SIGSEGV는 미해결로 별도 기록했다.

피드백 2건을 수정하고 Android 15(API 35)에서 실제 앱·API·파일 저장 흐름을 확인했다. 기기 검수에서 추가로 발견한 만료 화면의 스크롤 문제도 수정했다. 커밋·푸시·서버 배포 및 실제 서버 `.env` 변경은 하지 않았다.

추가 검수(같은 날): 미커밋 수정 중 남았던 다섯 가지를 Android 15에서 실행했다. 자르기 손잡이와 시스템 뒤로가기 제스처의 충돌 1건을 발견해 수정하고 재검수했다. 최신 결과는 아래 「추가 검수」에 기록한다. 최신 서버+실제 카카오 인증 및 전체 앱 전수 검수 완료를 의미하지 않는다.

- Android 15 / API 35, `emulator-5556`, 720×1560px, 293dpi, 제스처 내비게이션. ADB의 터치·연속 swipe 입력으로 실제 네이티브 화면을 조작했다. 물리 기기에서 사람이 손가락으로 수행한 검수는 아니다.

- debug APK의 네이티브 코드와 Metro의 최신 JS를 함께 실행했다. 수정 후 앱을 강제 종료·재시작했고, 기기 내부의 실제 JS 번들에 최종 자르기 계산식이 들어 있는 것도 확인했다. APK·기기 번들·소스 해시는 아래 메타데이터에 남겼다.

### 발견한 결함과 수정

사진 전체를 자르는 초기 상태에서 모서리 손잡이가 화면 가장자리에 붙어 잘렸다. 이 에뮬레이터의 시스템 뒤로가기 제스처 영역은 왼쪽 0~54px, 오른쪽 666~720px였다. 기존 오른쪽 아래 손잡이의 보이는 영역은 x=672~698px로 시스템 제스처 영역 안에 있었다. `(684,934)→(484,774)`를 1.2초 동안 드래그하면 크기 조절 대신 자르기 창이 닫혔다.

`CropModal`에서 사진 주위에 28dp 조작 여백을 확보해 네 손잡이가 작업 영역 안에 온전히 보이도록 수정했다. 저장 좌표는 이전과 동일한 원본 사진 기준 정규화 좌표다. 수정 후 오른쪽 아래 손잡이 중심은 x≈647px로 이동했으며 같은 방향 드래그가 정상적으로 크기를 조절했다. 전체 사진 상태의 네 손잡이가 작업 영역 안에 포함되는 회귀 테스트를 추가했다.

로컬 근거: [수정 전 손잡이](../artifacts/android15-followup-20261106/15-crop-initial.png), [드래그 후 창 닫힘](../artifacts/android15-followup-20261106/16-crop-resized.png), [수정 후 전체 사진](../artifacts/android15-followup-20261106/21-crop-fixed-full.png). 18~20번은 진단 중 캡처이며 최종 판정에는 사용하지 않았다.

### 정리와 남은 범위

검수용 `.verify` 앱은 삭제했고, 일회용 API·워커·DB·네트워크, Metro·프록시를 종료·정리했다. 임시 인증서 비밀키와 테스트 계정 세션 파일도 삭제했다. 기존 서버 설정은 유지했고 커밋·푸시·서버 배포는 수행하지 않았다. Git 제외 Android 빌드 입력도 원래 상태로 복원했다.
