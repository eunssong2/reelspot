## 반영하지 않은 것과 이유

- **QA-03(후보 사진 확대·자르기, Q25):** 12번 문서가 임시안을 "승인된 요구가 아님"으로 두고 있고 실제 이미지 자르기에는 새 네이티브 처리가 필요해, 11월 13일 회의 결정 전에는 넣지 않았다.
- **Q24(기록 메뉴 밖 정보 수정 진입), Q27(기록 메뉴 위치), Q28(촬영 확인 즉시 전송), Q29(장소 수정 라벨):** 결정 전 기준대로 두었다. 일정 메뉴·선택 모드의 `내 기록 수정·삭제`는 남아 있고, 장소 수정 라벨은 프로토타입 관찰값(`검색`/`다른 장소로`/`+ 스팟에 추가`/`이 장소로 바꾸기`)이다.
- **장소 검색 화면 구성(전체 화면 지도 위 결과 시트·핸들):** 구조 변경이 커서 이번에는 결과 없음 안내 위치만 고쳤다.
- **취소된 날 카드의 `⋯`·일정 변경 화면 진입:** 취소된 빈 날을 삭제하려고 넣은 기존 동작이라 명세와 다른 채로 두었다. 어느 쪽으로 맞출지 결정이 필요하다.
- **기록 필터 시트(N02):** "보류"라 기존 화면을 그대로 두었다.
- **장소 교체와 새 업로드가 동시에 일어날 때:** 서버는 둘을 직렬화해 기록이 있는 방문의 교체를 거부한다. 다만 교체가 먼저 확정되면 뒤따른 업로드는 같은 방문(새 장소 이름)에 붙는다. 업로드 요청에 방문 버전을 싣지 않는 한 막을 수 없다.

## 확인하지 못한 것

- **실제 카카오 로그인 경로**(브라우저 복귀 화면을 거치는 스택 정리, production/provider 조합): 격리 서버가 development 인증이라 실행하지 못했다. 테스트 서버 배포 뒤 실제 로그인으로 확인이 필요하다.
- **QA-07의 실기기 재현:** 원문 캡처는 삼성 카메라 결과 화면이다. 에뮬레이터 카메라에서는 담기·업로드가 정상이라 원인을 특정하지 못했다. 삼성 실기기에서 `확인` 뒤 후보에 담기는지, 담기 실패 오류가 뜨는지 확인이 필요하다. 이번에 넣은 담기 실패 표시가 그 단서가 된다.
- **한글 입력:** adb로는 한글을 넣을 수 없어 이름 수정·검색은 영문·숫자로 했다.
- **카메라 권한 창:** 에뮬레이터의 권한 관리 앱이 응답 없음 상태가 되어 권한은 adb로 검증 패키지에 부여했다.
- **브이로그 재생 환경:** 현재 에뮬레이터의 호스트 가속 H.264 디코더는 세로 1080×1920 영상을 처리하지 못한다(사진 앱에서 녹색 화면, 앱 완성 화면에서는 에뮬레이터 프로세스 종료 2회). 수정 전 코드로 만든 파일도 같았고 720p 기록 영상은 정상이다. `-feature -HardwareDecoder`로 게스트 소프트웨어 디코더를 쓰게 해 검증했다. 실기기 재생은 확인하지 않았다.
- 전송 실패 주입·오프라인 대기, 120개 선택 상한, 저장 공간 부족, 한 번 10개 업로드, 사진 5·영상 2 초과 거부의 기기 재확인은 하지 않았다(서버 테스트와 화면 흐름 테스트로만 확인).

## 2차 검토 후속: 저장 중 편집 잠금 (2026-11-13 저녁)

지적: 충돌 뒤 최신값을 다시 읽는 동안 입력한 내용이, 응답이 오면 서버 값으로 덮어써졌다. 저장을 누른 순간의 입력으로 병합 여부를 판단하는데 그동안 입력 칸이 열려 있었다. 충돌이 없어도 저장 요청 중 더 입력한 내용은 저장되지 않고 화면이 닫혔다.

수정 (`src/app/places.tsx`):
- 주된 해결: 저장 요청부터 충돌 후 재조회가 끝날 때까지 이름·주소·검색 입력, 시간 버튼, 지도 핀 지정, `핀 지우기`, `현재 위치`, 헤더 `검색`/`다른 장소로`/`직접` 전환을 잠근다. 실패하면 다시 편집할 수 있다. 중복 저장도 막는다.
- 보조 장치: 병합할 때 응답 도착 시점의 실제 입력(렌더마다 갱신되는 ref)을 읽는다. 잠금을 넘어 입력이 들어와도 사라지지 않는다.
- 재조회 실패: `최신 내용으로 바꿨어요` 대신 `최신 내용을 불러오지 못했어요. 입력은 그대로 두었어요.`라고 안내한다. 다시 저장하면 옛 버전이라 서버가 다시 충돌로 답하고 덮어쓰지 않는다.

테스트: `tests/flows/place-edit-lock.test.tsx`(정상 저장 지연 중 잠금·핀 무시·저장 후 복귀, 충돌 후 재조회 지연 중 잠금과 입력 유지·실패 후 잠금 해제, 재조회 실패 문구·입력 유지·재저장 시 옛 버전 전송). 검토자 재현 테스트는 "대기 중 주소 칸이 열려 있다"는 첫 전제에서 실패한다. 앱 단위 44개·화면 흐름 115개·타입 검사 통과, lint 새 경고 없음. 서버 변경 없음(diff 해시 `f1c7cb88…`).

3차 검토 지적(같은 날): 오류 아래 공통 `다시 시도`가 잠금을 우회하고 실패 당시의 옛 입력을 다시 보냈다. `useAction`이 내부 저장 함수를 그대로 다시 실행하기 때문이다. 수정: 저장(장소 수정·장소 등록)에 별도 action을 두고 인라인 재시도를 끄게 했다. 다시 저장은 현재 입력을 읽고 잠금을 거치는 저장 버튼으로만 한다. 같은 입력이면 같은 요청 키라 응답 유실 뒤 다시 눌러도 중복되지 않는다. 장소 정보 조회 실패의 `다시 시도`는 잃을 입력이 없어 유지했다. 테스트 `tests/flows/place-edit-retry.test.tsx`는 화면 흐름 테스트 중 처음으로 실제 `useAction`을 쓴다. 검토자 재현 테스트는 `다시 시도` 버튼이 없어 실패한다. 앱 단위 44개·화면 흐름 117개·타입 검사 통과, lint 새 경고 없음.

Android 15 검증(`emulator-5556`, Android 15/API 35): APK `artifacts/android15-v34-lockfix-20261113/at-that-place-v34verify.apk`(해시는 같은 폴더 `verification.json`). 서버는 backend 작업 트리(diff 해시 `f1c7cb88…`)를 읽기 전용으로 띄운 격리 API·워커와 일회용 DB였다. 대기 상태를 화면에서 보려고 로컬 HTTPS 프록시가 해당 요청만 붙잡게 했다(`tls-proxy.mjs`의 `delay.json`). 서버 코드는 바꾸지 않았다.

## 정리

검증할 때마다 환경을 새로 만들었고, 각 회차가 끝나면 아래를 지웠다. 마지막 회차(3차 검토 후속, 2026-11-13 19시)를 마친 현재도 모두 지운 상태다.

- 에뮬레이터의 `kr.atthatplace.app.v34`와 그 앱이 만든 시험 파일, 에뮬레이터 세션
- 격리 API·워커·DB 컨테이너, 로컬 HTTPS 프록시, 임시 인증서 개인키, 시험 파일 저장소, 빌드 복사본

2차 검토 후속 회차에는 디스크 부족으로 기기 검증을 못 해서, 다음 회차를 위해 격리 서버와 프록시를 잠시 띄워 두었다. 3차 회차 검증 뒤 함께 지웠다. 검증 APK와 캡처·로그는 각 `artifacts/android15-v34-*` 폴더(Git 제외)에 남겼다. 테스트 서버(`1-api-1` 등), 실제 `.env`, 기기의 기존 앱(`kr.atthatplace.app`)은 어느 회차에서도 바꾸지 않았다.
