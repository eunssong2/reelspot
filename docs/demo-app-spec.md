# AT THAT PLACE 테스트 앱(데모) — 화면·기능 명세서

대상: 이 문서만 보고 같은 앱을 구현하거나 실제 서비스(서버 연동)로 확장할 개발자.
기준 빌드: `dist/ReelSpot-Demo.apk` (Android, Expo SDK 54 / React Native 0.81 / expo-router 6, 패키지 `com.reelspot.app.demo`, 앱 이름 "AT THAT PLACE 테스트(데모)").

> **화면 번호는 기능명세 v1.7과 같다**: S01 일정 요약, S02 날짜별 장소, S03 장소 검색·추가, S04 장소별 기록, S05 순서 편집, V1 확대/재생 뷰어(S0 은 데모 전용 시작 화면). 제품 기준·구현 상태는 [feature-spec-v2.md](feature-spec-v2.md).
>
> 이 앱은 **서버·로그인 없이 예시 데이터로 동작하는 체험용 앱**이다. 아래 "1.3 범위 밖"에 적은 기능은 다른 팀원 담당이므로 구현하지 않는다.

## 1. 개요

### 1.1 목적
여행 일정 안에서 **날짜별 장소를 보고, 장소를 추가·정렬하고, 장소별로 스팟원들이 남긴 사진·동영상을 열어 보는** 흐름을 휴대폰에서 눌러 보며 검증한다.

### 1.2 담당 기능(구현 완료)
| # | 기능 | 화면 |
|---|------|------|
| F1 | 일정 선택(데모 시작 화면) | S0 |
| F2 | 일정 요약 조회(이름·기간·인원·날짜별 카드·장소 수·미디어 수), 일정 추가(새 날짜 추가) | S01 |
| F3 | 일정 대표(배경) 사진 변경·되돌리기 | S01 |
| F4 | 날짜별 장소 목록(날짜 탭 4개씩 넘겨 보기, 타임라인 카드: 번호·방문 시간·장소명·기록 링크) | S02 |
| F5 | 방문 시간 수정 | S02, S05 |
| F6 | 장소 검색·추가(검색어·카테고리 필터·지도·결과 목록, 중복 방지, 추가 후 자동 복귀) | S03 |
| F7 | 장소 순서 편집, 날짜 제목·메모 편집, 저장(메모는 정식 범위 제외 결정 — 앱에는 입력칸이 남아 있음) | S05 |
| F8 | 장소별 사진·동영상 기록 조회(작성자·시각·설명, 최신/오래된순) | S04 |
| F9 | 사진 확대 보기, 동영상 재생 | V1 |
| F10 | 업로드 버튼(선택 시트까지, 실제 업로드는 연결 지점만) | S04 |
| F11 | 기기 내 저장(앱 재시작 후 유지), 데모 초기화 | 전체 |

### 1.3 범위 밖(구현하지 않음 — 다른 팀원 담당)
로그인, 일정 생성, 방 생성·멤버 구성, 사진·동영상 촬영/선택 결과의 **실제 업로드 처리**, 영상 병합.
이 기능들은 **연결 지점만** 둔다(8장 참조). 업로드가 된 것처럼 꾸미지 않는다.

### 1.4 데모 모드 규칙
- 데모 빌드는 환경변수 `EXPO_PUBLIC_DEMO_MODE=1` 로 켠다(`src/demo/config.ts`의 `IS_DEMO_BUILD`). 꺼져 있으면 기존 서비스 흐름 그대로다.
- 데모에서는 모든 화면 맨 위에 **`TEST · 예시 데이터로 체험 중이에요`** 띠가 붙는다.
- 예시 검색 결과·예시 지도에는 반드시 "예시/실제 아님" 표시를 한다.
- 인터넷 없이 모든 핵심 기능이 동작해야 한다(이미지·영상은 앱에 포함).
- 비밀 키·서버 주소를 번들에 넣지 않는다(빌드 스크립트가 `.env` 를 복사하지 않는다).

## 2. 화면 흐름

```
앱 실행
  └ S0 일정 선택 ──(일정 버튼)──▶ S01 일정 요약 ──(날짜 카드)──▶ S02 날짜별 장소
        ▲   ‹ 뒤로                  │  └ 배경 이미지 탭 → 배경 사진 시트          ├ (장소 추가) ▶ S03 장소 검색·추가 ─(추가)─▶ S02로 자동 복귀
        └───────────────────────────┘                                              ├ (편집) ▶ S05 순서·제목·메모 편집 ─(저장)─▶ S02
                                                                                   ├ (시간 수정) ▶ M1 시간 수정 창
                                                                                   └ (장소 카드) ▶ S04 장소 기록 ──(사진/동영상)──▶ V1 확대/재생 뷰어
                                                                                                      └ (＋ 사진·동영상 올리기) ▶ M2 업로드 시트 ▶ M3 선택 시트
```
- 일정 요약의 `↺ 데모 초기화`(상단 띠)는 S01 에서만 보인다.
- 일정 요약의 ‹ 는 S0 로, 그 외 화면의 ‹ 는 이전 화면으로 돌아간다. Android 뒤로 가기는 모달(M·V1)을 먼저 닫고, 화면을 이전으로 돌린다. S0 에서는 앱이 종료된다.

### 2.1 라우트(expo-router, `app/prototype/*`)
| 경로 | 화면 | 쿼리 파라미터 |
|------|------|---------------|
| `/prototype` | S0 (데모) / 모임 목록(비데모) | — |
| `/prototype/itinerary` | S01 | `tripId`, `itineraryId` |
| `/prototype/itinerary-day` | S02 | `tripId`, `itineraryId`, `dayId` |
| `/prototype/place-search` | S03 | `tripId`, `itineraryId`, `dayId` |
| `/prototype/place-order` | S05 | `tripId`, `itineraryId`, `dayId` |
| `/prototype/place-records` | S04 | `tripId`, `itineraryId`, `dayId`, `placeId` |

잘못된 id 조합이면 "일정을 찾을 수 없어요 / 날짜를 찾을 수 없어요 / 장소를 찾을 수 없어요" 문구만 가운데에 표시한다.
모든 화면은 `PrototypeProvider`(상태) 안에서 `ScreenFrame`(공통 틀)으로 그린다. 폭은 최대 430px(웹), 배경 흰색.

## 3. 화면별 명세

공통 디자인 토큰은 `src/prototype/styles/tokens.ts`(코랄 `primary`, 회색 `surface`, 좌우 여백 `GUTTER=20`, 카드 곡률 20). 터치 영역 최소 56(큰 버튼).

### S0 일정 선택 (`src/demo/DemoHome.tsx`)
- **구성**: 흰 배경 가운데 정렬. `AT THAT PLACE`(작은 코랄 글씨) → 제목 `어떤 일정을 볼까요?` → 일정 버튼 N개(세로 나열).
- **일정 버튼**: 코랄 배경 큰 버튼. 1행 `일정 이름`, 2행 `{하루 일정|N일 일정} · {기간}`(기간 표기는 `tripRangeLabel`). 하루짜리는 `하루 일정 · 2026.10.24 토요일`.
- **동작**: 버튼 → S01(`tripId`, `itineraryId`). 접근성 라벨 `{일정이름} 열기`.
- **데이터**: `itineraries.filter(tripId === 'trip1')`. 예시는 2개.

### S01 일정 요약 (`ItinerarySummaryScreen.tsx`)
- **헤더**: ‹ 와 가운데 `AT THAT PLACE`만 있다(오른쪽 프로필 묶음 없음).
- **본문(세로 스크롤)**
  1. **대표 배너**(`ItineraryCoverBanner`, `square`): 16:9, **좌우 여백 없이 화면 가로 끝까지**, 모서리 둥글지 않음. 직접 고른 사진이 있으면 꽉 채워(cover), 없으면 기본 그림(이모지+색). 우하단 `📷 배경 변경` 배지. 탭 → 배경 사진 시트(M4).
  2. **일정 정보**: 일정 이름(24px 굵게), `📅 {기간} · {인원}명`과 오른쪽 아바타 스택(최대 4 + `+N`).
  3. **날짜 카드**(날짜 수만큼, 섹션 제목·`DAY n` 배지·썸네일 아이콘 없음):
     - 1행: `M월 D일`. 2행: 제목(날짜 제목, 없으면 `M월 D일의 장소`)과 오른쪽 `›`. 3행: 통계.
     - 통계: 장소가 있으면 `장소 N곳 · 미디어 K개 (사진 a·동영상 b)`(미디어 0이면 `미디어 없음`), 없으면 `아직 정한 장소가 없어요`.
     - 장소가 없는 날짜는 `아직 정한 장소가 없어요`만 보인다(카드 안 버튼 없음).
     - 카드 탭 → S02(해당 `dayId`).
  4. **`일정 추가`** 버튼(날짜 카드 목록 맨 아래, 테두리 버튼, 접근성 라벨 `일정 추가`): 마지막 날짜의 다음 날을 빈 날짜로 추가한다(`addDay` → `addDayToItinerary`). 일정의 `endDate` 도 그 날짜로 늘어나 `📅 2026.10.17 - 10.20 · 5명`처럼 바뀐다. 새 날짜 id 는 `day-{번호}`. 최대 30일(`MAX_DAYS`)이며 도달하면 버튼이 사라진다. 기기에 저장되어 재실행 후에도 유지되고 `데모 초기화`로 사라진다.
- **상단 띠(데모)**: `↺ 데모 초기화` → 확인창(M5) → 초기화.

### M4 배경 사진 시트 (`CoverEditSheet.tsx`)
- 아래에서 올라오는 시트. 제목 `배경 사진`. 항목: `🖼️ 앨범에서 사진 고르기`, (직접 고른 사진이 있을 때만) `↺ 기본 이미지로 되돌리기`, `취소`.
- **사진 고르기**: `expo-image-picker` 앨범(이미지만), **자르기 화면 없음**(`allowsEditing:false`), `quality 0.4`, `base64:true`. 결과를 `data:{mime};base64,…` 로 만들어 저장. 선택한 사진은 배너가 가운데를 16:9로 채워 보여준다.
- **오류**(안내창 `배경 사진`): base64 없음 → "사진을 불러오지 못했어요. 다른 사진을 골라 보세요." / 문자열 길이 1,400,000 초과 → "사진 용량이 너무 커요. 더 작은 사진을 골라 보세요." / 예외 → "사진을 열지 못했어요. 사진 접근 권한을 확인해 주세요."(Android AsyncStorage 값 2MB 제한 때문에 1.4MB 로 제한)
- 취소(앨범에서 돌아옴)는 아무 변화 없음.

### S02 날짜별 장소 (`ItineraryScreen.tsx`)
- **헤더**: ‹, 제목 `{일정 이름}`, 부제 `{기간}`(프로필·인원 표시 없음).
- **날짜 탭**: 날짜가 2개 이상일 때만. 위 `M월 D일`·아래 `토요일`(`DAY n` 없음). 선택된 탭은 코랄 배경. 1일이면 탭 없음. **한 화면에 최대 4개만 보이고** 5일 이상이면 옆으로 넘겨 본다(가로 스크롤, 스크롤바 없음). 탭 폭은 (화면 폭 − 좌우 여백 − 간격) ÷ 보이는 개수(2~3일이면 그 수로 나눠 가득 채움, 4일 이상은 4등분)이며 모두 같다. 날짜를 고르면(또는 화면에 들어올 때) 선택한 탭이 가운데쯤 오도록 자동으로 넘어간다.
- **본문**(옅은 회색 바탕)
  - 머리글: 큰 글씨 `10월 17일` + 회색 `토요일`, 오른쪽 `편집`(장소가 있을 때만, → S05), 아래에 날짜 제목(있으면).
  - 장소가 없으면 빈 카드 `가고 싶은 곳을 담아 하루를 채워보세요.`
  - **타임라인**(장소 순서대로): 왼쪽 열(폭 60) — 코랄 번호 동그라미(30px), 아래로 이어지는 옅은 세로선, 동그라미 아래 방문 시간(`HH:mm` 또는 `시간 미정`)과 `수정`(탭 → M1). 오른쪽 — 흰 카드(곡률 16, 옅은 그림자): 장소명(18px 굵게, 최대 2줄), 아래 줄에 기록 링크 `사진 a · 동영상 b`(코랄) 또는 `아직 기록 없음`(회색)과 `›`.
    - **장소 이미지·분류 칩·주소는 표시하지 않는다.**
    - 방금 추가한 장소(`highlightId`)는 코랄 테두리 + `추가됨` 배지.
    - 카드 탭 → S04.
  - 맨 아래 테두리 버튼 `장소 추가` → S03.

### M1 방문 시간 수정 (`TimeEditModal.tsx`)
- 중앙 카드 창. 제목 `방문 시간`, 장소명.
- **돌려서 고르는 세 칸**: `오전/오후`, `시`(1~12), `분`(00~59, 1분 단위). 각 칸은 위아래로 스크롤하며(`ScrollView`, 한 줄 48px, 5줄 표시) 가운데 줄(두 선 사이)이 선택값이다. 선택 줄은 굵은 검정, 위아래 줄은 흐리게. 스크롤을 멈추면 가장 가까운 줄에 맞추고(웹은 140ms 뒤 보정), 줄을 눌러도 그 값으로 이동한다. 시·분 사이에 `:`.
- `시간 미정으로 두기`(→ 저장 시 시간 제거), `취소`, `확인`. (＋/－ 버튼과 빠른 선택 칩은 없다.)
- 초기값: 현재 `visitTime`, 없으면 `오후 12:00`. 저장 값은 24시간 `HH:mm`(`^([01]\d|2[0-3]):[0-5]\d$`).
- S02 에서 확인하면 즉시 `updateDay`(해당 날짜 장소 배열 갱신, 메모는 유지), S05 에서는 화면 내 임시 상태만 바꾸고 `변경 저장` 때 한꺼번에 저장.

### S03 장소 검색·추가 (`PlaceSearchScreen.tsx`)
- **헤더**: ‹, `장소 추가`, 부제 `{일정 이름} · {YYYY년 M월 D일 요일}`.
- **검색창**: `🔍` + 입력(placeholder `장소를 검색하세요 (예: 성수 카페)`) + 지우기 ✕. 제출(키보드 검색/돋보기)로 검색.
- **카테고리 칩**: `전체 관광지 맛집 카페 숙소`. 카테고리 칩 선택 → 해당 카테고리 검색(검색어 비움). `전체`: 검색어가 있으면 다시 검색, 없으면 결과 비움.
- **모드 칩(데모)**: `예시 검색 (오프라인)`(기본) / `실제 지도 (인터넷 필요)`. 예시 모드 안내문 `※ 아래 결과는 데모용 예시 장소예요. 실제 지도 검색 결과가 아닙니다.`
  - 실제 지도 모드: 카카오 지도(WebView). 지도 키가 없으면 안내 `이 테스트 앱에는 카카오 지도 키가 들어 있지 않아요…` + `예시 검색으로 체험하기` 버튼. 로딩 15초 초과/오류 시 오류 카드 + `다시 시도`, `예시 검색으로 체험하기`.
  - 모드를 바꾸면 검색어·결과·선택 상태를 모두 초기화.
- **지도 영역**
  - 예시 지도(`DemoMapView.tsx`): 단순 그림(격자+한강)에 결과 핀(이모지 원 + 이름표) 배치, 좌상단 `예시 지도 (실제 아님)` 표시. 결과가 있으면 핀이 보이도록 확대 범위를 맞춘다. 핀 탭 → 상세 패널, 빈 곳 탭 → 선택 해제. `현재 위치` 버튼은 토스트 `예시 지도에서는 현재 위치를 쓰지 않아요`.
  - 결과가 있을 때 `⟳ 이 지역 다시 검색` 버튼.
- **결과 시트**(`PlaceResultSheet.tsx`): 헤더 `예시 장소 N곳`(실제 지도는 `검색 위치 기준 N곳`) + 정렬 토글 `관련도순 ▾ / 거리순 ▾`. 항목: `이름 [카테고리] 예시`, `거리 · 주소`, 썸네일, `+ 스팟에 추가` 버튼(이미 담았으면 `✓ 스팟에 추가됨`, 비활성). 펼치기/접기 핸들.
- **상세 패널**(`PlaceDetailPanel.tsx`): 이름·카테고리·`예시`, `📍 주소`, `📅 선택한 날짜 · {날짜}`, 예시일 때 `※ 데모용 예시 장소예요. 실제 장소 정보가 아닙니다.`, 큰 버튼 `이 날의 장소로 추가`(이미 있으면 `✓ 이 날의 장소에 추가됨` 비활성).
- **추가 동작**: 추가 성공 → **즉시 S02 로 돌아간다**(`nav.back`). 방금 추가 장소는 S02 에서 `추가됨`으로 강조, 시간은 `시간 미정`, 기록은 `아직 기록 없음`. 같은 날짜에 이미 있으면 추가하지 않고 토스트 `{이름}은(는) 이미 {날짜} 장소에 담겨 있어요`.
- **빈 상태 문구**: 초기 `예시 장소를 검색하거나 카테고리를 눌러 보세요 (예: 카페, 성수, 호텔)`, 결과 없음 `예시 장소 중에 찾는 결과가 없어요. 다른 검색어를 입력해 보세요`, 검색 중 `검색 중…`.

### S05 순서·제목·메모 편집 (`PlaceOrderEditScreen.tsx`)
- **헤더**: ‹, `장소 순서 편집`, 부제 `M월 D일 일요일` 형식(`DAY n` 없음).
- **날짜 제목**: 라벨 `날짜 제목`, 한 줄 입력(최대 30자, placeholder `예: 빵 먹고 전시 보고 저녁까지`), 카운터 `n/30 · 비워 두면 "M월 D일의 장소"로 보여요`.
- 안내 배너 `위·아래 버튼으로 방문 순서를 바꾸세요.`
- **장소 행**: 순번, 이름, 주소(장소 이미지 없음), `방문 시간 [HH:mm ✎ | 시간 미정 ✎]`(탭 → M1), 우측 ▲▼(첫 행 ▲·마지막 행 ▼ 비활성). 드래그는 제공하지 않는다.
- **장소 메모**: 여러 줄 입력(최대 100자), 카운터 `n/100`.
- **하단 `변경 저장`**: 장소 배열(순서·시간), 메모(trim), 날짜 제목(trim)을 저장하고 이전 화면으로. 제목이 빈 문자열이면 제목 삭제. 취소(‹) 시 저장 안 함.

### S04 장소 기록 (`PlaceRecordsScreen.tsx`)
- **헤더**: ‹, 장소명, 부제 `{일정 이름} · MM.DD 요일`.
- **`＋ 사진·동영상 올리기`**(윤곽선 큰 버튼) → M2.
- **섹션 제목**: 동영상이 하나라도 있으면 `함께 남긴 순간`, 아니면 `함께 남긴 사진` + 회색 `사진 a·동영상 b`(미디어가 있을 때). 우측 정렬 토글 `최신순 ⌄` ↔ `오래된순 ⌄`(탭하면 전환, 기본 최신순). 그 아래 보기 전환 `사진별 | 사람별`(기본 사진별, 화면을 나가면 초기화). 사람별 보기는 스팟원마다 카드 1개(프로필·이름·`사진 a · 동영상 b · 시각`)와 격자(1장 크게, 2장 나란히, 3장 위 1+아래 2, 4장 이상 2×2, 5장 이상은 네 번째 칸 `+N`을 눌러 모두 펼침/`접기`). 칸을 누르면 V1.
- **기록 카드**(사진/동영상 한 건당 카드 1개): 
  - 이미지 영역은 **가로폭에 맞춘 4:3 고정 높이**(`(min(화면폭,430) − 40) × 3/4`), cover. 
  - 동영상이면 좌상단 `▶ m:ss` 배지.
  - 하단 흰 그라데이션 띠 위에 작성자 아바타(28), `작성시각 · 작성자`, 설명(있으면 1줄).
  - 탭: 사진 → V1 확대 / 동영상(재생 파일 있음) → V1 재생 / 재생 파일 없는 동영상 → 토스트 `재생은 아직 지원하지 않아요`.
  - 이미지 로딩 실패 → `SafeImage` 자리표시(🖼️ + `이미지를 불러오지 못했어요`).
- **기록이 없을 때**: `아직 이곳에 남긴 사진·동영상이 없어요.` + `스팟원이 올리면 여기에 모여요.`
- **정렬 규칙**(`records.sortRecords`): 게시물(작성자 묶음) 단위. 시각이 `MM.DD HH:mm` 이면 숫자 비교, `방금 전`·`12분 전` 같은 상대 표현이면 원래 배열 순서(앞이 최신). 같은 시각은 원래 순서 유지. 같은 게시물의 항목 순서는 유지.

### M2 업로드 시트 / M3 선택 시트 (S04 안)
- M2 `지금 이 순간 남기기`: 선택한 항목 썸네일 가로 목록(각 ✕ 삭제) + 점선 `＋` 타일, 안내 `사진·동영상 최대 10개`, 하단 `업로드하기`(선택 0개면 비활성).
- 데모에서는 처음에 **빈 상태**로 시작한다(미리 담긴 가짜 선택 없음).
- `＋` → M3(`MediaPickerSheet`): `사진 보관함에서 선택 / 동영상 보관함에서 선택 / 사진 촬영 / 동영상 촬영 / 취소`. 같은 파일 중복 선택 시 토스트 `이미 추가한 파일은 다시 담지 않았어요`, 10개 초과 시 `사진과 동영상은 최대 10개까지 올릴 수 있어요`, 촬영 권한 거부 시 `카메라 권한이 필요해요`, 실패 시 `불러오지 못했어요`.
- **`업로드하기`(데모)**: 업로드 처리는 팀원 영역. `requestUpload`(8장)를 호출하고, 처리되지 않으면 안내창 `업로드 기능은 팀원 구현 영역입니다`만 띄우며 **선택 항목을 그대로 둔다**(기록 목록에 추가하거나 "완료"라고 표시하지 않는다). 처리되면(`handled:true`) 토스트 `N개를 업로드 기능으로 넘겼어요` 후 선택 비움·시트 닫기.

## 4. 데이터 모델(`src/prototype/mock/tripData.ts`)

```ts
interface Trip { id; name; destination; period; memberCount: number; cover: 'beach'|'sunset'|'town'; subtitle; clipSeconds: 5|10|15 }
interface TripMember { id; name; avatarUrl: string | number /* URL 또는 번들 자산 */; isMe?: boolean }

interface ItineraryPlace {
  id: string;            // 장소 id (카카오 장소 id 또는 'demo-…')
  name; address; categoryLabel;   // 관광지·맛집·카페·숙소·장소 등 표시용 이름
  emoji; tint;                    // 썸네일(이모지+배경색)
  visitTime?: string;             // 'HH:mm' (없으면 시간 미정)
  visitId?: string;               // 방문 식별자 = `${itineraryId}/${dayId}/${placeId}`
}
interface ItineraryDay { id; date: 'YYYY-MM-DD'; dayNumber; title?: string; places: ItineraryPlace[]; memo?: string }
interface Itinerary { id; tripId; name; startDate; endDate; days: ItineraryDay[] }

interface PlaceRecordItem { id; kind: 'photo'|'video'; imageUrl: string|number; videoSource?: number; durationLabel?: string; caption?: string }
interface PlaceRecord { id; memberId; time: string /* 'MM.DD HH:mm' 또는 상대 표현 */; items: PlaceRecordItem[] }
```
검색용 `Place`(`src/prototype/map/types.ts`): `{ id, name, address, roadAddress, lat, lng, category: string /* 카카오 형식 '음식점 > 카페 > …' */, phone, sample?: boolean }`.

### 4.1 식별자 규칙(필수)
- 모임 `tripId` ≠ 일정 `itineraryId`. 날짜 `dayId` 는 일정 안에서만 유일(`day-1` 등은 다른 일정과 겹쳐도 됨).
- **방문 식별자 `visitId = itineraryId/dayId/placeId`**. 같은 장소를 다른 날짜(또는 다른 일정)에 담아도 기록·미디어 수가 섞이지 않는다. 기록 조회는 항상 `recordsForVisit(itineraryId, dayId, place)` 로 한다.
- 같은 **날짜**에는 같은 `placeId` 를 두 번 담을 수 없다.

### 4.2 카테고리 분류(`placeStyle.ts`, 위에서부터 먼저 맞는 규칙)
`카페`→카페☕ / `숙박`→숙소🛏️ / `^음식점`→맛집🍽️ / `고궁|문화재|관광|명소|공원`→관광지🏯 / `미술관|박물관|문화|예술`→관광지🖼️ / 그 외 장소📍.
카테고리 칩 ↔ 분류 이름: 관광지→`관광지`, 맛집→`맛집`, 카페→`카페`, 숙소→`숙소`.

### 5.2 기기 내 저장(데모 빌드, AsyncStorage)
| 키 | 내용 |
|---|---|
| `reelspot.demo.itineraries.v1` | `{version:1, itineraries:[…]}` (제목 없는 날짜는 `title:''` 로 기록) |

## 7. 검색 로직(`src/demo/sampleSearch.ts`)
- **키워드 검색**: 검색어를 공백으로 나눈 **모든 조각**이 (이름 + 주소 + 카테고리 문자열 + 분류 이름) 안에 있으면 결과(대소문자·공백 무시). 이름에 맞은 조각이 많을수록 앞. 검색어가 공백뿐이면 결과 없음. 예) `성수 카페` → `성수 로스터리 카페` 1건.
- **카테고리 검색**: 분류 이름이 일치하는 장소 전부(`맛집`은 카페 제외).
- 결과는 `searchResult` 이벤트(`done`/`empty`)로 전달(실제 지도와 같은 `MapHandle`/`MapEvent` 계약, `src/prototype/map/types.ts`).
- 거리순 정렬 기준점: 지도 중심(예시 지도는 서울시청 37.5665,126.978).

## 8. 외부(팀원) 연결 지점
1. **업로드**(`src/demo/uploadBridge.ts`): `setUploadHandler((req) => Promise<{handled:boolean}>)` 등록. 요청 `{ tripId, itineraryId, dayId, visitId, placeId, placeName }`. 업로드 결과는 `visitId` 에 연결해야 날짜별 기록이 섞이지 않는다. 선택된 파일 자체(`staged`)를 넘기는 확장은 `UploadRequest` 에 필드를 추가해 구현한다.
2. **일정·기록 데이터 소스 교체**: `PrototypeProvider` 의 초기 `itineraries`·저장 로직, `src/demo/records.ts` 의 `recordsForVisit` 를 서버 조회로 바꾼다. 화면은 이 함수들만 의존한다.
3. **대표 사진 저장**: 현재 data URI 를 AsyncStorage 에 보관한다. 서버 연동 시 업로드 URL 로 교체하고 `covers` 의 값만 URL 로 바꾸면 화면은 그대로 동작한다.
4. **실제 지도**: 카카오 JavaScript 키(`EXPO_PUBLIC_KAKAO_JS_KEY`)를 넣고 빌드하면 `실제 지도 (인터넷 필요)` 칩이 동작(`-IncludeKakaoKey`). 키는 앱에서 추출 가능한 클라이언트 키다.

## 10. 수용 기준(테스트 시나리오)
`node scripts/check-demo-logic.mjs`(14개 로직 점검)와 아래 수동/자동 시나리오를 모두 통과해야 한다.
1. 앱 실행 → 로그인 없이 S0, 일정 2개 버튼. 3일 일정 선택 → S01 통계가 6.4 표와 일치.
2. 하루 일정 선택 → 날짜 카드 1개, S02 에 날짜 탭 없음, 일정 제목 `성수 당일치기`.
3. S02 에서 시간 `수정` → 돌려서 `오후 4:05` 로 확인 → 목록에 `16:05`. 순서 편집에서도 같은 시간 창으로 변경, `시간 미정` 되돌리기 동작.
4. S03 에서 `카페` 검색 → 4건, `zzzz` → 결과 없음 문구, `관광지` 칩 → 경복궁 등만. 추가 → **S02 로 자동 복귀** + `추가됨`.
5. 같은 날짜에 같은 장소 재추가 불가, 다른 날짜에는 추가 가능하며 기록이 섞이지 않음.
6. 순서 편집에서 ▲▼로 이동·저장 → 순서 반영. 날짜 제목 수정 → S01 카드·S02 에 반영, 비우면 `M월 D일의 장소`.
7. 앱 완전 종료 후 재실행 → 추가/순서/시간/제목/배경 사진 유지. `데모 초기화` → 모두 처음 상태.
8. S04: 기본 최신순(도윤 14:25 가 수아 14:12 보다 위), 토글 시 오래된순. 사진 카드는 4:3 로 잘림 없이 표시.
9. 사진 확대 1→3배, 동영상(0:06) 재생 시간이 진행. ✕/뒤로가기로 닫힘.
10. `사진·동영상 올리기` → 선택 시트 → `업로드하기` 시 안내창, 기록 목록 변화 없음.
11. S01 에서 `일정 추가` → 마지막 날 다음 날(예: 10월 20일)이 빈 날짜로 생기고 기간이 늘어남. 재실행 후에도 유지, `데모 초기화`로 사라짐, `＋ 장소 담기` 버튼은 없음.
12. 배경 사진 변경 → 시스템 자르기 화면 없이 선택 사진이 배너에 채워짐, `기본 이미지로 되돌리기` 동작.

## 12. 알려진 한계·확장 아이디어
- 사진 확대에 핀치 제스처 없음(버튼·두 번 탭만).
- 시간 창의 분 칸은 59 → 00 으로 이어지지 않는다(0~59 에서 끝).
- 순서 편집은 ▲▼ 버튼(드래그 없음).
- 장소가 없는 날짜는 `편집`이 없어 날짜 제목을 바꿀 수 없다.
- 대표 사진은 data URI(약 1.4MB 이하)로 보관하며 서버 업로드는 없다.
- 예시 지도는 위치 감만 주는 그림이며 실제 지도·길찾기가 아니다.
- 촬영(카메라) 선택은 앱 설정상 카메라 권한이 꺼져 있어 기기에 따라 권한 거부 안내가 뜰 수 있다(팀원 업로드 구현 시 권한 설정 필요).
- 이 APK 는 디버그 키로 서명한 테스트용이라 스토어 배포는 이 빌드로는 불가하다(스토어용은 릴리스 키 서명 AAB 를 따로 만든다).
- 날짜 추가는 마지막 날 다음 날만 가능하고(중간 삽입·삭제 없음) 최대 30일이다.
